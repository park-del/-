题目描述：

给定一个含有 n 个正整数的数组和一个正整数 s ，找出该数组中满足其和 ≥ s 的长度最小的 连续 子数组，并返回其长度。如果不存在符合条件的子数组，返回 0。

- 输出：2

# 视频内容总结



视频通过对比两种解法，深入浅出地讲解了如何解决这个问题：

1. **暴力解法 [[00:20](http://www.youtube.com/watch?v=7brhpecjOSY&t=20)]**：
   - 思路：使用两层 `for` 循环。第一层循环确定子数组的起始位置，第二层循环确定子数组的结束位置。
   - 缺点：遍历了所有可能的子数组组合，时间复杂度高达 O(n²)，在数据量大时效率低下。
2. **滑动窗口算法（双指针法）[[00:44](http://www.youtube.com/watch?v=7brhpecjOSY&t=44)]**：
   - **核心思想**：用两个指针（`i` 和 `j`）表示一个“窗口”的起始和结束位置。这个窗口在数组上滑动，从而在一次遍历中找到答案。
   - **窗口如何扩大**：<span style="color:#CC0000;">`j` 指针（结束位置）不断向右移动，将新的元素纳入窗口，并累加窗口内的元素和 `sum`</span> [[01:46:00](http://www.youtube.com/watch?v=7brhpecjOSY&t=6360)]。
   - **窗口如何缩小**：<span style="color:#CC0000;">当窗口内的元素和 `sum` 达到了目标值 `S`，就找到了一个满足条件的子数组。此时，需要记录下当前长度，然后尝试缩小窗口来寻找更优解。具体做法是：将 `i` 指针（起始位置）向右移动，并从 `sum` 中减去移出窗口的那个元素的值</span> [[02:08:00](http://www.youtube.com/watch?v=7brhpecjOSY&t=7680)]。
   - **<span style="color:#CC0000;">关键点 (`while` vs `if`</span>) [[03:18:00](http://www.youtube.com/watch?v=7brhpecjOSY&t=11880)]**：视频特别强调，<span style="color:#FF0000;">在缩小窗口时必须使用 `while` 循环</span>。因为在你将起始位置向右移动一位后，新的窗口和可能仍然满足条件，需要继续移动起始位置，直到找到当前 `j` 位置下长度最小的满足条件的子数组。如果用 `if`，则只会移动一次，可能会错过最优解。

总的来说，滑动窗口算法用 O(n) 的时间复杂度和 O(1) 的空间复杂度解决了这个问题，是一种在嵌入式开发中处理数据流或序列问题时非常有用的高效算法。

# 嵌入式算法面试问题与答案



以下是根据视频内容为您准备的，适合嵌入式算法面试的经典问题，旨在考察您对算法的理解深度和在实际场景中的应用能力。

#### 问题 1：请简述滑动窗口算法的核心思想，并说明它相比于暴力解法，在嵌入式系统等资源受限的环境中，最主要的优势是什么？



答案解析：

滑动窗口算法的核心思想是维护一个动态的、大小可变的“窗口”，<span style="color:#FF0000;">通过移动窗口的起始和结束边界来遍历序列的子集，从而在单次遍历中完成计算。它将暴力解法的 O(n²) 时间复杂度优化到了 O(n)。</span>

在嵌入式系统中，其主要优势体现在两个方面：

1. **高时间效率 (Time Complexity)**：嵌入式系统常常需要<span style="color:#FF0000;">实时处理传感器数据流或其他形式的连续数据</span>。O(n) 的时间复杂度意味着算法的处理速度与数据量成正比，能够保证实时性和快速响应，避免了 O(n²) 算法可能带来的处理延迟和系统卡顿。
2. **低空间复杂度 (Space Complexity)**：该算法通常<span style="color:#CC0000;">只需要常数级别的额外空间（几个变量用于存储指针位置、当前和、最小长度等），即 O(1) 的空间复杂度。嵌入式设备的内存（RAM）非常宝贵，这种低内存占用的特性使得算法可以在内存极小的微控制器（MCU）上运行</span>，而无需开辟大量缓冲区来存储中间计算结果。



#### 问题 2：在视频 [[03:18:00](http://www.youtube.com/watch?v=7brhpecjOSY&t=11880)] 处，作者强调了缩小窗口时必须使用 `while (sum >= S)` 而不是 `if (sum >= S)`。请解释这背后的原因，并举一个具体的例子说明如果使用 `if` 会导致什么错误。



答案解析：

这是<span style="color:#CC0000;">考察对滑动窗口算法精髓是否理解的关键问题</span>。

原因是：当我们的窗口和 `sum` 第一次满足 `>= S` 的条件时，我们找到了一个“可行解”，但它不一定是“最优解”（即长度最小的解）。我们的目标是让窗口尽可能地窄。

- **使用 `while`**：可以确保一旦 `sum >= S`，我们<span style="color:#CC0000;">会持续地从窗口左侧移除元素并更新长度，直到 `sum < S` 为止。</span>这个过程保证了对于当前的结束位置 `j`，我们找到了与之匹配的、长度最小的子数组。
- **使用 `if`**：只会检查一次条件。如果左侧元素移除后，窗口和仍然满足 `>= S` 的条件（例如，移除的元素很小，而新加入的元素很大），`if` 语句不会再次执行，我们就错过了继续缩小窗口、寻找更优解的机会。

举例说明：

假设数组 nums = [2, 3, 1, 2, 8, 3]，目标和 S = 10。

1. 窗口滑动到 `[2, 3, 1, 2]`，`sum = 8`，不满足条件。
2. `j` 右移，窗口变为 `[2, 3, 1, 2, 8]`，`sum = 16`。此时 `sum >= 10`。
   - **如果用 `if`**：
     - `if (16 >= 10)` 为真，更新最小长度为 5。
     - `sum` 减去 `nums[i]` (即 2)，`sum` 变为 14。`i` 右移。
     - `if` 逻辑结束，`j` 继续向右移动。最终我们可能找不到更短的解。
   - **如果用 `while`**：
     - `while (16 >= 10)` 为真，更新最小长度为 5。`sum` 减去 2 变为 14，`i` 右移，窗口变为 `[3, 1, 2, 8]`。
     - 循环继续，`while (14 >= 10)` 为真，更新最小长度为 4。`sum` 减去 3 变为 11，`i` 右移，窗口变为 `[1, 2, 8]`。
     - 循环继续，`while (11 >= 10)` 为真，更新最小长度为 3。`sum` 减去 1 变为 10，`i` 右移，窗口变为 `[2, 8]`。
     - 循环继续，`while (10 >= 10)` 为真，更新最小长度为 2。`sum` 减去 2 变为 8，`i` 右移，窗口变为 `[8]`。
     - 循环结束，因为 `8 < 10`。
   - 通过 `while`，我们正确地找到了最小长度 2（子数组 `[2, 8]`）。而 `if` 只会满足一次，给出的答案是 5，是错误的。



#### 问题 3：<span style="color:#CC0000;">如果题目要求改为“数组中可能包含负数”，那么视频中介绍的滑动窗口算法是否还能直接使用？为什么？如果不能，你有什么解决思路？</span>



答案解析：

<span style="color:#FF0000;">不能直接使用。</span>

**原因**：视频中的<span style="color:#FF0000;">滑动窗口算法</span>依赖于<span style="color:#CC0000;">一个核心的单调性假设</span>：<span style="color:#CC0000;">当窗口向右扩大（增加元素）时，窗口内的和会增加（或不变，如果元素为0）。正是因为这个特性，我们才可以在 `sum >= S` 时，放心地从左侧缩小窗口来寻找更优解。</span>

如果数组中包含负数，这个<span style="color:#FF0000;">单调性就被打破了。当我们从左侧移除一个负数时，窗口的和反而会增加。这使得窗口的收缩和扩张逻辑变得复杂，无法保证我们总是在朝最优解的方向前进。</span>

解决思路：

<span style="color:#CC0000;">对于包含负数的数组，滑动窗口不再适用，需要转换思路。一个常见的、更通用的方法是 前缀和 + 哈希表。</span>

1. **计算前缀和**：创建一个前缀和数组 `prefixSum`，其中 `prefixSum[k]` 表示原数组从 `0` 到 `k-1` 的元素之和。
2. **问题转换**：找到长度最小的子数组 `[i, j]` 使得 `sum(i, j) >= S`，就等价于找到 `j > i` 使得 `prefixSum[j+1] - prefixSum[i] >= S`，即 `prefixSum[i] <= prefixSum[j+1] - S`。
3. **使用哈希表（或单调队列）**：遍历 `j`，对于每个 `prefixSum[j+1]`，我们需要在 `i < j` 的所有 `prefixSum[i]` 中找到一个满足 `prefixSum[i] <= prefixSum[j+1] - S` 且 `j-i` 最小的值。这可以通过一个维护单调性的数据结构（如单调队列）或通过哈希表来优化查找过程，从而在 O(n) 或 O(n log n) 的时间内解决。

# 滑动窗口变体题目

当然可以。<span style="color:#CC0000;">滑动窗口问题的精髓在于其 **“双指针”** 的思想和 **“不走回头路”** 的特性，它将嵌套循环的暴力解法优化为单次遍历。理解滑动窗口的关键在于想清楚以下三个问题：</span>

1. **窗口内维护的是什么？** (例如：一个和、字符的频率、不同元素的个数)
2. **什么时候扩大窗口？** (通常是移动右指针 `right`，以纳入新元素)
3. **什么时候缩小窗口？** (这是最关键的逻辑，当窗口内的状态不再满足要求时，移动左指针 `left`)

下面我为您准备了三种极具代表性的滑动窗口变体，它们分别展示了不同的窗口收缩逻辑和问题思考角度，足以让您对滑动窗口产生“原来如此”的深刻理解。

### 变体一：固定长度的滑动窗口



这是最简单的一种模式，窗口大小始终不变。它考验的是你是否理解了滑动窗口相比于暴力解法的核心优势：**复用计算结果**。

**问题：** <span style="color:#CC0000;">给定一个整数数组 `nums` 和一个整数 `k`，请找出所有长度为 `k` 的连续子数组中的最大平均数。</span>

<span style="color:#CC0000;">“恍然大悟”的深刻理解：</span>

暴力解法是每次都重新计算 k 个元素的和，效率很低。而滑动窗口的核心在于，当窗口从 [i, ..., j] 滑动到 [i+1, ..., j+1] 时，你不需要重新把 k 个数加一遍。你只需要：

- **减去** 滑出窗口的元素 `nums[i]`。

- 加上 滑入窗口的新元素 nums[j+1]。

  这样每次滑动，操作都是常数时间 O(1)，而不是 O(k)。这正是其高效的本质。

**C++ 代码：**

C++

```C++
#include <iostream>
#include <vector>
#include <numeric> // For std::accumulate
#include <algorithm> // For std::max

double findMaxAverage(const std::vector<int>& nums, int k) {
    // 1. 计算初始窗口的和
    // 使用 long long 防止整数溢出
    long long currentSum = 0;
    for (int i = 0; i < k; ++i) {
        currentSum += nums[i];
    }
    
    long long maxSum = currentSum;

    // 2. 开始滑动窗口
    // right 指针从 k 开始，代表新滑入的元素
    for (int right = k; right < nums.size(); ++right) {
        // left 指针是 right - k
        int left = right - k;
        
        // 核心：减去滑出的元素，加上滑入的元素
        currentSum += nums[right] - nums[left];
        
        // 更新最大和
        maxSum = std::max(maxSum, currentSum);
    }
    
    // 3. 返回最大平均值
    return static_cast<double>(maxSum) / k;
}

int main() {
    std::vector<int> nums = {1, 12, -5, -6, 50, 3};
    int k = 4;
    // 窗口 [-5, -6, 50, 3] 的和最大，为 42。平均值为 10.5
    std::cout << "Max average: " << findMaxAverage(nums, k) << std::endl; // Output: 10.5
    return 0;
}
```

### 变体二：寻找最长/最短的动态窗口（带辅助数据结构）

这类问题的<span style="color:#CC0000;">窗口大小是动态变化</span>的，通常是<span style="color:#CC0000;">为了寻找满足某个条件的**最长**或**最短**子串/子数组。你需要一个辅助数据结构（如哈希表）来维护窗口内的状态。</span>

**问题：**<span style="color:#CC0000;"> 给定一个字符串 `s`，请你找出其中不含有重复字符的 **最长子串** 的长度。</span>

“恍然大悟”的深刻理解：

这个<span style="color:#CC0000;">问题的难点</span>在于<span style="color:#CC0000;">如何高效地判断窗口内有无重复字符</span>，以及<span style="color:#CC0000;">出现重复时，left 指针该如何移动</span>。

- **判断重复**：使用一个<span style="color:#CC0000;">哈希表 `window` 来记录窗口内每个字符出现的次数</span>。
- **收缩逻辑**：当 `right` 指针指向的字符在 `window` 中已经存在时（`window[char] > 1`），说明窗口内出现了重复。此时，我们必须收缩窗口。但 `left` 指针应该移动到哪里呢？**不是简单地 `left++`**。我们应该持续地移动 `left` 指针并更新 `window` 计数，直到重复的那个字符被移出窗口，即`window[char]`重新变回 1。

**C++ 代码：**

C++

```C++
#include <iostream>
#include <string>
#include <unordered_map>
#include <algorithm>

int lengthOfLongestSubstring(const std::string& s) {
    if (s.empty()) return 0;

    std::unordered_map<char, int> window; // 维护窗口内字符的频率
    int left = 0;
    int maxLength = 0;

    for (int right = 0; right < s.length(); ++right) {
        char charIn = s[right];
        window[charIn]++; // 扩大窗口

        // 当窗口内出现重复字符时 (charIn 的计数 > 1)
        // 开始收缩窗口
        while (window[charIn] > 1) {
            char charOut = s[left];
            window[charOut]--; // 将左侧字符移出窗口
            left++;            // 收缩
        }

        // 此时，从 [left, right] 的窗口内肯定没有重复字符
        // 更新最大长度
        maxLength = std::max(maxLength, right - left + 1);
    }
    
    return maxLength;
}

int main() {
    std::string s1 = "abcabcbb";
    std::cout << "Longest substring for '" << s1 << "': " << lengthOfLongestSubstring(s1) << std::endl; // Output: 3 ("abc")

    std::string s2 = "pwwkew";
    std::cout << "Longest substring for '" << s2 << "': " << lengthOfLongestSubstring(s2) << std::endl; // Output: 3 ("wke")
    return 0;
}
```

### 变体三：求解满足“恰好为 K”条件的子数组个数

这是滑动窗口问题中最具技巧性、也最能让人“恍然大悟”的变体。直接计算**“恰好为 K”**通常非常困难，因为当窗口满足条件时，继续扩张或收缩都可能轻易破坏这个“恰好”的状态。

“恍然大悟”的深刻理解：

这个问题的解决思路是一种精妙的数学转换：

count(恰好为 K) = count(最多为 K) - count(最多为 K-1)

为什么可以这么做？

- “最多为 K”这个条件是**单调**的。如果一个窗口满足“最多为 K 个不同元素”，那么它的所有子窗口也一定满足。这使得滑动窗口的收缩逻辑变得简单：当窗口不满足条件时（例如有了 K+1 个不同元素），我们才收缩窗口。
- 一个满足“最多为 K”条件的子数组，其不同元素的个数可能是 `1, 2, ..., K`。
- 一个满足“最多为 K-1”条件的子数组，其不同元素的个数可能是 `1, 2, ..., K-1`。
- 那么，前者的集合减去后者的集合，剩下的不就正是那些“恰好为 K 个不同元素”的子数组吗？

通过这个转换，我们把一个复杂的问题，变成了两个可以用标准滑动窗口模板解决的简单问题。

**问题：** 给定一个正整数数组 `nums` 和一个整数 `k`，返回 `nums` 中不同整数个数为 `k` 的子数组的个数。

**C++ 代码：**

C++

```C++
#include <iostream>
#include <vector>
#include <unordered_map>

// 辅助函数：计算最多有 k 个不同整数的子数组个数
int atMostK(const std::vector<int>& nums, int k) {
    if (k < 0) return 0;
    
    std::unordered_map<int, int> window;
    int left = 0;
    int count = 0;

    for (int right = 0; right < nums.size(); ++right) {
        window[nums[right]]++; // 扩大窗口

        // 当窗口内不同元素的数量超过 k 时，收缩窗口
        while (window.size() > k) {
            int numOut = nums[left];
            window[numOut]--;
            if (window[numOut] == 0) {
                window.erase(numOut);
            }
            left++;
        }
        
        // 核心理解：
        // 对于当前右指针 right，所有以 right 结尾且满足条件的子数组为：
        // [left, right], [left+1, right], ..., [right, right]
        // 总共有 right - left + 1 个
        count += (right - left + 1);
    }
    return count;
}

// 主函数
int subarraysWithKDistinct(const std::vector<int>& nums, int k) {
    // 运用“恍然大悟”的转换技巧
    return atMostK(nums, k) - atMostK(nums, k - 1);
}

int main() {
    std::vector<int> nums = {1, 2, 1, 2, 3};
    int k = 2;
    // 满足条件的子数组: [1,2], [2,1], [1,2], [2,1,2], [1,2,3] -> [2,3], [1,2,1,2]
    // 应该是: [1,2], [2,1], [1,2], [2,3], [1,2,1], [2,1,2], [1,2,1,2] -> 7个
    std::cout << "Subarrays with " << k << " distinct integers: " << subarraysWithKDistinct(nums, k) << std::endl; // Output: 7
    return 0;
}
```
