### 视频核心内容总结



视频围绕**“如何删除链表中所有值为 `val` 的节点”**这一问题，提出了两种解决方案，并重点对比了它们的优劣。



#### 方法一：直接在原链表上操作 (不使用虚拟头节点)



这种方法直接对传入的链表 `head` 进行操作。

- **核心逻辑**：
  1. **单独处理头节点**：由于头节点没有前驱节点，它的删除方式与普通节点不同。需要用一个 `while` 循环持续判断头节点的值是否为目标值，如果是，则将 `head` 指针后移 (`head = head.next`)，直到头节点不再是目标值或者链表为空。
  2. **处理非头节点**：遍历剩余的链表。使用一个当前指针 `cur`，判断 `cur.next` (即当前节点的下一个节点) 的值。如果 `cur.next.val` 是目标值，就执行删除操作：`cur.next = cur.next.next`。如果不是，`cur` 正常后移。
- **缺点 (视频中强调的痛点)**：
  - **逻辑不统一**：删除头节点和删除非头节点需要写两套完全不同的逻辑。
  - **代码复杂**：需要分开处理，容易出错，特别是对于初学者。
  - **边界条件处理麻烦**：比如链表为空、所有节点都需要被删除等情况都需要额外考虑。



#### 方法二：使用虚拟头节点 (Dummy Node) - (视频极力推荐)

为了解决方法一的逻辑不统一问题，引入了一个技巧性的节点。

- **核心逻辑**:
  1. **创建虚拟节点**：在原链表的头部 `head` 之前，创建一个新的节点 `dummyHead`，并让 `dummyHead.next = head`。
  2. **统一删除操作**：之后所有的删除操作都变成了“删除非头节点”的操作。因为即使是原链表的头节点，现在也变成了 `dummyHead` 的后继节点，它也有了前驱节点 `dummyHead`。
  3. **遍历和删除**：使用一个当前指针 `cur` 从 `dummyHead` 开始遍历。判断 `cur.next` 的值，如果匹配则删除 (`cur.next = cur.next.next`)，否则 `cur` 后移 (`cur = cur.next`)。
  4. **返回结果**：操作完成后，新的链表头节点是 `dummyHead.next`，返回它即可。
- **优点 (视频的核心思想)**：
  - **逻辑统一**：无论要删除的是否是原头节点，操作都完全一样，简化了代码逻辑。
  - **代码简洁**：只需要一个循环就能完成所有操作。
  - **轻松处理边界情况**：即使原链表为空，或者所有节点都被删除，该方法依然能正确工作，最后返回 `dummyHead.next` (此时为 `null`)。

### 补充与扩展

在视频内容的基础上，我为你进行更深入的补充和扩展：

#### 1. 完整的代码实现 (以 Java 为例)



视频中是在白板上书写伪代码，这里提供可以直接运行的完整代码，让你更清晰地对比两种方法的差异。

Java

```C++
/**
 * Definition for singly-linked list.
 * struct ListNode {
 * int val;
 * ListNode *next;
 * ListNode() : val(0), next(nullptr) {}
 * ListNode(int x) : val(x), next(nullptr) {}
 * ListNode(int x, ListNode *next) : val(x), next(next) {}
 * };
 */
class Solution {
public:
    // 方法一：直接在原链表上操作
    ListNode* removeElementsDirect(ListNode* head, int val) {
        // 1. 处理头节点（可能连续多个头节点都需要删除）
        while (head != nullptr && head->val == val) {
            ListNode* nodeToDelete = head; // 临时保存要删除的节点
            head = head->next;             // 移动头指针
            delete nodeToDelete;           // 释放原头节点的内存
        }

        // 如果链表为空或者所有节点都被删除了
        if (head == nullptr) {
            return nullptr;
        }

        // 2. 处理非头节点
        ListNode* current = head;
        // 确保 current->next 不为空，因为我们要判断 current->next->val
        while (current->next != nullptr) {
            if (current->next->val == val) {
                ListNode* nodeToDelete = current->next; // 临时保存要删除的节点
                // 删除 current->next 节点
                current->next = current->next->next;
                delete nodeToDelete; // 释放节点的内存
            } else {
                // current 指针后移
                current = current->next;
            }
        }
        return head;
    }

    // 方法二：使用虚拟头节点 (Dummy Node) - 更推荐
    ListNode* removeElementsWithDummy(ListNode* head, int val) {
        // 1. 创建虚拟头节点，并指向原链表头
        ListNode* dummyHead = new ListNode(0); // 节点值是多少不重要
        dummyHead->next = head;

        // 2. 使用 cur 指针从虚拟头节点开始遍历
        ListNode* current = dummyHead;
        while (current->next != nullptr) {
            if (current->next->val == val) {
                // 临时保存要删除的节点
                ListNode* nodeToDelete = current->next; 
                // 删除 current->next 节点
                current->next = current->next->next;
                // 释放节点的内存
                delete nodeToDelete;
                // 注意：这里 current 指针不后移，因为下一个节点可能也需要删除
            } else {
                // 只有当 current->next 不需要删除时，才后移
                current = current->next;
            }
        }
        
        // 3. 记录新链表的头节点，准备返回
        ListNode* resultHead = dummyHead->next;
        // 4. 释放虚拟头节点的内存
        delete dummyHead; 
        
        // 5. 返回新链表的头节点
        return resultHead;
    }
};
```



#### 2. 算法复杂度分析

- **时间复杂度**: O(N)
  - 两种方法都需要遍历整个链表一次，其中 N 是链表的节点数。因此时间复杂度是线性的。
- **空间复杂度**: O(1)
  - 方法一仅使用了几个额外的指针 (`current`)，是常数空间。
  - 方法二虽然创建了一个虚拟头节点 (`dummyHead`)，但只创建了一个，其空间开销是固定的，不随链表长度 N 的变化而变化，因此也属于常数空间。



#### 3. 虚拟头节点 (Dummy Node) 的深层价值

虚拟头节点是链表问题中一个极其重要且常用的技巧，它的价值远不止于本题。

- **统一逻辑，简化代码**：这是最核心的价值，如视频中所述，它将对头节点的特殊操作转化为普通操作。
- **简化边界条件处理**：你不再需要写 `if (head == null)` 这样的预判断。虚拟节点的逻辑天然地覆盖了以下情况：
  - **空链表**：`head` 为 `null`，`dummy.next` 指向 `null`，循环不执行，直接返回 `dummy.next` (`null`)，结果正确。
  - **所有节点都被删除**：循环会把所有节点都删掉，`dummy.next` 最终会指向 `null`，结果正确。
- **适用场景广泛**：除了删除节点，在**插入节点**、**反转链表**、**合并链表**等多种链表操作中，虚拟头节点都能大显身手。例如：
  - **LeetCode 21. 合并两个有序链表**：使用虚拟头节点可以方便地构建新链表，无需特殊处理第一个节点。
  - **LeetCode 92. 反转链表 II**：需要找到反转区间的“前一个”节点，虚拟头节点可以确保即使从第一个节点开始反转，也能找到它的“前驱”（即虚拟节点）。
