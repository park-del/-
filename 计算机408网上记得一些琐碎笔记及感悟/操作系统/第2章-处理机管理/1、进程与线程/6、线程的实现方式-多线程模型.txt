一、用户级线程
1、用户级线程由应用程序通过线程库来实现，所有的【线程管理工作】都由【应用程序负责】（包括线程切换）。
2、用户级线程中，【线程切换】可以在【用户态】下即可完成，无需操作系统干预。
3、在用户看来，是有多个线程，但是在操作系统内核看来，并没有意识到线程的存在。“用户级线程”就是“从用户视角能看到的线程”。

优缺点：
优点：用户级线程的切换在用户空间即可完成，不需要切换到核心态，线程管理的系统开销小，效率高。

缺点：当一个用户级线程被阻塞后，整个进程都会被阻塞，并发度不高。多个线程不可在多核处理机上运行。

用户级线程实现的逻辑：
while（ 1 ）
{
      if (true==0) { }
      if (true==1) { }
      if (true==2) { }

     true=(true+1)%3 ;
}
分析：这段代码相当于是一个用户级线程，这个用户级线程相当于同时在干3件事，相当于3个线程。


二、内核级线程
1、【内核级线程的管理工作】由操作系统内核完成。
2、线程调度、切换等工作都由内核负责，因此【内核级线程的切换】必然需要在【核心态】下才能完成。
3、操作系统会为每个内核级线程建立相应的TCB（线程控制块，Thread是线程的意思），通过TCB来对线程进行管理。“【内核级线程】”就是“【从操作系统内核视角看能看到的线程】”。
（将一个进程中的代码段部分分成n个部分，每个部分完成一个功能，则要实现该进程的所有工作就需要n个线程，可以通过一个内核级线程采用时间片方式实现这n个线程；这n个用户级线程互相竞争着这一个内核级线程，即互相竞争着这一个运行机会）

优缺点：
优点：当一个线程被阻塞后，别的线程还可以继续执行，并发能力强。多线程可在多核处理机上并行执行。

缺点：
一个用户级进程会占用多个内核级线程，线程切换由操作系统内核完成，需要切换到核心态，因此线程管理的成本高，开销大。




三、线程模型
在支持内核级线程的系统中，根据用户级线程和内核级线程的映射关系，可以划分为几种多线程模型。

1、一对一模型：一个用户级线程映射到一个内核级线程。 （这里就是一个用户级进程，即一个应用程序拥有多个内核级线程）

优点：当一个线程（这里指的是用户级线程）被阻塞后，别的线程（指的是该应用程序中的另外一个线程）还可以继续执行，并发能力强。多线程可在多核处理机上并行执行。

缺点：一个用户级进程（指的是一个应用程序，该应用程序中有多个用户级线程，如QQ这个进程中就有多个用户级线程，为语音聊天、视频聊天、文字处理的等）会占用多个内核级线程，线程切换由操作系统内核完成，需要切换到核心态（因为该应用程序中的一个用户级线程对应了1个内核级线程，因此进行用户级线程的切换实际上就是内核级线程的切换），因此线程管理的成本高，开销大；每当创建一个用户线程，相应地就要创建一个内核级线程，开销较大。


2、多对一模型：多个用户级线程映射到一个内核级线程。（这里就是一个用户级继承，即一个应用程序拥有一个内核级线程） 

优点：用户线程的切换在用户空间即可完成，不需要切换到核心态，线程管理的系统开销小，效率高。（这里就相当于利用代码的方式实现了多个并发运行的线程）

缺点：当一个用户级线程被阻塞后，整个进程都会被阻塞，并发度不高。多个线程不可在多核处理机上并行执行。


重点重点重点：
操作系统只“看的见”内核级线程，因此只有内核级线程才是处理机分配的单位。


3、多对多模型：n个用户级线程映射到m个内核级线程（n≥m）。（这里一个应用程序由n个用户级线程组成，对这n个线程的执行是由m个内核级线程来实现的）

克服了多对一模型并发度不高的缺点（一个阻塞全体阻塞），又克服了一对一模型中一个用户进程占用太多内核级线程，开销太大的缺点。

内核级线程中可以运行任意一个有映射关系的用户级线程代码，只有两个内核级线程中正在运行的代码逻辑都阻塞时，这个进程才会阻塞。

可以这么理解：
用户级线程是“代码逻辑”的载体；内核级线程是“运行机会”的载体。
内核级线程才是处理机分配的单位。例如：多核CPU环境下，左边这个进程最多能被分配两个核。
一段“代码逻辑”只有获得了“运行机会”才能被CPU执行。



自己的理解：
①用户级线程可以当成是一段代码，如QQ这个程序中肯定也是包含有很多代码的，有“视频聊天相关的代码”“有文字聊天相关的代码”“有文件传送相关的代码”。内核级线程可以当成是“运行机会”，可以当成是“CPU”，操作系统中有几个内核级线程就相当于是有几个CPU（线程，准确地说应该是内核级线程是操作系统进行调度的基本单位）。
②如果操作系统将QQ这个进程分成了3个内核级线程，则这3个内核级线程在一段时间内就可以同时并发地执行“3段代码”，即QQ这个进程中“视频聊天相关的代码”“有文字聊天相关的代码”“有文件传送相关的代码”这3个代码（用户级线程）就可以同时并发执行。
③在多对一模型中，多个用户级线程对应有一个内核级线程，这个内核级线程是轮流依次执行这几个用户级线程（代码逻辑）的，因此，给了我们一种这几个用户级线程同时发生的感觉。但是，当这个内核级线程在执行一个用户级线程被阻塞的时候（执行一个代码段需要等待某些事件发生），此时这个内核级线程就会由“运行态”切换到“阻塞态”，由于该进程只有一个线程，故阻塞队列中只有这一个线程，即使当等待的事情发生了以后，这个内核级线程会先切换到就绪态，而不是运行态。即这个内核级线程被阻塞后就不会在执行了，此时对应的就是所有的用户级线程都被阻塞。

④在一对一模型中，一个用户级线程对应有一个内核级线程，此时每一个内核级线程是不需要切换要执行的用户级线程的，只管执行自己的用户级线程（代码逻辑）就可以了。
⑤在多对多模型中，多个用户级线程对应有多个内核级线程，此时内核级线程中可以运行任意一个有映射关系的用户级线程代码，只有这个用户级线程对应的所有内核级线程都被阻塞时（即该用户线程代码执行阻塞，消耗一个内核级线程，然后执行时又阻塞，又消耗掉一个内核级线程）这个用户级线程才会被阻塞。（这中方式是多对一模型和一对一模型的折中）
