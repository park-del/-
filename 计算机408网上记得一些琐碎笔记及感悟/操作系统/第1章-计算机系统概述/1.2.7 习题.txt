操作系统的发展：
手工操作系统（没有操作系统）----------> 批处理操作系统（分为  单道批处理操作系统、多道批处理操作系统）----------> 分时操作系统 ---------->  实时操作系统（当分时操作系统应用于军工邻域而诞生出的一种新的操作系统）----------> 分布式操作系统（随着云计算的发展，近些年兴起的一种新型的操作系统，这个操作系统是用来管理一堆计算机中的硬件资源与软件资源的，传统的操作系统都是用来管理一台计算机的硬件与软件资源的）


09、
A、加大时间片是不利于改善分时系统的响应时间的。
原因：假设我们原来的时间片是1ms，则在3ms内可以有3个用户得到响应；假设我们的时间片变成了2ms，则此时3个用户要想都能够得到响应，就需要6ms。因此，加大时间片是不利于改善分时系统的响应时间的。


B、
静态页式管理：即基本分页存储管理，进程运行前就将所有页面调入内存。
动态页式管理：即请求分页存储管理，当需要使用进程的某个页面时才将该页面调入内存。

例如：
微信程序中是包含有许多模块的，有“微信文字聊天模块”“微信视频聊天模块”。
微信程序是存放在“外存”中的，当我们启动微信程序的时候，就会将微信程序给调入到内存中。
如果我们是在启动微信程序的时候将“微信程序中所有模块”都调入到内存中（每一个模块由一页或者几页组成），这种存储管理方式就是“静态页式管理”；
如果我们是在启动微信程序的时候只将“当前要使用的模块（如微信文字聊天模块，就是将当前要使用的模块对应的那几页给调入到内存中）”调入到内存中，这种存储管理方式就是“动态页式管理”。

因此，
当我们启动微信的时候，采用静态页式管理启动微信程序的响应时间会更长，而采用动态页式管理启动微信的响应时间会更短。
当启动了微信之后，用户和微信之间的交互（即是微信在运行的时候），采用静态页式管理微信的响应时间会更短，而采用动态页式管理微信的响应时间会更长。（因为，当我们从文字聊天切换到视频聊天时，由于采用静态页式管理的微信的视频聊天模块就已经是在内存中了，因此，采用静态页式管理的响应时间会更短）


D、
代码可重入：多个进程/线程共享一段代码，执行结果不会相互影响。这类代码可以很安全地被多个进程/线程共享。（代码可重入对系统的响应时间并没有什么影响）

可重入的代码：
void test( )
{
     printf(“Hello world\n”)；
}

分析：上面这段代码就是可重入的代码，假设我们现在有 3个进程或者线程，则这3个进程或者线程是可以共享这段代码的，彼此之间不会影响。


不可重入的代码：
int v=1；
int f( )
{
   v += 2；
   return v；
} 
分析：上面这段代码就是不可重入的代码，假设我们现在有 3个进程或者线程，则这3个进程或者线程会访问同一个全局变量v，彼此之间是会产生影响的，我们是通过进程之间的同步互斥机制来去解决相互影响的问题的。


C、
我们可以为每一个进程都设置一个优先级，当有多个进程同时响应的时候，CPU先去处理优先级高的那个进程。
非抢占式：指的是当一个进程正在占用CPU资源的时候，此时如果已经有一个更高优先级的进程已经就绪了，此时这个更高优先级的进程也是不会被响应的，其必须等到CPU执行完当前这个进程之后，才会获得CPU的使用权。

C选项也不是很严谨：对于高优先级的进程来说，是可以改善系统的响应时间的，但是对于低优先级的进程来说，确是会增长系 统的响应时间的。



10、
多道批处理系统追求的目标：
充分利用I/O设备。（不同的进程可能会使用到不一样的I/O设备，而多个进程并发运行就可以使得系统中各种各样的I/O设备都尽可能多的同时投入工作，因此，多道程序运行可以有效地提高I/O设备的利用率）
提高系统吞吐率。
充分利用内存。（内存中同时存在多个进程的数据）

多道批处理系统的局限性：无法快速响应用户，没有人机交互性。
当用户将自己的程序提交给操作系统后，整个程序执行的过程中用户和操作系统是不可以有任何交互的，只有操作系统把这个作业完全运行完了之后，用户才可以从输出设备那取走自己程序运行的结果。由于用户在运行自己整个程序的过程中，用户和机器都不可以进行交互（比如用户提出的各种请求，如调试等，操作系统都不会响应），因此称为“没有人机交互性”。

由于多道批处理系统不能使得每个用户都能够得到响应，因此，人们提出了分时操作系统，用户在自己所处的时间片中是可以通过键盘鼠标等一些外部设备来与自己的进程进行一些交互的。因此，分时操作系统追求的目标是“比较快速地响应用户”。（打印机使用的操作系统就是属于多道批处理操作系统的，打印机一旦开始运行的时候，我们在打印机执行的时候发给打印机的各种请求打印机都是无法响应的；我们现在电脑和手机上使用的各种操作系统都是属于分时操作系统的，它可以响应用户的请求，即是各个应用程序的请求，具备人机交互性）
 

14、
补充知识点：操作系统的发展
手工操作系统（以前的纸袋机，打点） （主要矛盾：人机速度矛盾导致资源利用率低）----------> 批处理操作系统 ----------> 分时系统 ---------->  实时系统 ----------> PC操作系统

批处理系统：
①单道批处理系统：引入脱机输入/输出技术（磁带）；监督程序（操作系统的雏形）。
主要矛盾：CPU等待I/O导致资源利用率低。（只有将磁带中的数据读取到主存中，CPU才可以访问，因此在将数据从磁带调入到主存的这段过程中,CPU是需要等待的，等待这个I/O结束之后，CPU才可以接着下一个作业）

解释：
脱机输入输出技术：以前每装一次程序人们就需要拆装一次纸袋，引入了脱机输入/输出技术之后，人们就提前把纸袋机上的数据读取并且存放在一个更高速的磁带上，我们的CPU是从磁带上来快速地读取数据，而不是像以前一样等待CPU来慢速地读取。
监督程序：每当做一个作业结束之后，我们的监督程序就会让操作系统从磁带上读取一个新的作业来让CPU处理，因此，监督程序就代替了人们手工管理作业调度的过程。

②多道批处理系统：引入中断技术。（当CPU在执行一个进程的时候，如果这个进程需要用到I/O设备而进行了等待，此时CPU就会转而去执行另外的一个进程）


15、
补充知识点：
CPU利用率：CPU忙的时间所占的比例。
系统开销：处理处理作业之外，系统在进程、内存管理上消耗的时间。
I/O设备利用率：I/O设备忙的时间所占的比例。
系统吞吐量：单位时间内CPU完成作业数量。（计算机网络里面的吞吐量指的是单位时间内通过某个网络的数据量，这里的单位时间指的是“发送时延+传输时延+接收方发送时延+传输时延”）

eg.
作业A：CPU 5ms----------I/O 5ms----------CPU 5ms----------I/O 5ms
作业B：CPU 5ms----------I/O 5ms----------CPU 5ms----------I/O 5ms

单道系统：先完成作业A的“CPU 5ms----------I/O 5ms----------CPU 5ms----------I/O 5ms”，再完成作业B的“CPU 5ms----------I/O 5ms----------CPU 5ms----------I/O 5ms”。

多道系统：
作业A：CPU 5ms		I/O 5ms		CPU 5ms		I/O 5ms		
作业B：			CPU 5ms		I/O 5ms		CPU 5ms		I/O 5ms

单道程序系统：完成2个作业，总耗时40ms，CPU利用率=20/40=50%，I/O设备利用率=20/40=50%
多道程序系统：完成2个作业，总耗时25ms，CPU利用率=20/25=80%，I/O设备利用率=20/25=80%

由于我们的多道系统内存中有多道程序，因此会多花一些时间在进程管理，内存管理上。因此，多道系统的系统开销要比单道系统的系统开销大。
