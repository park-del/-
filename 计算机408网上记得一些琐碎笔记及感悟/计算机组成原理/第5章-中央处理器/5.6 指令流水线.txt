指令流水线的基本概念
性能指标

1、指令流水的定义
一条指令的执行过程可以分成多个阶段（或过程）。
根据计算机的不同，具体的分法也不同。

取指     分析   执行

取指：根据PC内容访问主存储器，取出一条指令送到IR中。（取指时不一定是从主存中取，也可能是从cache中取的）
分析：将指令中的操作码送入到指令译码器ID中，对指令中的操作码进行译码，按照给定的寻址方式和地址字段中的内容形成操作数的有效地址EA，并从有效地址EA中取出操作数。（这里的操作数可能是位于主存中、可能是位于寄存器Ri中、可能是位于Cache中）
执行：根据操作码字段，完成指令规定的功能，即把运算结果写到通用寄存器或主存中（或cache中）。

特点：每个阶段用到的硬件不一样。


设取指、分析、执行3个阶段的时间都相等，用t表示，按以下几种执行方式分析n条指令的执行时间：
（1）顺序执行方式
 从第k条指令一直执行到第k+1条指令：
【取指k】【分析k】【执行k】【取指k+1】【分析k+1】【执行k+1】

传统冯诺依曼采用顺序执行方式，又称串行执行方式。
优点：控制简单，硬件代价小。
缺点：执行指令的速度较慢，在任何时刻，处理机中只有一条指令在执行，各功能部件的利用率很低。

采用顺序执行方式执行指令时，执行n条指令需要：T=n × 3t 的时间。


（2）一次重叠执行方式（第2条指令会和第1条指令在一个阶段有重叠，因此叫做一次重叠）

		                                       【取指k+2】【分析k+2】【执行k+2】
                               【取指k+1】【分析k+1】【执行k=1】
【取指k】【分析k】【执行k】

优点：程序的执行时间缩短了1/3（宏观上看，采用一次重叠方式时，执行每条指令需要2t的时间，采用顺序执行的方式时，执行每条指令需要3t的时间，因此，采用一次重叠方式相比较于采用顺序执行的方式，执行每条指令的时间缩短了1/3），各功能部件的利用率明显提高。

缺点：需要付出硬件上较大开销的代价，控制过程也比顺序执行复杂了。


采用一次重叠执行方式执行指令时，执行n条指令需要：T = 3 t + ( n-1 )×2t = ( 1+2n )t
分析：采用一次重叠执行的方式时，执行第1条执行需要“3t”的时间，之后每执行1条指令只需要花费 2t 的时间就可以了，因此执行n条指令需要花费 T = 3 t + ( n-1 ) 2t  = ( 1+2n )t 的时间。


（3）二次重叠执行方式

		    【取指k+2】【分析k+2】【执行k+2】
                【取指k+1】【分析k+1】【执行k=1】
【取指k】【分析k】【执行k】

特点：与顺序执行方式相比，指令的执行时间缩短近 2/3。这是一种理想的指令执行方式，在正常情况下，处理机中同时有3条指令在执行。

用二次重叠执行方式执行指令时，执行n条指令需要：T = 3 t + ( n-1 )×t = ( 2+n )t

注意：也可以把每条指令的执行过程分成4个或5个阶段，分成5个阶段是比较常见的做法。

3、流水线的性能指标
（1）吞吐率：吞吐率是指在单位时间内流水线所完成的任务数量，或是输出结果的数量

理解：吞吐率指的就是 每s钟CPU所执行的指令数量，假设我们将一个指令执行的过程划分为了k个阶段，每个阶段所需要花费的时间是△t，则执行完一条指令需要花费 k△t 的时间。如果我们采用的是 k-1 次重叠的指令流水线的方式，则执行n条指令需要花费时间为 “k△t +（n-1）△t”，即“（k+n-1）△t”。此时平均每执行一条指令需要花费时间“n / [（k+n-1）△t ]”，所求出的“(n / [（k+n-1）△t ]”就是为“采用了k-1次重叠方式的指令流水线的吞吐率 TP”。当执行的指令非常多时，即 n--->∞时，第1条指令的作用近似忽略，此时得到了理想情况下的该指令流水线的吞吐率“TPmax = 1 / △t”。

一条指令的执行分为k个阶段，每个阶段耗时 △t，一般取 △t=一个时钟周期。（△t应该是包含多个时钟周期的，这里是取最理想的情况下，即△t取一个时钟周期）

（2）加速比：完成同样一批任务，不使用流水线（指的就是顺序执行）所用的时间与使用流水线所用的时间之比。
设T0表示不使用流水线时的执行时间，即顺序执行所用的时间；Tk表示使用流水线时的执行时间。
则计算流水线加速比（S）的基本公式为 S=T0/Tk。

理解：将指令划分为了k个阶段，每个阶段所需要的时间为 △t，则顺序完成n个任务需要时间 T0=nk△t，假设我们采用了“k-1次重叠方式的指令流水线”，则完成n个任务需要 Tk=k△t+（n-1）△t。则该指令流水线的加速比（S）= T0/Tk = n k △t / （k △t +（n-1）△t ）= k n /（k+n-1）。当执行的指令非常多时，即 n--->∞时，最大加速比为Smax=k（S在n--->∞时的极限值就是为k）。

（3）效率：流水线的设备利用率称为流水线的效率。
流水线效率 E= n个任务占用k时空区有效面积 / n个任务所用的时间与k个流水段所围成的时空区总面积 = T0 / kTk 。

理解：结合着时空图来理解这个效率。假设有n个任务，我们将指令流水线划分为了 k 个阶段，则整个矩形的高就为k，整个矩形的长就是采用了“k-1次重叠方式的指令流水线”所花费的时间Tk=k△t + (n-1)△t ，时空图中n个任务占用时空区的有效面积就是为 n个k△t，就是 T0（顺序执行n个任务所需要花费的时间）。当执行的指令非常多时，即 n--->∞时，n个任务所占用的时空区所占的比例会越来越大，设备空闲时的时空区所占的比例会越来越小，因此最高效率为 Emax=1。




2、指令流水线的影响因素和分类
（1）5段式指令流水线概述：
我们之前所学过的指令阶段的划分是一种方式，下面这是一种 RISC精简指令集系统 中的指令划分为5个阶段的过程：
5段式指令流水线的设置：IF（取指阶段，fetch表示“取出”）、ID（译码阶段，decode表示“译码”）、EX（执行阶段，execute表示“执行”）、M（访存阶段，M表示内存）、WB（写存阶段，write back 表示写回）

注意：
每个阶段所需要的耗时一般都是不一样的，为了我们方便指令流水线的设计，我们一般选取“耗时最长的那个阶段”作为“指令流水线中的每个阶段的时间”。
流水线每一个功能段部件后面都要有一个缓冲寄存器，或称为锁存器，其作用是保存本流水段的执行结果，提供给下一流水段使用。

指令cache与数据cache：
cpu内部的cache分成了两部分，分别是指令cache和数据cahce，其中指令cache是用来存放指令的，数据cache是用来存放数据的。IF阶段（取指阶段）对应的是指令cache，M（访存阶段）对应的是数据cache。在IF阶段，cpu会从指令cache中取指令，指令cache中没有的话才是会访问主存的（一般指令cache的命中率都是很高的），在M阶段，cpu会从数据cache中取数据，数据cache中没有的话才是会去访问主存的。将cache分为了“指令cache”和“数据cache”，则此时“IF阶段”与“M阶段”的硬件部件就可以独立的工作，更加方便指令流水线的设计。

5个阶段中各个阶段进行的工作：
①IF阶段（取指阶段）：根据PC给出的地址，从指令cache中找出当前要执行的指令，然后将取出的指令放在IF阶段中的锁存器里面。
②ID阶段（译码阶段）：从IF阶段的锁存器中取出指令并对这个指令进行译码，除此之外这个阶段还会完成取数的操作，取数操作就是“把当前这个指令所需要用到的操作数从通用寄存器中把它取出来，然后放到锁存器A和B中”，如果是为立即数的话，则就从指令中取出这个立即数将其放到“立即数锁存器中”。

注意：这和我们之前学习过的“操作数可以来自于主存不一样”，在RISC精简指令集系统下，我们所需要使用的操作数都是只能够来自“通用寄存器的”，不能够是直接来自于“主存的”，如果需要使用的操作数在主存中的话，则一定是要先将主存中的这个操作数取出放到通用寄存器中，然后再从通用寄存器中取出这个操作数放入到锁存器A和B中。

③EX阶段（执行阶段）：ALU的两个输入端分别来自于锁存器A和锁存器B，这里完成的是取出锁存器A中的操作数A和锁存器B中的操作数B，通过ALU对它们进行运算，注意ALU的一个输入端也是有与立即数锁存器Imm相连接的，即“ALU的一个输入可以是为指令中的立即数的”。同时，会把运算的结果放入到一个锁存器中。

④M阶段（访存阶段）：将ALU的运算结果取出放入到数据cache中，或者，将ALU的运算结果直接取出放入到一个锁存器中。

⑤WB阶段（写回阶段）：可以直接从M阶段的锁存器中取出ALU运算的结果，将其放入到一个锁存器中，也可以从数据cache中取出一个数据放入到锁存器中。执行写的命令，将锁存器中的内容写入到通用寄存器中，或者写入到主存中。


（2）影响流水线的因素
①结构相关（资源冲突，其实就是操作系统中的互斥问题）
由于多条指令在同一时刻争用同一资源（如都要访问主存，都要访问某一个寄存器）而形成的冲突称为结构相关

解决办法：
《1》后一相关指令暂停一周期
《2》资源重复配置：数据存储器+指令存储器（即是存放指令的cache和存放数据的cache并行运行，避免了访指令，与访数据的冲突）

②数据相关（数据冲突，其实就是操作系统中的同步问题）
数据相关指在一个程序中，存在必须等前一条指令执行完后才能执行后一条指令的情况，则这两条指令即为数据相关。（即这几条指令的执行有先后顺序）

解决办法：
《1》把遇到数据相关的指令及其后续指令都暂停一至几个时钟周期，直到数据相关问题消失后再继续执行。可分为硬件阻塞（stall）和软件插入“NOP”两种方法。
理解：当一个指令A要用到另一个指令B修改完之后的数据，必须要等到指令B执行完之后指令A才可以再执行。此时可以采用硬件阻塞的方式，先阻塞指令A的执行，待指令B执行完之后，再执行指令A。

《2》数据旁路技术。
在ALU的一个输出端直接连接一个线路将运算结果直接输出到另一个指令的ALU的输入端。

《3》通过编译器调整指令执行顺序。
当前某一个指令A需要用到另一个指令B执行的结果，而我们可以将一些毫不相关的指令与指令B构成流水线，此时相比较于《1》中的方式来说，就是用阻塞的时间执行了其他的指令，当指令B执行完之后，我们就可以执行指令A了。


③控制相关（控制冲突）
当流水线遇到转移指令和其他改变PC值的指令而造成断流时，会引起控制相关。

除了“转移指令”之外，还有“函数调用”“函数返回”“发生中断”都是会导致控制相关的问题的。

解决办法：
《1》转移指令分支预测。简单预测（永远猜true或false）、动态预测（根据历史情况动态调整）
《2》预取转移成功和不成功两个控制流方向上的目标指令。
《3》加快和提前形成条件码。
《4》提高转移方向的猜准率。

3、流水线的多发技术
（1）超标量流水线技术（在同一时刻同时执行多条指令）
每个时钟周期内可并发多条独立指令。
要配置多个功能部件。
不能调整指令的执行顺序。
通过编译优化技术，把可并行执行的指令搭配起来。

（2）超流水技术
在一时钟周期内再分段（3段）
在一个时钟周期内一个功能部件使用多次（3次）
不能调整指令的执行顺序。
靠编译程序解决优化问题。


（3）超长指令字
由编译程序挖掘出指令间潜在的并行性，
将多条能并行操作的指令组合成一条，
具有多个操作码字段的超长指令字（可达几百位）
