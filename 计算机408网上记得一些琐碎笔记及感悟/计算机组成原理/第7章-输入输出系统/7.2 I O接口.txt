
I/O接口：又称 I/O控制器、设备控制器，负责协调主机与外部设备之间的数据传输以及命令的发送。


1、I/O接口的作用

	《== 数据总线 ==》  数据寄存器  
CPU         《== 地址总线 ==》  控制寄存器  《==  USB连接线  ==》 I/O设备（如键盘）
	《== 控制总线 ==》  状态寄存器  


注意：上述中“数据寄存器、控制寄存器、状态寄存器”都是与“数据总线”相连的，而“地址总线”是与“地址译码”相连的，“控制总线”是与“I/O控制逻辑”相连的。


数据缓冲：通过数据缓冲寄存器（DBR）达到主机和外设工作速度的匹配。（一个慢速的外设可以慢慢的往这个数据寄存器中写数据，当这个数据寄存器中的数据写满了之后，I/O接口就会通知CPU，CPU可以很快地将这个数据给取走）

错误或状态监测：通过状态寄存器反馈设备的各种错误、状态信息，供CPU查用。（I/O设备还需要给CPU反馈各种状态信息，如目前工作是否已经完成，当前是否已经就绪。I/O接口需要不断地查外设的状态，当这个外设的状态发生了改变的时候，I/O接口对这个状态寄存器中的内容进行修改）

控制和定时：接收从控制总线发来的控制信号、时钟信号。（I/O接口收到CPU发送过来的命令之后，需要给相应的I/O设备发出对应的控制信号。同时，为了能够让各种外设与主机之间相互协调配合着工作，所以I/O接口也需要通过控制总线来接收CPU发送过来的一系列时钟信号）

数据格式转换：串--并、并--串  等格式转换。（很多I/O设备输入或者输出数据的时候都是串行输入或者输出的，即都是 1bit 1bit 的输入或者输出，我们CPU通过数据总线把数据送到I/O接口，或者从I/O接口把数据送到CPU的时候，是采用并行的方式的。因此，I/O接口就需要实现数据格式的转换，串行的转并行，并行的转串行。）

与主机和设备通信：实现  主机--I/O接口--I/O设备  之间的通信。


对数据格式转换的理解：
USB连接线是为一种串行总线的，而CPU与外设或者主存进行信息交互的“数据总线、地址总线、控制总线”都是为并行总线的。
当I/O接口中的数据寄存器串行地接收到了I/O设备的数据之后，要先将接收到的 1bit、1bit 的数据先存放到数据寄存器中，也叫作数据缓冲寄存器，然后在同时将 32bit 的数据传送给CPU（假设CPU中的数据总线的位数是为32位的话）。同理，当I/O接口一次性并行地接收到了CPU传送过来的32bit的数据之后，也是要先将其存放到数据寄存器中的，然后在1bit 1bit的通过USB总线传送给I/O设备。


2、I/O接口工作原理
一个I/O接口可能连接多个外设。

									                |  ←----→ 数据
	    ------------→【数据缓冲寄存器】←------              --------------→【外设界面控制逻辑】---|  ←-------状态
	 |				   |	 |			                |  -------→控制
数据线←   |				   |	 |		……………………
	    ------------→【状态/控制寄存器】          |	 |		……………………
			        ↑		   |	 |		……………………
			        ↓                         ↓             |		……………………
地址线←---------------------→	【地址译码和I/O控制逻辑】←---		……………………
控制线←---------------------→	【地址译码和I/O控制逻辑】------------------→【外设界面控制逻辑】


CPU操控打印机进行打印的任务：
CPU首先要将打印机所对应的命令“一串二进制代码”输入到“控制寄存器”中。（这一串二进制代码的大小为一个字，将这串二进制代码称为一个“命令字”或者“控制字”）
提示：不同I/O设备所能够识别的“命令字”都是不一样的，是厂家事先规定好的，是只有厂家才事先知道的。
I/O接口就会在“I/O控制逻辑”的指挥下，就会根据CPU发送过来的命令字，去给对应的设备发出一系列的控制信号（就是一系列的电信号）。
提示：启动打印机也是通过上面这种方式的。
接下来，CPU需要从“状态寄存器”里面去取出“状态字”，根据“状态字”来确定此时设备是否已经就绪，或者此时设备的工作是否已经完成，都是从这个“状态寄存器”中来查询的。
如果打印机已经就绪了的话，接下来CPU就需要通过数据总线将打印机要打印的数据写入到“数据寄存器”中，然后再在这个“I/O控制逻辑电路”的控制下，把这个数据逐个的输出到打印机中。
当打印机完成之后，打印机就可以给这个I/O接口一个反馈，当这个I/O接口检测到打印机的工作已经完成之后，就会修改相应的“状态寄存器中的内容”。
CPU就可以通过状态寄存器来得知I/O操作的完成。

CPU可以通过“轮询检查”的方式来不断检查“状态寄存器”里面的内容，从而确定对应设备的I/O操作是否完成；I/O接口当检测到对应的I/O设备已经完成了之后，可以通过“控制线”给CPU发送一个中断请求信号，当CPU检测到这个中断信号的时候，再来对这个中断进行处理。

为什么把状态寄存器和控制寄存器写在一起？
因为 控制寄存器、状态寄存器 在使用时间上是错开的，因此有的I/O接口中可将二者合二为一，只用一个寄存器来完成两个功能。




3、I/O端口

I/O控制器中的各种寄存器称为“I/O端口”，将“数据寄存器”称为是“数据端口”，将“控制寄存器”称为是“控制端口”，将“状态寄存器”称为是“状态端口”。
由于I/O接口内部有多个I/O端口，故CPU在进行读或者写的时候就需要指明其要对哪一个端口进行读，或者进行写。

地址线：CPU会通过地址线来指明其要往哪个寄存器（往哪个端口中，我们通常）中读数据，或者写数据。
控制线：CPU通过控制线来发出读或者写的命令，来指明对这个地址线指明的I/O端口是要进行读还是要进行写。（注意：I/O接口不可以通过控制线来发送向CPU的反馈信号的，I/O接口应该是通过数             据线来发送向CPU的反馈信号的；I/O接口可以通过控制线来发送总线请求信号或者握手信号的，CPU通过控制线发送总线仲裁信号或者握手信号）
数据线：CPU要输出到外设的数据，或者，外设要输入主机（指的是 CPU、主存）中的数据都会通过数据总线的传送，放到“I/O接口中的数据缓冲寄存器中”，放到“CPU中的某个寄存器中”。除此              之外，除了输入输出的数据之外，数据总线也会用于传输“状态字”“命令字（控制字）”相关的信息。除此之外，数据总线还可以用来传输“中断类型号”。

I/O接口可以接多个设备，那么CPU如何确定要操作的设备呢？
在有的系统中，地址线除了指明CPU要读要写的寄存器之外，也有可能用于指明具体的设备编号，此时寄存器的编号和设备编号要分开两次进行传输。
我们需要连接多个外设，那么我们就让每一个外设都对应有一个与之对应的一组“数据寄存器、状态寄存器、控制寄存器”就可以了，假设我们现在有两组外设，我们就需要设置两组I/O端口，两组I/O端口就会有4个相互独立的寄存器，CPU对不同的寄存器进行读或者写就相当于CPU对不同的设备进行操作。因此，我们可以给每一组设备都设置一组寄存器，当CPU操作不同组别的寄存器时就相当于是在操作不同的设备。


为了表明CPU要访问的是哪一个寄存器，因此，我们就需要给这个寄存器，给这个端口进行编址。
数据端口：CPU可以读，可以写。
控制端口：CPU只能写
状态端口：CPU只能读

统一编址：I/O端口的编址和内存的编址是一整套的东西。（靠【不同的地址码】就可以区分内存和I/O设备。访存类的指令都可以访问I/O端口，如LOAD访存指令就可以访问I/O端口，此时只需要给出I/O端口的对应的主存地址就可以）
独立编址：I/O端口的编址和内存的编址是相互独立的。（靠【不同的指令区】分内存和I/O设备。只能用专门的【I/O指令】访问I/O端口）

注意：I/O指令是为特权指令的，CPU是通过I/O指令来访问I/O端口的，I/O指令本质上就是读操作，或者写操作，即CPU执行I/O指令（一串01代码）完成的是对I/O接口中的某个端口的读操作或者写操作。

 

4、分类

按数据传送方式可以分为：
并行接口：一个字节或一个字所有位同时传送。
串行接口：一位一位地传送。

按主机访问I/O设备的控制方式可以分为：（就是主机与CPU与I/O接口之间进行数据交互的方式，主机包含了CPU与主存，程序查询接口和中断接口是用来实现CPU与外设之间的数据交互的，DMA接口是用来实现主存与外设之间的数据交互的）
