# 1.从indeo结点底层理解目录x权限

<span style="color:#FF0000; background:#00FF80;">我是不是可以这样理解呢，目录权限中的w权限是修改目录项的内容，包括目录项的修改，添加和删除。修改比较好理解，因为修改目录项（文件或目录）的名字则对应的inode结点中的名字也要跟着修改，此时肯定是需要目录的x权限找到这个inode结点来进行修改的吧；如果修改的不是名字，而是一些属性比如权限、时间啥的，此时就不需要目录的w权限，只需要x权限找到这个inode结点就可以了。假设是新增目录项，此时肯定是需要创建一个新的inode结点的吧，这里创建inode结点应该也是属于x权限来进行管理的吧。假设是删除目录项，肯定是需要对inode结点中的硬链接数啥的进行修改，肯定也是需要访问这个inode结点的，肯定也是需要x权限的吧。我的理解对吗。</span>

你的理解**大方向很对**：目录的 `w` 确实就是控制“能不能修改目录项”，包括**添加、删除、改名**。

但是你里面有几个关键点需要修正：

> **inode 里面一般不保存文件名。**
> 文件名保存在目录项里。
> 所以改名时，不是“修改 inode 里的名字”，而是**修改目录文件里的目录项名字**。

------

## 1. 先建立正确模型

假设有：

```bash
test/a.txt
```

底层可以理解成：

```text
test 目录文件的数据块：

a.txt  ->  inode 1001
```

而 `inode 1001` 里面保存：

```text
文件类型
权限
所有者
所属组
大小
时间戳
硬链接计数
数据块地址
```

注意：

```text
inode 里面通常没有 a.txt 这个名字
```

文件名 `a.txt` 是目录文件里的内容。

------

## 2. 修改文件名：改的是目录项，不是 inode 里的名字

比如：

```bash
mv test/a.txt test/new.txt
```

本质是把 `test` 目录里的目录项：

```text
a.txt    -> inode 1001
```

改成：

```text
new.txt  -> inode 1001
```

所以这里修改的是：

```text
test 目录文件的数据块内容
```

不是修改 `inode 1001` 里的名字。

因此需要：

```text
test 目录的 w + x
```

其中：

```text
w：允许修改 test 目录里的目录项
x：允许在 test 目录中查找 a.txt 这个名字
```

所以你说“改名需要目录的 x 权限找到 inode”，这个有一半对。更准确是：

> <span style="color:#FF0000;">需要目录 `x` 权限，是为了在目录中查找旧名字 `a.txt`，并定位这个目录项；不是因为 inode 里面有名字要修改。</span>

------

## 3. 修改文件属性：不需要父目录 w

比如：

```bash
chmod 600 test/a.txt
```

或者：

```bash
touch test/a.txt
```

如果 `a.txt` 已经存在，这些操作主要修改的是 `a.txt` 对应 inode 里的元信息：

```text
权限
时间戳
所有者
所属组
```

<span style="color:#FF0000;">这时候一般不需要修改 `test` 目录的目录项，因为：</span>

```text
a.txt -> inode 1001
```

<span style="color:#FF0000;">这个映射关系没有变。</span>

所以不需要 `test` 的 `w` 权限。

但是需要：

```text
test 目录的 x 权限
```

因为你要通过路径 `test/a.txt` 找到 `a.txt` 对应的 inode。

所以可以这样记：

```text
修改文件内容或属性：通常不需要父目录 w
通过路径找到文件：需要路径上目录的 x
```

举例：

```bash
chmod 600 test/a.txt
```

大致需要：

```text
test 目录：x
a.txt 文件：你是所有者，或者有足够权限
```

不需要：

```text
test 目录：w
```

------

## 4. 新增目录项：需要父目录 w + x，但“创建 inode”不是由 x 管理

比如：

```bash
touch test/c.txt
```

如果 `c.txt` 不存在，本质是：

```text
1. 创建一个新的 inode，比如 inode 1002
2. 在 test 目录中新增目录项：

c.txt -> inode 1002
```

这里需要：

```text
test 目录的 w + x
```

其中：

```text
w：允许往 test 目录中新增目录项
x：允许进入/搜索 test 目录
```

但是要注意：

> 创建 inode 不是由目录的 `x` 权限“管理”的。
> `x` 只是让你能进入/搜索这个目录。
> 真正允许新增文件名的是目录的 `w` 权限。

所以你的这句话需要修正：

> “创建 inode 应该也是属于 x 权限来管理的吧”

更准确应该是：

> 创建新文件需要在父目录里新增目录项，所以核心权限是父目录 `w`；同时为了能在这个目录中操作，还需要父目录 `x`。<span style="color:#FF0000; background:#00FF80;">inode 的分配是文件系统内部完成的，不是单独由 `x` 权限控制。</span>

------

## 5. 删除目录项：需要父目录 w + x，不看文件本身 w

比如：

```bash
rm test/a.txt
```

本质是从 `test` 目录中删除：

```text
a.txt -> inode 1001
```

然后 `inode 1001` 的硬链接计数减 1。

所以需要：

```text
test 目录的 w + x
```

其中：

```text
w：允许删除目录项
x：允许找到 a.txt 这个目录项
```

你说删除时需要修改 inode 的硬链接数，这个是对的。

但是权限判断上要注意：

> <span style="color:#FF0000; background:#00FF80;">虽然内核内部会修改 inode 的硬链接计数，但用户是否能删除这个文件，主要看的是父目录的 `w + x` 权限，而不是文件本身的 `w` 权限。</span>

例如：

```bash
-r--------  test/a.txt
drwx------  test
```

虽然 `a.txt` 本身没有写权限，但如果你对 `test` 有 `w + x`，仍然可以：

```bash
rm test/a.txt
```

<span style="color:#FF0000; background:#00FF80;">因为删除的是目录项，不是修改 `a.txt` 的内容。</span>

------

## 6. 权限不要理解成“内核每一步都要重新检查”

你现在容易混淆的地方是：

> 既然删除时要修改 inode 的硬链接计数，那是不是也需要某种权限访问 inode？

从实现上，内核当然会访问 inode。

但从权限模型上，不是这么划分的。

你可以这样理解：

```text
权限检查是针对“你要做什么操作”
不是针对“内核内部顺手改了哪些结构”
```

比如：

```bash
rm test/a.txt
```

用户想做的操作是：

```text
删除 test 目录中的一个名字
```

所以权限检查重点是：

```text
test 目录是否允许你删除目录项？
```

也就是：

```text
test 目录的 w + x
```

至于硬链接数减 1，是文件系统内部为了维护一致性自动做的事。

------

## 7. 用表格帮你彻底理清

| 操作                           | 修改了什么              | 需要父目录 `w` 吗 | 需要父目录 `x` 吗 | 需要文件本身权限吗    |
| ------------------------------ | ----------------------- | ----------------- | ----------------- | --------------------- |
| `touch test/c.txt`，文件不存在 | 新增目录项 + 新 inode   | 需要              | 需要              | 不涉及旧文件          |
| `touch test/a.txt`，文件已存在 | 修改 `a.txt` 的时间戳   | 不需要            | 需要              | 需要有对应权限        |
| `rm test/a.txt`                | 删除目录项，硬链接数 -1 | 需要              | 需要              | 通常不需要文件 `w`    |
| `mv test/a.txt test/new.txt`   | 修改目录项名字          | 需要              | 需要              | 通常不需要文件 `w`    |
| `chmod 600 test/a.txt`         | 修改 inode 权限信息     | 不需要            | 需要              | 需要你是所有者或 root |
| `echo hi > test/a.txt`         | 修改文件数据块内容      | 不需要父目录 `w`  | 需要父目录 `x`    | 需要文件 `w`          |
| `cat test/a.txt`               | 读取文件数据块内容      | 不需要父目录 `w`  | 需要父目录 `x`    | 需要文件 `r`          |

------

## 8. 你可以把三类操作分开记

### 第一类：改目录项

包括：

```bash
touch test/c.txt   # c.txt 不存在时
rm test/a.txt
mv test/a.txt test/new.txt
ln test/a.txt test/b.txt
```

本质是改目录里的：

```text
文件名 -> inode
```

所以需要：

```text
父目录 w + x
```

------

### 第二类：改文件 inode 属性

包括：

```bash
chmod 600 test/a.txt
chown user test/a.txt
touch test/a.txt   # 文件已存在时
```

本质是修改 inode 元信息。

所以需要：

```text
路径上目录 x
+ 你对该 inode 有对应管理权限
```

通常不需要：

```text
父目录 w
```

------

### 第三类：改文件内容

包括：

```bash
echo hello > test/a.txt
vim test/a.txt
```

本质是修改文件数据块。

所以需要：

```text
路径上目录 x
+ 文件本身 w
```

也通常不需要：

```text
父目录 w
```

------

## 10. 最终版本

你可以把你的理解整理成下面这个版本：

```text
目录本身有 inode，目录 inode 指向目录的数据块。
目录数据块中保存的是目录项，也就是“文件名 -> inode 编号”的映射。

目录的 r 权限：
允许读取目录项列表，也就是看到有哪些文件名。

目录的 x 权限：
允许在目录中根据已知文件名查找对应 inode，也就是路径解析、进入、搜索目录。

目录的 w 权限：
允许修改目录项，包括新增文件名、删除文件名、重命名文件名。

如果是修改文件自身内容或 inode 属性，一般不需要父目录 w；
但需要路径上目录的 x，才能找到这个文件的 inode。
```

最关键的一句话：

```text
父目录 w 管“能不能改名字表”；
父目录 x 管“能不能在名字表里查找”；
文件自身 r/w/x 管“找到文件之后能不能读、写、执行它”。
```



# 2.目录x权限“进入目录”从底层inode和数据块角度理解

可以从底层这样理解：

> **目录的 `x` 权限不是“执行目录”，而是允许把这个目录当作“路径查找的中转站/起点”。**
> 所谓“进入目录”，底层不是把目录内容全部读出来，而是让进程的“当前工作目录”指向这个目录的 inode。

------

## 1. 目录底层是什么？

假设有目录：

```bash
test/
├── a.txt
└── b.txt
```

从底层看：

```text
test 目录项：
test -> inode 1000

inode 1000：
类型：目录
权限：rwx
数据块地址：block 500

block 500：
.      -> inode 1000
..     -> inode 999
a.txt  -> inode 2001
b.txt  -> inode 2002
```

也就是说：

```text
目录 inode：记录目录属性和目录数据块地址
目录数据块：保存“文件名 -> inode 编号”的映射
```

------

## 2. `cd test` 的底层过程

你执行：

```bash
cd test
```

底层大概发生：

```text
1. shell 调用 chdir("test")
2. 内核在当前目录的数据块中查找 test 这个名字
3. 找到 test -> inode 1000
4. 检查 inode 1000 是不是目录
5. 检查你对 test 目录有没有 x 权限
6. 如果有，就把当前进程的工作目录切换为 inode 1000
```

<span style="color:#FF0000; background:#00FF80;">所以“进入目录”不是说把目录内容显示出来，而是：</span>

```text
当前进程的工作目录 cwd
从原来的目录 inode
切换成 test 目录 inode
```

可以理解成：

```text
cd test 之前：
当前工作目录 -> inode 999

cd test 之后：
当前工作目录 -> inode 1000
```

------

## 3. 目录的 `x` 权限到底管什么？

目录的 `x` 权限管的是：

```text
能不能把这个目录作为路径查找的入口
能不能进入这个目录
能不能在这个目录中根据文件名查找 inode
```

比如你进入 `test` 后执行：

```bash
cat a.txt
```

<span style="color:#FF0000; background:#00FF80;">因为当前工作目录已经是 `test`，所以系统会在 `test` 的数据块中查找：</span>

```text
a.txt -> inode 2001
```

<span style="color:#FF0000; background:#00FF80;">这一步就需要 `test` 目录的 `x` 权限。</span>

所以目录 `x` 可以理解成：

```text
允许使用这个目录的数据块进行“按名字查找 inode”
```

注意<span style="color:#FF0000; background:#00FF80;">，是**按已知名字查找**，不是列出全部名字。</span>

------

## 4. 目录的 `r` 和 `x` 的底层区别

### `r`：读目录数据块中的“名字列表”

如果你执行：

```bash
ls test
```

它要读取 `test` 目录数据块里的目录项列表：

```text
a.txt
b.txt
```

所以目录 `r` 权限控制：

```text
能不能读取目录项列表
能不能看到目录里面有哪些名字
```

------

### `x`：根据已知名字查找 inode

如果你执行：

```bash
cat test/a.txt
```

它不需要列出 `test` 里面所有文件，只需要查找一个确定的名字：

```text
在 test 目录数据块中查找 a.txt
找到 a.txt -> inode 2001
```

这个操作需要 `test` 的 `x` 权限。

所以：

```text
r：看完整名单
x：知道名字后，能不能按名字找到它
```

------

## 5. 一个非常关键的例子

假设目录权限是：

```bash
d--x------ test
```

只有 `x`，没有 `r`。

这时你不能：

```bash
ls test
```

因为没有 `r`，不能读取目录项列表。

但是如果你已经知道里面有 `a.txt`，可以：

```bash
cat test/a.txt
```

只要 `a.txt` 本身有读权限，这个操作可能成功。

底层原因是：

```text
没有 r：不能把 test 数据块里的所有目录项列出来
有 x：可以在 test 数据块里按名字查找 a.txt
```

------

## 6. 为什么没有 `x` 就进不去？

假设：

```bash
drw------- test
```

有 `r` 和 `w`，但是没有 `x`。

这时你可能可以看到名字：

```bash
ls test
```

但是不能：

```bash
cd test
cat test/a.txt
rm test/a.txt
touch test/c.txt
```

因为没有 `x`，内核不允许你把 `test` 当作路径查找的目录。

底层可以理解成：

```text
你可以读取 test 目录数据块里的名字列表，
但是不能使用这些名字继续解析成 inode。
```

也就是：

```text
你能看到名单，但不能按名单去找人。
```

------

## 7. “进入目录”最准确的底层理解

你可以这样理解：

```text
目录 x 权限 = 允许当前进程把这个目录 inode 作为路径解析的起点或中间节点。
```

具体到 `cd test`：

```text
有 x：
进程的当前工作目录可以切换到 test 的 inode。

没有 x：
即使你知道 test 存在，也不能把当前工作目录切换过去。
```

具体到 `cat test/a.txt`：

```text
有 test 的 x：
可以进入 test 这个目录结构，查找 a.txt 对应的 inode。

没有 test 的 x：
不能通过 test 去找到 a.txt。
```

------

## 8. 总结一句话

从 inode 和数据块角度看：

> 目录的 `x` 权限表示：你是否有资格使用这个目录 inode 所指向的目录数据块，按照某个已知文件名去查找对应的 inode，并把这个目录作为路径解析的中转站或当前工作目录。

最简记法：

```text
目录 r：读取目录数据块，列出有哪些名字
目录 x：使用目录数据块，按名字查找 inode
目录 w：修改目录数据块，增删改目录项
```

所以“进入目录”本质上就是：

```text
把进程当前工作目录切换到该目录 inode，
以后相对路径查找就从这个 inode 对应的目录数据块开始。
```





# 3.目录权限关于r和w的一个重要理解

<span style="color:#FF0000; background:#00FF80;">我有一个问题，就是我已经利用了ls命令得到了映射关系，为什么我查找的时候还需要x权限呢？</span>

因为这里要区分两件事：

```text
知道映射关系 ≠ 有权使用这个映射关系
```

你用 `ls` 得到的信息，只是**看到了目录项数据**；但你后面真正访问文件时，内核还要重新做一次**路径解析权限检查**。

------

## 1. `r` 权限：让你“看见名单”

假设目录 `test` 权限是：

```bash
dr-------- test
```

也就是只有 `r`，没有 `x`。

你可能通过：

```bash
ls test
```

看到：

```text
a.txt
b.txt
```

甚至用：

```bash
ls -i test
```

看到类似：

```text
1001 a.txt
1002 b.txt
```

这说明你能读取目录数据块里的目录项。

也就是：

```text
a.txt -> inode 1001
b.txt -> inode 1002
```

但是这只是“看到了名单”。

------

## 2. `x` 权限：让你“使用名单去找文件”

当你执行：

```bash
cat test/a.txt
```

内核会重新解析路径：

```text
1. 找到 test 目录
2. 检查你有没有 test 的 x 权限
3. 在 test 目录中查找 a.txt
4. 找到 a.txt 对应的 inode
5. 检查 a.txt 的 r 权限
6. 读取 a.txt 的内容
```

如果 `test` 没有 `x` 权限，第 2 步就失败。

所以即使你已经知道：

```text
a.txt -> inode 1001
```

也不能绕过 `x` 权限。

------

## 3. 为什么不能直接拿 inode 编号访问？

因为 Linux 普通用户访问文件，一般是通过**路径名**访问的，比如：

```bash
cat test/a.txt
```

而不是这样：

```bash
cat inode 1001
```

<span style="color:#FF0000; background:#00FF80;">inode 编号只是文件系统内部用来定位文件的编号，普通用户不能随便说：</span>

```text
我知道 inode 是 1001，所以我要直接访问它
```

<span style="color:#FF0000; background:#00FF80;">如果允许这样做，目录权限就失去意义了。</span>

------

## 4. 一个比喻

可以这样理解：

```text
目录 r：允许你看门牌列表
目录 x：允许你按照门牌真正走到那扇门前
```

你看到名单：

```text
101号房间：a.txt
102号房间：b.txt
```

不代表你有权走进去。

所以：

```text
r = 看名单
x = 用名单找人 / 进入路径
```

------

## 5. 最核心的一句话

> `ls` 得到的映射关系只是“信息”；
> 但访问文件是一个新的系统调用，内核必须检查你是否有目录的 `x` 权限。
> 没有 `x`，就算你知道文件名和 inode，也不能通过这个目录去访问它。

所以目录权限可以这样最终记：

```text
目录 r：能不能读取目录项列表
目录 x：能不能把目录项用于路径解析
目录 w：能不能修改目录项列表
```
