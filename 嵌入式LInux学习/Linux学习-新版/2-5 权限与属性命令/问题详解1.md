# 1.文件类型

有的。你这里说的应该是 `ls -l` 最前面的**第 1 个字符**，它表示“文件类型”。

常见类型如下：

```bash
-rw-r--r--   普通文件
drwxr-xr-x   目录
lrwxrwxrwx   符号链接/软链接
crw-rw----   字符设备文件
brw-rw----   块设备文件
prw-r--r--   管道文件
srwxr-xr-x   套接字文件
```

整理成表格：

| 第 1 位 | 文件类型         | 含义                                        |
| ------- | ---------------- | ------------------------------------------- |
| `-`     | 普通文件         | 文本文件、程序文件、图片、视频等普通文件    |
| `d`     | directory        | 目录                                        |
| `l`     | link             | 符号链接，也叫软链接，类似 Windows 快捷方式 |
| `c`     | character device | 字符设备文件，比如终端、串口等              |
| `b`     | block device     | 块设备文件，比如硬盘、U盘、磁盘分区         |
| `p`     | pipe             | 管道文件，用于进程间通信                    |
| `s`     | socket           | 套接字文件，也用于进程间通信                |

最常见、最需要先掌握的是这三个：

```bash
-   普通文件
d   目录
l   软链接
```

比如：

```bash
ls -l
```

可能看到：

```bash
-rw-r--r--  1 book book  1234 a.txt
drwxr-xr-x  2 book book  4096 test
lrwxrwxrwx  1 book book     5 link -> a.txt
```

可以这样理解：

```text
a.txt 是普通文件
test 是目录
link 是指向 a.txt 的软链接
```

所以 `ls -l` 输出中，最前面的第一个字符不是权限，而是**文件类型**；后面的 9 个字符才是权限：

```text
- rw- r-- r--
│ │   │   │
│ │   │   └── 其他用户权限
│ │   └────── 同组用户权限
│ └────────── 所有者权限
└──────────── 文件类型
```



# 2.不同的文件的作用

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">上面这些文件的作用都是什么呢，我不是太懂，你能够给我解释下吗，最好能够举些例子来让我彻底弄明白。</span>

可以。你可以先抓住一个核心思想：

> Linux 里很多东西都被抽象成“文件”。
> 但这里的“文件”不一定都是 Word、图片、视频那种普通文件，也可能是目录、快捷方式、设备接口、进程通信接口。

也就是 `ls -l` 最前面的第 1 个字符，是在告诉你：**这个东西到底是哪一类文件对象。**

------

## 1. `-`：普通文件

例如：

```bash
-rw-r--r--  1 book book  1234 a.txt
-rwxr-xr-x  1 book book  8304 hello
```

最前面是 `-`，表示这是**普通文件**。

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">普通文件就是我们最熟悉的文件</span>，比如：

```text
文本文件：a.txt
代码文件：main.c
图片文件：test.png
视频文件：movie.mp4
可执行程序：hello
压缩包：test.zip
```

<span style="background:#00FF80;">它的作用就是**存放真实内容**。</span>

比如：

```bash
cat a.txt
```

可以查看文本内容。

```bash
./hello
```

可以执行程序文件。

所以 `-` 类型最容易理解，就是普通的数据文件。

------

## 2. `d`：目录文件

例如：

```bash
drwxr-xr-x  2 book book 4096 test
```

最前面是 `d`，表示这是一个**目录**。

<span style="background:#00FF80;">目录的作用是：**用来存放文件名和子目录名**。</span>

比如：

```text
test/
├── a.txt
├── b.txt
└── subdir/
```

这里的 `test` 就是目录。

你可以把目录理解成 Windows 里的“文件夹”。

常用操作：

```bash
ls test
```

查看目录里面有什么。

```bash
cd test
```

进入这个目录。

```bash
mkdir newdir
```

创建目录。

注意：<span style="background:#00FF80;">目录本身不是用来存普通文本内容的，它主要用来组织文件。</span>

------

## 3. `l`：符号链接，也叫软链接

例如：

```bash
lrwxrwxrwx  1 book book  5 link -> a.txt
```

最前面是 `l`，表示这是一个**软链接**。

软链接类似 Windows 里的“快捷方式”。

比如你有一个真实文件：

```bash
a.txt
```

然后创建一个软链接：

```bash
ln -s a.txt link
```

此时：

```bash
ls -l
```

可能看到：

```bash
lrwxrwxrwx 1 book book 5 link -> a.txt
-rw-r--r-- 1 book book 100 a.txt
```

意思是：

```text
link 不是一个真正的新文件
link 只是指向 a.txt
```

你执行：

```bash
cat link
```

其实看的还是 `a.txt` 的内容。

软链接的作用：**给某个文件或目录起一个“快捷入口”**。

举个生活例子：

```text
真实文件：/home/book/project/hello
软链接：/usr/bin/hello
```

你以后直接输入：

```bash
hello
```

就可以运行那个真实程序。

所以软链接的作用很重要：**方便访问某个很深路径下的文件。**

------

## 4. `c`：字符设备文件

例如：

```bash
crw-rw-rw- 1 root root 1, 3 /dev/null
crw-rw-rw- 1 root root 5, 0 /dev/tty
```

最前面是 `c`，表示这是**字符设备文件**。

这个就不是普通文件了，它<span style="background:#00FF80; color:#FF0000;">一般出现在 `/dev` 目录下面。</span>

<span style="background:#00FF80;">字符设备的特点是：**数据一个字符、一个字符地传输**。</span>

常见例子：

```bash
/dev/null
/dev/tty
/dev/random
```

### 例子 1：`/dev/null`

`/dev/null` 可以理解成“黑洞文件”。

你写进去的东西都会消失。

比如：

```bash
echo "hello" > /dev/null
```

这句话不会显示任何东西，因为内容被丢进“黑洞”了。

它常用于丢弃不想看的输出：

```bash
command > /dev/null
```

意思是：执行命令，但不要显示普通输出。

------

### 例子 2：`/dev/tty`

`/dev/tty` 通常表示当前终端。

比如：

```bash
echo "hello" > /dev/tty
```

意思<span style="color:#FF0000; background:#00FF80;">是把 `hello` 输出到当前终端屏幕上。</span>

所以<span style="background:#00FF80;">字符设备文件本质上是：**操作系统提供给用户程序访问设备的接口**。</span>

你<span style="color:#FF0000; background:#00FF80;">不是在读写普通文件，而是在和某个设备打交道。</span>

------

## 5. `b`：块设备文件

例如：

```bash
brw-rw---- 1 root disk 8, 0 /dev/sda
brw-rw---- 1 root disk 8, 1 /dev/sda1
```

<span style="background:#00FF80;">最前面是 `b`，表示这是**块设备文件**。</span>

它也常见于 `/dev` 目录下面。

<span style="background:#00FF80;">块设备的特点是：**数据一块一块地读写**。</span>

常见例子：

```bash
/dev/sda
/dev/sda1
/dev/nvme0n1
```

这些一般代表：

```text
硬盘
U盘
磁盘分区
SSD
```

比如：

```text
/dev/sda   表示一整块磁盘
/dev/sda1  表示这块磁盘的第 1 个分区
```

你可以这样理解：

```text
字符设备：像键盘、终端，一个字符一个字符处理
块设备：像硬盘、U盘，一块一块读写数据
```

<span style="color:#FF0000; background:#00FF80;">块设备一般不要随便操作，因为直接写错可能破坏磁盘数据。</span>

------

## 6. `p`：管道文件

例如：

```bash
prw-r--r-- 1 book book 0 mypipe
```

最前面是 `p`，表示这是**管道文件**。

它的<span style="background:#00FF80;">作用是：**让两个进程之间传递数据**。</span>

创建一个管道文件：

```bash
mkfifo mypipe
```

查看：

```bash
ls -l mypipe
```

会看到：

```bash
prw-r--r-- 1 book book 0 mypipe
```

### 举个例子

一个终端输入：

```bash
cat mypipe
```

<span style="background:#00FF80;">它会卡住，等待别人往管道里写东西。</span>

另一个终端输入：

```bash
echo "hello" > mypipe
```

<span style="background:#00FF80;">第一个终端就会显示：</span>

```bash
hello
```

所以管道文件不是用来长期保存数据的，而是用来**临时传递数据**。

你可以把它理解成：

```text
管道文件 = 两个程序之间的一根水管
一个程序往里面倒水
另一个程序从另一端接水
```

------

## 7. `s`：套接字文件

例如：

```bash
srw-rw-rw- 1 root root 0 docker.sock
srwxrwxrwx 1 mysql mysql 0 mysql.sock
```

最前面是 `s`，表示这是**套接字文件**。

它的<span style="background:#00FF80;">作用也是**进程间通信**，但是比管道更强大。</span>

常见例子：

```bash
/var/run/docker.sock
/run/mysqld/mysqld.sock
```

比如 MySQL 服务运行时，可能会生成一个：

```bash
mysql.sock
```

<span style="background:#00FF80;">客户端程序可以通过这个 socket 文件和 MySQL 服务通信。</span>

你可以这样理解：

```text
管道文件 p：比较简单，像一根水管
套接字文件 s：更像一个本地通信接口，可以双向通信
```

例如：

```text
MySQL 客户端  <---->  mysql.sock  <---->  MySQL 服务器
Docker 命令   <---->  docker.sock <---->  Docker 服务
```

所以 socket 文件通常用于**本机上的服务程序通信**。

------

## 8. 总结表

| 类型 | 名称       | 常见位置           | 作用                         | 好理解的比喻         |
| ---- | ---------- | ------------------ | ---------------------------- | -------------------- |
| `-`  | 普通文件   | 任意目录           | 存放普通数据                 | Word、图片、代码文件 |
| `d`  | 目录       | 任意目录           | 存放文件名和子目录           | 文件夹               |
| `l`  | 软链接     | 任意目录           | 指向另一个文件或目录         | 快捷方式             |
| `c`  | 字符设备   | `/dev`             | 一个字符一个字符地和设备通信 | 终端、串口接口       |
| `b`  | 块设备     | `/dev`             | 一块一块地读写磁盘数据       | 硬盘、U盘接口        |
| `p`  | 管道文件   | 任意目录           | 进程之间传递数据             | 一根水管             |
| `s`  | 套接字文件 | `/run`、`/var/run` | 进程之间通信                 | 本地服务接口         |

------

# 3.不同文件类型对应的rwx的操作

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">对于上面不同的文件类型，可读可写可执行分别对应的操作都是什么呢，我不是太懂，你能够给我详细解解释下吗，最好能够举些例子来让我彻底弄明白。</span>

可以。你要先建立一个总框架：

> `rwx` 这三个权限在不同文件类型上，含义不完全一样。
> 对普通文件来说，`rwx` 是“读内容、改内容、运行文件”；
> 对目录来说，`rwx` 是“看目录名、改目录项、进入目录”；
> 对设备、管道、套接字来说，`rwx` 更多是在控制“能不能读写这个接口”。

------

## 一、先记住最核心的区别

### 1. 对普通文件 `-`

```bash
-rwxr-xr--
```

这里的 `rwx` 作用在**文件内容本身**上。

| 权限 | 对普通文件的含义     |
| ---- | -------------------- |
| `r`  | 可以读取文件内容     |
| `w`  | 可以修改文件内容     |
| `x`  | 可以把文件当程序执行 |

例如：

```bash
cat a.txt
```

需要 `a.txt` 有读权限 `r`。

```bash
echo "hello" > a.txt
```

需要 `a.txt` 有写权限 `w`。

```bash
./hello
```

需要 `hello` 有执行权限 `x`。

------

### 2. 对目录 `d`

```bash
drwxr-xr-x
```

这里的 `rwx` 不是作用在“文件内容”上，而是<span style="background:#00FF80;">作用在**目录项**上。</span>

目录本质上可以理解为：

```text
目录 = 文件名列表 + 文件名到文件的映射关系
```

比如目录 `test/` 里面有：

```text
test/
├── a.txt
├── b.txt
└── subdir/
```

那么目录权限的含义是：

| 权限 | 对目录的含义                         |
| ---- | ------------------------------------ |
| `r`  | 可以查看目录里面有哪些文件名         |
| `w`  | 可以在目录里创建、删除、重命名文件   |
| `x`  | 可以进入目录，或者访问目录里面的文件 |

目录的 `x` 非常重要，它不是“执行目录”，而是：

> 可以穿过这个目录、进入这个目录、访问里面的文件。

------

## 二、普通文件 `-` 的 `rwx`

### 1. `r`：读权限

比如有文件：

```bash
-rw-r--r-- 1 book book 100 a.txt
```

你有读权限，就可以：

```bash
cat a.txt
less a.txt
head a.txt
```

也就是可以查看它的内容。

如果没有读权限：

```bash
--w------- 1 book book 100 a.txt
```

执行：

```bash
cat a.txt
```

可能会报错：

```bash
Permission denied
```

------

### 2. `w`：写权限

写权限表示可以修改文件内容。

例如：

```bash
echo "hello" > a.txt
```

或者：

```bash
vim a.txt
```

需要 `a.txt` 有写权限。

注意一个细节：

> 文件的 `w` 权限表示可以修改文件内容，但不代表可以删除这个文件。

删除文件看的是**所在目录的写权限**，不是文件自己的写权限。

比如：

```bash
rm a.txt
```

真正需要的是：你对 `a.txt` 所在目录有 `w` 和 `x` 权限。

这个很容易混淆。

------

### 3. `x`：执行权限

执行权限表示可以把这个文件当作程序运行。

比如：

```bash
-rwxr-xr-x 1 book book 8304 hello
```

你可以执行：

```bash
./hello
```

如果没有执行权限：

```bash
-rw-r--r-- 1 book book 8304 hello
```

执行：

```bash
./hello
```

会报错：

```bash
Permission denied
```

可以加上执行权限：

```bash
chmod +x hello
```

然后再执行：

```bash
./hello
```

------

### 4. 普通文件小总结

| 操作         | 需要什么权限     |
| ------------ | ---------------- |
| 查看文件内容 | 文件有 `r`       |
| 修改文件内容 | 文件有 `w`       |
| 执行文件     | 文件有 `x`       |
| 删除文件     | 父目录有 `w + x` |
| 重命名文件   | 父目录有 `w + x` |

举个例子：

```bash
-rw-r--r-- a.txt
```

表示：

```text
可以读，可以写，但不能执行
```

适合普通文本文件。

```bash
-rwxr-xr-x hello
```

表示：

```text
这是一个可以执行的程序文件
```

适合可执行程序或脚本。

------

## 三、目录 `d` 的 `rwx`

目录权限是最容易困惑的地方。

假设有一个目录：

```bash
drwxr-xr-x 2 book book 4096 test
```

### 1. `r`：可以列出目录内容

目录有 `r` 权限，表示可以查看目录下面有哪些文件名。

例如：

```bash
ls test
```

需要目录 `test` 有读权限 `r`。

但是注意：

> <span style="background:#00FF80;">只有 `r` 没有 `x`，通常也不能正常查看详细信息。</span>

比如目录权限是：

```bash
dr-------- test
```

<span style="background:#00FF80;">你可能能看到部分文件名，但不能进入目录，也不能访问里面的文件详细属性。</span>

------

### 2. `w`：可以修改目录内容

<span style="color:#FF0000;">目录的 `w` 不是修改某个文件内容，而是修改目录里的“文件名列表”。</span>

也就是可以：

```text
创建文件
删除文件
重命名文件
移动文件
```

例如：

```bash
touch test/a.txt
```

需要对目录 `test` 有 `w + x` 权限。

```bash
rm test/a.txt
```

也需要对目录 `test` 有 `w + x` 权限。

```bash
mv test/a.txt test/b.txt
```

也需要对目录 `test` 有 `w + x` 权限。

所以，目录的 `w` 可以理解为：

> 有没有权力改这个目录里面的“名单”。

------

### 3. `x`：可以进入目录 / 穿过目录

<span style="color:#FF0000; background:#00FF80;">目录的 `x` 不是执行目录，而是进入目录、访问目录里面内容的权限。</span>

例如：

```bash
cd test
```

需要目录 `test` 有执行权限 `x`。

访问目录中的文件：

```bash
cat test/a.txt
```

也需要目录 `test` 有 `x` 权限。

<span style="background:#00FF80; color:#FF0000;">即使 `a.txt` 本身有读权限，如果你对 `test` 没有 `x`，也不能访问：</span>

```text
test 目录都进不去，自然碰不到里面的 a.txt
```

------

### 4. 目录权限组合举例

#### 情况 1：`r-x`

```bash
dr-xr-xr-x test
```

表示：

```text
可以进入目录
可以查看目录里面有什么
不能创建、删除、重命名文件
```

可以：

```bash
ls test
cd test
cat test/a.txt
```

不可以：

```bash
touch test/new.txt
rm test/a.txt
```

------

#### 情况 2：`--x`

```bash
d--x--x--x test
```

表示：

```text
不能列出目录内容
但是如果你知道文件名，可以访问里面的文件
```

例如你不能：

```bash
ls test
```

但是如果你知道里面有 `a.txt`，并且 `a.txt` 本身可读，你可能可以：

```bash
cat test/a.txt
```

这个可以理解为：

```text
目录不让你看名单
但你知道准确名字的话，可以直接访问
```

------

#### 情况 3：`rw-`

```bash
drw------- test
```

这种权限很尴尬。

有 `r` 和 `w`，但没有 `x`。

理论上：

```text
可以读目录名列表
可以修改目录项
```

但是因为没有 `x`，很多操作都无法真正完成。

比如：

```bash
cd test
```

不行。

```bash
touch test/a.txt
```

通常也不行。

所以目录一般很少设置成没有 `x`。

------

#### 情况 4：`rwx`

```bash
drwx------ test
```

表示目录所有者可以：

```text
进入目录
查看目录内容
创建文件
删除文件
重命名文件
访问里面的文件
```

这是目录最完整的权限。

------

## 四、软链接 `l` 的 `rwx`

软链接例子：

```bash
lrwxrwxrwx 1 book book 5 link -> a.txt
```

你会发现软链接通常显示：

```bash
lrwxrwxrwx
```

看起来所有人都有 `rwx`，但这里要注意：

> <span style="background:#00FF80;">软链接自己的权限通常不重要，真正起作用的是它指向的目标文件权限。</span>

例如：

```bash
link -> a.txt
```

当你执行：

```bash
cat link
```

本质上是在访问：

```bash
cat a.txt
```

所以<span style="color:#FF0000; background:#00FF80;">最终看的是 `a.txt` 的权限。</span>

------

### 例子

```bash
-rw------- 1 book book 100 a.txt
lrwxrwxrwx 1 book book   5 link -> a.txt
```

虽然 `link` 显示：

```bash
lrwxrwxrwx
```

但是其他用户访问：

```bash
cat link
```

仍然可能失败。

因为真正的目标 `a.txt` 是：

```bash
-rw-------
```

只有所有者能读。

所以软链接可以这样记：

```text
软链接像快捷方式
快捷方式本身权限不关键
真正看目标文件权限
```

------

## 五、字符设备文件 `c` 的 `rwx`

字符设备例子：

```bash
crw-rw-rw- 1 root root 1, 3 /dev/null
crw-rw-rw- 1 root root 5, 0 /dev/tty
```

<span style="background:#00FF80; color:#FF0000;">字符设备不是普通文件，它是设备接口。</span>

### 1. `r`：可以从设备读数据

例如：

```bash
cat /dev/random
```

表示从随机数设备读取数据。

这里需要读权限 `r`。

又比如：

```bash
cat /dev/tty
```

可以从当前终端读取输入。

------

### 2. `w`：可以向设备写数据

例如：

```bash
echo "hello" > /dev/tty
```

<span style="color:#FF0000; background:#00FF80;">表示把 `hello` 输出到当前终端。</span>

再比如：

```bash
echo "hello" > /dev/null
```

表示把内容写入 `/dev/null`，但是它会被直接丢弃。

`/dev/null` 可以理解成：

```text
系统黑洞
写进去的东西全部消失
```

------

### 3. `x`：通常没有实际意义

字符设备文件一般不需要执行权限。

你不会这样执行：

```bash
./dev/null
```

这没有意义。

所以对字符设备来说：

```text
r = 能不能从设备读
w = 能不能往设备写
x = 通常没什么实际用途
```

------

## 六、块设备文件 `b` 的 `rwx`

块设备例子：

```bash
brw-rw---- 1 root disk 8, 0 /dev/sda
brw-rw---- 1 root disk 8, 1 /dev/sda1
```

块设备通常表示硬盘、U盘、磁盘分区。

### 1. `r`：可以读取磁盘数据

如果对块设备有读权限，理论上可以读取磁盘原始数据。

比如：

```bash
sudo dd if=/dev/sda of=disk.img
```

这表示从 `/dev/sda` 读取数据，复制到 `disk.img`。

这个操作需要读权限。

------

### 2. `w`：可以写入磁盘数据

如果对块设备有写权限，理论上可以直接写磁盘。

比如：

```bash
sudo dd if=image.img of=/dev/sda
```

这表示把镜像写入磁盘。

这个很危险，因为可能覆盖整个磁盘。

你现在只需要理解：

```text
块设备的写权限非常危险
因为它可能直接修改磁盘底层数据
```

------

### 3. `x`：通常没有实际意义

块设备也不是拿来执行的。

你不会这样：

```bash
./dev/sda
```

所以对块设备来说：

```text
r = 能读磁盘原始数据
w = 能写磁盘原始数据
x = 通常没什么实际用途
```

------

## 七、管道文件 `p` 的 `rwx`

管道文件例子：

```bash
prw-r--r-- 1 book book 0 mypipe
```

管道文件用来让两个进程传数据。

创建管道：

```bash
mkfifo mypipe
```

### 1. `r`：可以从管道读取数据

一个终端执行：

```bash
cat mypipe
```

这表示等待从管道读取数据。

需要 `mypipe` 有读权限。

------

### 2. `w`：可以向管道写入数据

另一个终端执行：

```bash
echo "hello" > mypipe
```

这表示往管道里写数据。

需要 `mypipe` 有写权限。

然后第一个终端就能看到：

```text
hello
```

------

### 3. `x`：通常没有实际意义

管道文件不是程序，不能执行。

所以：

```bash
./mypipe
```

没有意义。

管道文件可以这样理解：

```text
r = 可以从管道收消息
w = 可以往管道发消息
x = 基本不用
```

------

## 八、套接字文件 `s` 的 `rwx`

套接字文件例子：

```bash
srwxrwxrwx 1 mysql mysql 0 mysql.sock
srw-rw---- 1 root docker 0 docker.sock
```

套接字文件也是进程间通信的接口。

比如：

```text
MySQL 客户端  <---->  mysql.sock  <---->  MySQL 服务端
Docker 命令   <---->  docker.sock <---->  Docker 服务
```

### 1. `r` 和 `w`：控制能不能访问这个通信接口

对 socket 文件来说，`r` 和 `w` 不是读写普通内容，而是控制进程能不能通过这个 socket 与服务通信。

比如：

```bash
srw-rw---- 1 root docker docker.sock
```

表示：

```text
root 用户可以访问
docker 组的用户可以访问
其他用户不能访问
```

如果你不是 `root`，也不在 `docker` 用户组，执行 Docker 命令可能会失败：

```bash
docker ps
```

可能报类似：

```text
Permission denied
```

原因就是你没有权限访问：

```bash
/var/run/docker.sock
```

------

### 2. `x`：通常也不是重点

socket 文件不是用来执行的。

所以：

```bash
./mysql.sock
```

没有意义。

你可以这样记：

```text
socket 的权限主要控制谁能连接这个本地通信接口
```

------

## 九、总表总结

| 文件类型       | `r` 读权限         | `w` 写权限                     | `x` 执行权限             |
| -------------- | ------------------ | ------------------------------ | ------------------------ |
| `-` 普通文件   | 读取文件内容       | 修改文件内容                   | 作为程序运行             |
| `d` 目录       | 查看目录里的文件名 | 创建、删除、重命名目录里的文件 | 进入目录、访问目录内文件 |
| `l` 软链接     | 一般看目标文件权限 | 一般看目标文件权限             | 一般看目标文件权限       |
| `c` 字符设备   | 从设备读数据       | 向设备写数据                   | 通常无实际意义           |
| `b` 块设备     | 读磁盘原始数据     | 写磁盘原始数据                 | 通常无实际意义           |
| `p` 管道文件   | 从管道读数据       | 向管道写数据                   | 通常无实际意义           |
| `s` 套接字文件 | 访问通信接口       | 访问通信接口                   | 通常无实际意义           |

------

## 十、最重要的两个特殊点

### 特殊点 1：删除文件看的是目录权限，不是文件权限

比如：

```bash
-r-------- 1 book book 100 a.txt
drwx------ 2 book book 4096 test
```

虽然 `a.txt` 没有写权限，但是如果你对它所在的目录 `test` 有 `w + x`，你仍然可以删除它：

```bash
rm test/a.txt
```

因为删除文件本质上是：

```text
从目录的文件名列表中删除 a.txt 这个名字
```

所以看的是目录权限。

------

### 特殊点 2：访问文件还要看父目录的 `x` 权限

比如：

```bash
drw------- test
-rw-r--r-- test/a.txt
```

虽然 `a.txt` 有读权限，但 `test` 目录没有 `x` 权限。

此时你执行：

```bash
cat test/a.txt
```

可能失败。

因为你连 `test` 目录都“穿不过去”。

所以访问一个文件，其实要满足：

```text
父目录有 x 权限
文件本身有对应权限
```

如果路径是：

```bash
/home/book/test/a.txt
```

那么需要：

```text
/home 有 x
/home/book 有 x
/home/book/test 有 x
a.txt 有 r
```

才能读取 `a.txt`。

------

## 十一、用生活例子理解

可以把目录和文件想成一个房间系统：

```text
目录 = 房间
普通文件 = 房间里的文件
```

那么：

## 对普通文件

```text
r = 可以看文件内容
w = 可以改文件内容
x = 可以让这个文件运行起来
```

## 对目录

```text
r = 可以看房间里有哪些东西
w = 可以往房间里放东西、拿走东西、改名字
x = 可以进入这个房间
```

所以目录的 `x` 很像：

```text
进入房间的钥匙
```

目录的 `r` 很像：

```text
查看房间清单的权利
```

目录的 `w` 很像：

```text
整理房间物品的权利
```

------

## 十二、你现在最应该掌握的版本

目前你主要记这两个就够了：

### 普通文件

```text
r：读内容
w：改内容
x：执行它
```

### 目录

```text
r：看目录里有什么
w：在目录里创建、删除、重命名
x：进入目录、访问里面的文件
```

其他特殊文件先记成：

```text
设备文件：r/w 控制能不能读写设备
管道文件：r/w 控制能不能收发数据
套接字文件：r/w 控制能不能连接通信接口
软链接：主要看目标文件权限
```

最核心一句话：

> `rwx` 不是死板地等于“读写执行”三个字，而是要看它作用在哪种文件类型上。
> 对普通文件，控制文件内容；对目录，控制目录项和访问路径；对设备、管道、套接字，控制接口读写和通信。





# 4.对目录文件从操作系统的角度理解

从操作系统角度看，**目录不是普通“文件夹图标”**，而是一种特殊文件：

> **目录文件 =<span style="background:#00FF80;"> 存放“文件名 → inode 编号”映射关系的特殊文件。</span>**

也就是说，目录本身不直接保存 `a.txt` 的文本内容，它保存的是：

```text
文件名        对应的 inode 编号
a.txt        1001
b.txt        1002
subdir       1003
```

------

## 1. 普通文件和目录文件的根本区别

### 普通文件

普通文件保存的是**真实数据内容**。

比如：

```bash
cat a.txt
```

看到：

```text
hello world
```

那么 `a.txt` 的数据块里面存的就是：

```text
hello world
```

------

### 目录文件

目录文件保存的不是文章内容，而是**目录项列表**。

比如有目录：

```text
test/
├── a.txt
├── b.txt
└── subdir/
```

从操作系统角度看，`test` 目录里面大概保存的是：

```text
a.txt   -> inode 1001
b.txt   -> inode 1002
subdir  -> inode 1003
```

所以目录的作用是：

> <span style="background:#00FF80;">帮操作系统根据“文件名”找到真正的文件对象。</span>

------

## 2. 什么是 inode？

在 Linux 文件系统里，文件真正的核心不是文件名，而是 **inode**。

<span style="background:#00FF80;">inode 里面保存文件的属性信息，比如：</span>

```text
文件类型：普通文件 / 目录 / 链接 / 设备文件
权限：rwxr-xr-x
所有者：book
所属组：book
文件大小
时间信息
数据块位置
```

可以这样理解：

```text
文件名：给人看的名字
inode：操作系统识别文件的编号和属性信息
数据块：真正存放内容的地方
```

例如：

```text
a.txt 这个名字  ->  inode 1001  ->  数据块  ->  hello world
```

------

## 3. 目录文件在系统中的作用

假设你执行：

```bash
cat /home/book/test/a.txt
```

<span style="color:#FF0000; background:#00FF80;">操作系统不会一开始就知道 `a.txt` 在哪里，它会一层一层查目录。</span>

路径解析过程大概是：

```text
/              根目录
↓ 查找 home
/home          home 目录
↓ 查找 book
/home/book     book 目录
↓ 查找 test
/home/book/test  test 目录
↓ 查找 a.txt
/home/book/test/a.txt  普通文件
```

也就是：

```text
根目录中找 home
home 目录中找 book
book 目录中找 test
test 目录中找 a.txt
```

所以目录文件的核心作用是：

> 支撑路径查找，让操作系统能通过 `/home/book/test/a.txt` 找到具体文件。

------

## 4. 用一个具体例子理解

比如你有：

```bash
mkdir test
touch test/a.txt
touch test/b.txt
```

你看到的是：

```text
test/
├── a.txt
└── b.txt
```

但操作系统眼里更像是：

```text
目录 test 的内容：

.       -> test 自己的 inode
..      -> 上一级目录的 inode
a.txt   -> a.txt 的 inode
b.txt   -> b.txt 的 inode
```

其中：

```text
.   表示当前目录
..  表示上一级目录
```

所以你执行：

```bash
cd .
```

表示留在当前目录。

执行：

```bash
cd ..
```

表示进入上一级目录。

这两个其实也是目录文件中的特殊目录项。

------

## 5. 为什么目录也是“文件”？

因为在 Linux 中，文件系统把很多对象都统一抽象成文件。

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">目录也有：</span>

```text
文件类型
权限
所有者
所属组
大小
时间戳
inode 编号
数据块
```

你可以用：

```bash
ls -ld test
```

看到目录本身的信息：

```bash
drwxr-xr-x 2 book book 4096 May 29  test
```

这里第一个字符是：

```text
d
```

表示它是目录文件。

注意：

```bash
ls -l test
```

是查看 `test` 里面的内容。

```bash
ls -ld test
```

是查看 `test` 这个目录文件本身。

这两个很容易混淆。

------

## 6. 为什么目录的大小经常是 4096？

你可能看到：

```bash
drwxr-xr-x 2 book book 4096 test
```

这里的 `4096` 不是说目录里所有文件加起来 4096 字节。

它表示：

> <span style="background:#00FF80;">这个目录文件本身占用的空间大小。</span>

因为目录里面要保存：

```text
文件名 -> inode
文件名 -> inode
文件名 -> inode
```

这些映射关系也需要占磁盘空间。

所以目录也是有大小的。

------

## 7. 为什么目录不能像普通文件一样随便 cat？

你可能会想，既然目录也是文件，那能不能：

```bash
cat test
```

通常会报错：

```text
cat: test: Is a directory
```

原因是：

> <span style="background:#00FF80;">目录文件的内容不是给普通用户直接按文本读取的，而是由文件系统按照特定格式管理的。</span>

你不能像读 `a.txt` 那样读目录内容，而应该通过专门的系统调用或命令来读取，比如：

```bash
ls test
```

`ls` 背后会调用类似 `readdir` 的机制，专门读取目录项。

所以：

```text
cat a.txt
```

是读取普通文件内容。

```text
ls test
```

是<span style="color:#FF0000; background:#00FF80;">读取目录文件中的目录项。</span>

------

## 8. 目录权限从操作系统角度怎么理解？

目录权限其实控制的是“目录项”的操作。

假设：

```text
test/
├── a.txt
└── b.txt
```

### `r`：读目录项

目录有 `r` 权限，表示可以读取目录中有哪些名字。

对应命令：

```bash
ls test
```

也就是能看到：

```text
a.txt
b.txt
```

所以目录的 `r` 是：

```text
能不能查看目录里的文件名列表
```

------

### `w`：修改目录项

目录有 `w` 权限，表示可以修改目录项。

也就是可以：

```bash
touch test/c.txt
rm test/a.txt
mv test/a.txt test/new.txt
```

<span style="color:#FF0000; background:#00FF80;">这些操作本质上是在修改目录中的映射关系。</span>

比如创建文件：

```text
新增目录项：
c.txt -> inode 1004
```

删除文件：

```text
删除目录项：
a.txt -> inode 1001
```

重命名文件：

```text
把目录项 a.txt 改成 new.txt
```

所以目录的 `w` 是：

```text
能不能修改这个目录里的“名字表”
```

------

### `x`：搜索/进入目录

目录的 `x` 权限不是执行目录，而是：

> <span style="background:#00FF80;">能不能通过这个目录继续往下查找文件。</span>

比如：

```bash
cat test/a.txt
```

操作系统需要先进入 `test` 目录，找到 `a.txt` 这个目录项。

如果 `test` 没有 `x` 权限，即使 `a.txt` 本身有读权限，也可能访问不了。

所以目录的 `x` 可以理解成：

```text
能不能穿过这个目录
能不能进入这个目录
能不能根据文件名找到里面的文件
```

------

## 9. 一个非常重要的例子：删除文件为什么看目录权限？

假设：

```bash
-r-------- 1 book book 100 a.txt
drwx------ 2 book book 4096 test
```

你可能觉得：

```text
a.txt 没有写权限，所以不能删除吧？
```

但实际上，如果你对 `test` 目录有 `w + x` 权限，你就可以删除：

```bash
rm test/a.txt
```

原因是：

> 删除文件，本质上不是修改 `a.txt` 的内容，而是从 `test` 目录中删除 `a.txt -> inode` 这一条目录项。

也就是从：

```text
test 目录：
a.txt -> inode 1001
b.txt -> inode 1002
```

变成：

```text
test 目录：
b.txt -> inode 1002
```

所以删除文件看的是：

```text
父目录的 w + x 权限
```

而不是文件自己的 `w` 权限。

------

## 10. 从操作系统角度完整看一个目录

比如：

```text
/home/book/test/a.txt
```

操作系统眼里的结构可以理解成：

```text
根目录 /
  |
  |-- home -> inode 2
          |
          |-- book -> inode 10
                   |
                   |-- test -> inode 20
                            |
                            |-- a.txt -> inode 30
```

其中：

```text
/home/book/test
```

这个目录文件保存的是：

```text
.       -> inode 20
..      -> inode 10
a.txt   -> inode 30
```

而 `inode 30` 才记录 `a.txt` 的文件属性和数据块位置。

------

## 11. 用生活例子理解

你可以把文件系统想成一栋大楼。

```text
目录 = 房间门口的名单
普通文件 = 房间里真正的资料
inode = 每份资料的编号和档案
数据块 = 资料正文内容
```

目录不是资料正文，而是索引表。

比如：

```text
test 目录：
a.txt 在 1001 号柜子
b.txt 在 1002 号柜子
subdir 在 1003 号柜子
```

当你输入：

```bash
cat test/a.txt
```

系统做的是：

```text
先查 test 目录
找到 a.txt 对应 inode 1001
再根据 inode 1001 找到真正的数据内容
最后把内容读出来
```

------

## 12. 最后总结一句话

从操作系统角度看：

> **目录文件是一种特殊文件，它的内容不是普通文本，而是一张“文件名到 inode 的映射表”。操作系统通过目录文件完成路径查找、文件定位、创建文件、删除文件、重命名文件等操作。**

你可以重点记住这个模型：

```text
路径名  ->  目录逐层查找  ->  文件名映射到 inode  ->  inode 找到数据块
```

比如：

```text
/home/book/test/a.txt
```

实际上是：

```text
/ 找 home
home 找 book
book 找 test
test 找 a.txt
a.txt 对应 inode
inode 找到真正内容
```







# 5. 对普通文件从操作系统的角度理解

从操作系统角度看，**普通文件不是“文件名本身”**，而是由三部分共同组成的：

```text
文件名  ->  inode  ->  数据块
```

更准确地说：

> **普通文件 = inode 中记录的属性信息 + 磁盘数据块中保存的真实内容。**
> 文件名只是目录里指向这个 inode 的一个名字。

------

## 1. 普通文件在 `ls -l` 中长什么样？

比如：

```bash
ls -l a.txt
```

看到：

```bash
-rw-r--r-- 1 book book 12 May 29  a.txt
```

最前面的 `-` 表示：

```text
这是一个普通文件
```

后面的：

```text
rw-r--r--
```

表示权限。

从操作系统角度看，`a.txt` 不是一个简单的“名字”，而是一个文件对象。

------

## 2. 普通文件的三层结构

假设你有一个文件：

```bash
a.txt
```

内容是：

```text
hello world
```

从用户角度看：

```text
a.txt 里面有 hello world
```

但从操作系统角度看，更像这样：

```text
目录文件
└── a.txt  ->  inode 1001

inode 1001
├── 文件类型：普通文件
├── 权限：rw-r--r--
├── 所有者：book
├── 所属组：book
├── 文件大小：12 字节
├── 时间信息
└── 数据块位置：block 500、block 501...

数据块
└── hello world
```

所以<span style="color:#FF0000; background:#00FF80;">普通文件真正由两部分组成：</span>

```text
inode：记录文件属性和数据块位置
数据块：保存文件真实内容
```

<span style="color:#FF0000; background:#00FF80;">文件名 `a.txt` 只是目录中的一个入口。</span>

------

## 3. 文件名不是文件本体

这个非常重要。

你看到的：

```text
a.txt
```

<span style="color:#FF0000; background:#00FF80;">其实只是目录文件中的一条记录：</span>

```text
a.txt -> inode 1001
```

<span style="color:#FF0000; background:#00FF80;">真正的文件信息在 inode 里，真正的文件内容在数据块里。</span>

可以这样理解：

```text
文件名：人的名字
inode：身份证号 + 档案信息
数据块：真正的身体/内容
```

所以：

```text
a.txt 只是名字
inode 才是操作系统识别文件的核心
数据块才是真正保存内容的地方
```

------

## 4. 普通文件的 inode 里保存什么？

inode 可以理解为文件的“元信息表”。

它通常保存：

```text
文件类型：普通文件、目录、链接等
权限：rwx
所有者：属于哪个用户
所属组：属于哪个用户组
文件大小
创建/修改/访问时间
数据块位置
链接计数
```

例如：

```bash
ls -li a.txt
```

可能看到：

```bash
1001 -rw-r--r-- 1 book book 12 May 29 a.txt
```

最前面的 `1001` 就是 inode 编号。

可以理解为：

```text
a.txt 这个名字指向 inode 1001
```

------

## 5. 数据块保存什么？

数据块保存文件的真实内容。

比如：

```bash
echo "hello world" > a.txt
```

此时：

```text
a.txt -> inode 1001 -> 数据块
```

数据块里面保存：

```text
hello world
```

当你执行：

```bash
cat a.txt
```

操作系统大概会做这些事：

```text
1. 在当前目录里查找 a.txt
2. 找到 a.txt 对应的 inode 编号
3. 读取 inode，检查权限
4. 根据 inode 找到数据块
5. 把数据块中的内容读出来
6. 显示到终端
```

------

## 6. 普通文件的读、写、执行，从 OS 角度看

### 1）读文件：`cat a.txt`

命令：

```bash
cat a.txt
```

操作系统做的事情：

```text
1. 根据文件名 a.txt 找到 inode
2. 检查当前用户是否有 r 权限
3. 如果有权限，根据 inode 找到数据块
4. 读取数据块内容
5. 输出到屏幕
```

所以普通文件的 `r` 权限表示：

```text
允许读取这个文件的数据块内容
```

------

### 2）写文件：`echo "hi" > a.txt`

命令：

```bash
echo "hi" > a.txt
```

操作系统做的事情：

```text
1. 根据 a.txt 找到 inode
2. 检查当前用户是否有 w 权限
3. 如果有权限，就修改文件对应的数据块内容
4. 更新 inode 中的文件大小、修改时间等信息
```

所以普通文件的 `w` 权限表示：

```text
允许修改这个文件的数据块内容
```

注意：`w` 权限是修改文件内容，不是删除文件。

删除文件主要看父目录的 `w + x` 权限。

------

### 3）执行文件：`./hello`

命令：

```bash
./hello
```

操作系统做的事情：

```text
1. 根据 hello 找到 inode
2. 检查文件是否有 x 执行权限
3. 检查它是不是可执行文件或脚本
4. 如果可以执行，就把程序加载到内存
5. 创建进程运行它
```

所以普通文件的 `x` 权限表示：

```text
允许把这个文件当作程序运行
```

例如：

```bash
-rwxr-xr-x hello
```

表示 `hello` 可以执行。

如果是：

```bash
-rw-r--r-- hello
```

执行：

```bash
./hello
```

就可能报错：

```bash
Permission denied
```

因为没有执行权限。

------

## 7. 普通文件和进程的关系：<span style="background:#00FF80;">文件描述符</span>

当程序打开文件时，操作系统不会让程序直接操作磁盘。

比如 C 语言里：

```c
open("a.txt", O_RDONLY);
```

或者命令：

```bash
cat a.txt
```

操作系统会给这个进程分配一个**文件描述符**。

可以简单理解为：

```text
文件描述符 = 进程访问某个文件的编号
```

例如：

```text
0  标准输入
1  标准输出
2  标准错误
3  可能是打开的 a.txt
```

大致过程是：

```text
进程想读 a.txt
        ↓
操作系统打开 a.txt
        ↓
返回一个文件描述符 fd
        ↓
进程通过 fd 读文件
        ↓
操作系统帮它从磁盘读取数据
```

所以从操作系统角度看：

> 普通程序并不是直接碰磁盘，而是通过系统调用和文件描述符让操作系统帮它读写文件。

------

## 8. 普通文件的创建过程

比如执行：

```bash
touch a.txt
```

从操作系统角度看，发生了什么？

```text
1. 在当前目录中创建一条目录项：a.txt
2. 为 a.txt 分配一个新的 inode
3. 初始化 inode 信息：
   - 类型：普通文件
   - 权限
   - 所有者
   - 所属组
   - 文件大小：0
   - 时间信息
4. 此时文件内容为空，还没有多少数据块
```

也就是说：

```bash
touch a.txt
```

不是简单地“凭空出现一个名字”，而是：

```text
目录中新增：a.txt -> inode
inode 中记录：这是一个普通文件
```

------

## 9. 普通文件的写入过程

执行：

```bash
echo "hello" > a.txt
```

系统大概做：

```text
1. 找到 a.txt 对应的 inode
2. 检查写权限
3. 为文件分配或修改数据块
4. 把 hello 写入数据块
5. 更新 inode 中的文件大小和修改时间
```

如果原来文件中有内容，`>` 会覆盖。

例如原来：

```text
old content
```

执行：

```bash
echo "hello" > a.txt
```

之后变成：

```text
hello
```

如果用追加：

```bash
echo "hello" >> a.txt
```

则是在原内容后面追加。

------

## 10. 普通文件的删除过程

执行：

```bash
rm a.txt
```

很多人以为这是“删除文件内容”，但从操作系统角度看，更准确地说是：

```text
删除目录中 a.txt -> inode 这条映射关系
```

比如原来目录中有：

```text
a.txt -> inode 1001
```

执行：

```bash
rm a.txt
```

之后目录项被删除：

```text
a.txt 这个名字消失
```

如果没有其他文件名指向这个 inode，并且没有进程正在使用它，系统才会回收 inode 和数据块。

所以删除文件的本质是：

```text
先删除名字和 inode 的映射
再在合适时候回收 inode 和数据块
```

------

## 11. 为什么删除文件看父目录权限？

假设：

```bash
-r-------- 1 book book 100 a.txt
```

这个文件本身没有写权限。

但是如果你对它所在目录有 `w + x` 权限，你仍然可以：

```bash
rm a.txt
```

因为删除文件不是修改 `a.txt` 的内容，而是修改它所在目录的目录项：

```text
删除前：
a.txt -> inode 1001

删除后：
这条记录没了
```

所以删除文件看的是：

```text
父目录有没有 w + x 权限
```

不是看普通文件自己有没有 `w` 权限。

------

## 12. 硬链接可以帮助理解“文件名不是文件本体”

假设执行：

```bash
echo "hello" > a.txt
ln a.txt b.txt
```

然后查看 inode：

```bash
ls -li a.txt b.txt
```

可能看到：

```bash
1001 -rw-r--r-- 2 book book 6 a.txt
1001 -rw-r--r-- 2 book book 6 b.txt
```

你会发现：

```text
a.txt 和 b.txt 的 inode 编号一样
```

这说明：

```text
a.txt 和 b.txt 是两个名字
但它们指向同一个普通文件对象
```

结构是：

```text
当前目录
├── a.txt -> inode 1001
└── b.txt -> inode 1001

inode 1001 -> 数据块 -> hello
```

这时候执行：

```bash
rm a.txt
```

并不会真正删除内容，因为还有：

```text
b.txt -> inode 1001
```

只有当所有名字都删掉，并且没有进程使用它，数据块才会被回收。

------

## 13. 普通文件和目录文件的对比

| 对比项     | 普通文件 `-`             | 目录文件 `d`              |
| ---------- | ------------------------ | ------------------------- |
| 主要作用   | 保存真实数据内容         | 保存文件名到 inode 的映射 |
| 数据块内容 | 文本、图片、程序、视频等 | 目录项列表                |
| `r` 权限   | 读取文件内容             | 查看目录下有哪些文件名    |
| `w` 权限   | 修改文件内容             | 创建、删除、重命名目录项  |
| `x` 权限   | 执行文件                 | 进入/穿过目录             |
| 常见命令   | `cat`、`vim`、`./hello`  | `ls`、`cd`、`mkdir`、`rm` |

------

## 14. 用一张图总结普通文件

假设：

```bash
/home/book/a.txt
```

内容：

```text
hello
```

操作系统眼里大概是：

```text
/home/book 目录文件
└── a.txt  -> inode 1001

inode 1001
├── 类型：普通文件
├── 权限：rw-r--r--
├── 所有者：book
├── 大小：6 字节
├── 数据块地址：block 888
└── 链接计数：1

block 888
└── hello
```

所以你输入：

```bash
cat /home/book/a.txt
```

系统的路径解析过程是：

```text
/ 目录中找 home
home 目录中找 book
book 目录中找 a.txt
找到 inode 1001
检查权限
读取 block 888
显示 hello
```

------

## 15. 最核心的一句话

从操作系统角度看：

> **普通文件是由 inode 描述、由数据块保存内容的文件对象；文件名只是目录中指向 inode 的一个名字。**

你可以记成：

```text
文件名：给人看的入口
inode：操作系统管理文件的档案
数据块：文件真正的内容
```

完整流程：

```text
文件路径
  ↓
目录逐层查找文件名
  ↓
找到 inode
  ↓
检查权限和属性
  ↓
找到数据块
  ↓
读写或执行文件内容
```
