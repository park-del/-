# 1.区分权限中的用户、用户组、其他用户

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">对于某个文件的权限，有用户，用户组，其他用户都，这3个都是个什么东西呢，我不是太懂，你能够给我详细解释下吗，最好能够举些例子来让我彻底弄明白。</span>

可以。Linux 文件权限里的这三类：

```text
用户 / 用户组 / 其他用户
user / group / others
u / g / o
```

本质上是在回答一个问题：

> **当前这个人访问这个文件时，应该按哪一组权限来判断？**

------

## 1. 先看一个例子

比如：

```bash
ls -l a.txt
```

看到：

```bash
-rw-r----- 1 book student 100 May 29 a.txt
```

可以拆成：

```text
-rw-r-----  book  student  a.txt
 │ │  │      │      │
 │ │  │      │      └── 文件名
 │ │  │      └───────── 所属用户组 group
 │ │  └──────────────── 所有者 user
 │ └─────────────────── 权限部分
 └───────────────────── 文件类型，- 表示普通文件
```

权限部分：

```text
rw- r-- ---
│   │   │
│   │   └── 其他用户权限 others
│   └────── 用户组权限 group
└────────── 所有者权限 user
```

所以：

```text
-rw-r-----
```

表示：

```text
文件所有者 book：可以读、写，不能执行
同组用户 student：可以读，不能写，不能执行
其他用户：什么权限都没有
```

------

## 2. 第一类：用户 / 所有者 user

也叫：

```text
所有者
属主
user
u
```

它表示：**这个文件属于哪个用户。**

比如：

```bash
-rw-r----- 1 book student 100 a.txt
```

这里的 `book` 就是文件所有者。

也就是说：

```text
a.txt 这个文件属于 book 这个用户
```

<span style="color:#FF0000; background:#00FF80;">如果当前登录用户就是 `book`，那么访问 `a.txt` 时，就看第一组权限：</span>

```text
rw-
```

也就是：

```text
book 可以读取 a.txt
book 可以修改 a.txt
book 不能执行 a.txt
```

------

## 3. 第二类：用户组 group

也叫：

```text
所属组
用户组
group
g
```

它表示：**这个文件属于哪个用户组。**

比如：

```bash
-rw-r----- 1 book student 100 a.txt
```

这里的 `student` 就是文件所属组。

<span style="color:#FF0000; background:#00FF80;">一个用户可以属于某些用户组。</span>

比如：

```text
book 用户属于 student 组
tom 用户也属于 student 组
jack 用户不属于 student 组
```

那么<span style="color:#FF0000; background:#00FF80;">如果 `tom` 不是文件所有者，但他属于 `student` 组，访问 `a.txt` 时就看第二组权限：</span>

```text
r--
```

也就是：

```text
tom 可以读 a.txt
tom 不能写 a.txt
tom 不能执行 a.txt
```

用户组的作用就是：

> **方便给一批用户设置同样的权限。**

<span style="color:#FF0000; background:#00FF80;">比如一个项目组有 5 个人，你不想一个一个设置权限，就可以把他们放进同一个组。</span>

------

## 4. 第三类：其他用户 others

也叫：

```text
其他用户
others
other
o
```

它表示：

> 既不是文件所有者，也不属于文件所属组的人。

比如：

```bash
-rw-r----- 1 book student 100 a.txt
```

如果 `jack` 不是 `book`，也不属于 `student` 组，那么 `jack` 就属于“其他用户”。

他访问 `a.txt` 时看第三组权限：

```text
---
```

所以：

```text
jack 不能读
jack 不能写
jack 不能执行
```

------

## 5. 权限判断顺序很重要

Linux 判断权限时，大致按照这个顺序：

```text
1. 你是不是文件所有者？
   是：看 user 权限

2. 如果不是所有者，你是不是属于文件所属组？
   是：看 group 权限

3. 如果都不是：
   看 others 权限
```

也就是：

```text
先看 user
再看 group
最后看 others
```

注意一个细节：

> 如果你是文件所有者，就只看所有者权限，不会再去看用户组权限或其他用户权限。

比如：

```bash
----rwxrwx 1 book student 100 a.txt
```

权限是：

```text
--- rwx rwx
```

如果当前用户是 `book`，虽然 group 和 others 有 `rwx`，但是 `book` 是所有者，所以只看第一组：

```text
---
```

结果 `book` 反而没有权限。

------

## 6. 用生活例子理解

假设有一个房间 `a.txt`。

```text
所有者 user：房间主人
用户组 group：主人允许的一批同事
其他用户 others：其他所有陌生人
```

文件权限：

```bash
-rw-r----- 1 book student a.txt
```

可以理解为：

```text
房间主人 book：
可以看房间里的东西，可以修改房间里的东西

student 组的人：
可以看，但不能改

其他人：
不能看，也不能改
```

------

## 7. 一个具体例子

假设有 3 个用户：

```text
book
tom
jack
```

其中：

```text
book 属于 student 组
tom 也属于 student 组
jack 不属于 student 组
```

文件是：

```bash
-rw-r----- 1 book student a.txt
```

那么：

| 当前用户 | 身份判断                            | 使用哪组权限 | 结果         |
| -------- | ----------------------------------- | ------------ | ------------ |
| `book`   | 是所有者                            | `rw-`        | 可读、可写   |
| `tom`    | 不是所有者，但属于 `student` 组     | `r--`        | 可读，不可写 |
| `jack`   | 既不是所有者，也不属于 `student` 组 | `---`        | 没有权限     |

------

## 8. `chmod` 中的 u、g、o、a

所以你会看到这些写法：

```bash
chmod u+x a.txt
chmod g+w a.txt
chmod o-r a.txt
chmod a+r a.txt
```

含义是：

| 符号 | 含义                      |
| ---- | ------------------------- |
| `u`  | user，文件所有者          |
| `g`  | group，文件所属组         |
| `o`  | others，其他用户          |
| `a`  | all，所有人，也就是 u+g+o |

例如：

```bash
chmod u+x a.txt
```

表示给文件所有者增加执行权限。

```bash
chmod g+w a.txt
```

表示给文件所属组增加写权限。

```bash
chmod o-r a.txt
```

表示去掉其他用户的读权限。

```bash
chmod a+r a.txt
```

表示所有人都增加读权限。

------

## 9. `chown` 和 `chgrp` 是改谁？

比如：

```bash
-rw-r----- 1 book student a.txt
```

这里：

```text
book：所有者
student：所属组
```

如果要改所有者：

```bash
sudo chown tom a.txt
```

变成：

```bash
-rw-r----- 1 tom student a.txt
```

如果要改所属组：

```bash
sudo chgrp teacher a.txt
```

变成：

```bash
-rw-r----- 1 tom teacher a.txt
```

也可以同时改：

```bash
sudo chown tom:teacher a.txt
```

意思是：

```text
所有者改成 tom
所属组改成 teacher
```

------

## 10. 目录权限也一样分三类

比如：

```bash
drwxr-x--- 2 book student 4096 test
```

拆开：

```text
d rwx r-x ---
  │   │   │
  │   │   └── 其他用户权限
  │   └────── student 组用户权限
  └────────── book 用户权限
```

含义是：

```text
book 用户：
可以进入 test，可以列出内容，可以创建/删除/重命名文件

student 组用户：
可以进入 test，可以列出内容，但不能创建/删除/重命名文件

其他用户：
不能进入，也不能查看
```

------

## 11. 最核心的一句话

你可以这样记：

```text
user：文件主人
group：和文件同组的人
others：剩下所有人
```

权限判断：

```text
如果你是主人，看 user 权限；
如果你不是主人，但属于文件所属组，看 group 权限；
如果前两个都不是，看 others 权限。
```

对应到 `ls -l`：

```bash
-rw-r----- 1 book student a.txt
```

就是：

```text
book 这个主人：rw-
student 这个组的人：r--
其他所有人：---
```





# 2.对用户家目录与权限结合的理解

对，你理解得对：

```bash
book@ubuntu:~$
```

这里 `@` 前面的 `book` 就是**当前登录用户**，也就是 Linux 权限判断里的“用户”。

------

## 1. 不同用户的家目录是不是天然隔离？

<span style="background:#00FF80;">不是“天然绝对隔离”，而是靠**目录权限**隔离的。</span>

比如：

```bash
/home/book
/home/tom
```

能不能访问，不是因为它们名字不同，而是看权限。

例如：

```bash
ls -ld /home/tom
```

如果看到：

```bash
drwx------ tom tom /home/tom
```

也就是：

```text
rwx --- ---
```

那么：

```text
tom 自己：可以读、写、进入
同组用户：无权限
其他用户：无权限
```

<span style="color:#FF0000; background:#00FF80;">此时 `book` 当然访问不了：</span>

```bash
cd /home/tom
ls /home/tom
cat /home/tom/a.txt
```

因为 `book` 属于“其他用户”，而 `/home/tom` 对 others 是 `---`。

------

## 2. 但是如果 `/home/tom` 权限开放，book 就可能访问

比如 `/home/tom` 是： 

```bash
drwxr-xr-x tom tom /home/tom
```

也就是：

```text
rwx r-x r-x
```

那么其他用户有：

```text
r-x
```

这表示其他用户可以：

```text
进入 /home/tom
列出 /home/tom 里的文件名
```

这时 `book` 就可以：

```bash
ls /home/tom
```

如果里面有文件：

```bash
-rw-r--r-- tom tom a.txt
```

那么 `book` 也可以：

```bash
cat /home/tom/a.txt
```

因为：

```text
/home/tom 对 book 有 x 权限，可以进入/搜索
a.txt 对 others 有 r 权限，可以读取内容
```

<span style="color:#FF0000; background:#00FF80;">所以不同用户之间能不能访问，根本不是只看“是不是别人的家目录”，而是看：</span>

```text
路径上的目录权限 + 文件自身权限
```

------

## 3. 权限的意义就在这里：控制隔离程度

你说：

> 不同用户创建的文件不应该相互隔离吗？

更准确应该说：

> <span style="background:#00FF80;">Linux 支持不同用户隔离，但隔离程度由权限决定。</span>

比如：

### 完全私有

```bash
chmod 700 /home/tom
```

效果：

```text
只有 tom 能进入 /home/tom
其他人进不去，看不到里面内容
```

------

### 允许别人看文件名和读取公开文件

```bash
chmod 755 /home/tom
```

效果：

```text
别人可以进入 /home/tom
别人可以列出文件名
但能不能读具体文件，还要看文件权限
```

------

### 只允许别人穿过，但不能列出

```bash
chmod 711 /home/tom
```

效果：

```text
别人不能 ls /home/tom
但如果知道准确文件名，可能可以访问
```

例如：

```bash
cat /home/tom/public.txt
```

可能成功，但前提是 `public.txt` 本身允许别人读。

------

## 4. 举个完整例子

假设：

```bash
/home/tom          drwx------  tom tom
/home/tom/a.txt   -rw-r--r--  tom tom
```

虽然 `a.txt` 对 others 有 `r` 权限，但是 `book` 仍然不能读：

```bash
cat /home/tom/a.txt
```

因为 `/home/tom` 没有给 others `x` 权限，路径进不去。

也就是说：

```text
文件允许你读，但是目录不允许你到达它。
```

------

换一种：

```bash
/home/tom          drwxr-xr-x  tom tom
/home/tom/a.txt   -rw-r--r--  tom tom
```

这时 `book` 可以读：

```bash
cat /home/tom/a.txt
```

因为：

```text
/home/tom 有 x，可以进入/搜索
a.txt 有 r，可以读取内容
```

------

再换一种：

```bash
/home/tom          drwxr-xr-x  tom tom
/home/tom/a.txt   -rw-------  tom tom
```

这时 `book` 可以进入 `/home/tom`，但不能读 `a.txt`：

```bash
cat /home/tom/a.txt
```

会失败。

因为：

```text
目录允许你到达它
但文件本身不允许你读
```

------

## 5. 权限不只是管家目录，也管整个系统

<span style="color:#FF0000; background:#00FF80;">权限的意义不只是 `/home/book` 和 `/home/tom`。</span>

<span style="color:#FF0000; background:#00FF80;">Linux 里很多地方都需要权限控制：</span>

```text
/home/book        用户自己的文件
/tmp              所有人都能临时使用的目录
/usr/bin          系统命令
/etc              配置文件
/var/log          日志文件
/project          多人协作目录
/dev              设备文件
```

比如：

```bash
/bin/ls
```

通常是：

```bash
-rwxr-xr-x root root /bin/ls
```

意思是：

```text
root 可以读、写、执行
其他用户可以读、执行
但不能修改
```

所以普通用户可以执行：

```bash
ls
```

但不能修改 `/bin/ls` 这个程序。

这就是权限的意义。

------

## 6. 用户组的意义：多人共享

比如有一个项目目录：

```bash
/project
```

里面需要 `book`、`tom`、`jack` 三个人一起修改文件。

可以创建一个组：

```text
dev
```

然后让三个人都属于 `dev` 组。

目录设置成：

```bash
drwxrwx--- root dev /project
```

意思是：

```text
root：可以全部操作
dev 组成员：可以全部操作
其他用户：无权限
```

这样：

```text
book 可以访问
tom 可以访问
jack 可以访问
其他人不能访问
```

这就是 group 权限的作用。

------

## 7. 最核心的一句话

你可以这样理解：

```text
不同用户的家目录不是靠“名字不同”隔离的，
而是靠目录和文件的权限隔离的。
```

判断一个用户能不能访问某个文件，要看：

```text
1. 路径上每一级目录有没有 x 权限
2. 最终文件本身有没有对应的 r/w/x 权限
3. 当前用户属于 user、group、others 中哪一类
```

所以：

```text
用户权限：控制文件主人能做什么
用户组权限：控制同组成员能做什么
其他用户权限：控制剩下所有人能做什么
```

家目录只是一个典型例子：

```text
/home/tom 是 tom 的家目录
但 book 能不能访问它，最终还是看 /home/tom 的权限。
```





# 3.默认创建的文件的拥有者和用户组和默认权限

可以。你创建一个文件时，它的**所有者、所属组、默认权限**大致由这三件事决定：

```text
谁创建它        → 决定所有者
在哪个目录创建    → 可能影响所属组
当前 umask 值    → 决定默认权限
```

------

## 1. 文件所有者是谁？

一般情况下：

> **谁创建文件，谁就是文件所有者。**

比如你当前终端是：

```bash
book@ubuntu:~$
```

你执行：

```bash
touch a.txt
```

那么 `a.txt` 的所有者通常就是 `book`。

查看：

```bash
ls -l a.txt
```

可能看到：

```bash
-rw-r--r-- 1 book book 0 May 30 a.txt
```

这里两个 `book`：

```text
第一个 book：文件所有者
第二个 book：文件所属组
```

也就是：

```text
a.txt 的所有者是 book
a.txt 的所属组是 book
```

------

## 2. 如果用 sudo 创建呢？

如果你这样创建：

```bash
sudo touch b.txt
```

那么创建者变成了 `root`，所以文件所有者通常是 `root`：

```bash
ls -l b.txt
```

可能看到：

```bash
-rw-r--r-- 1 root root 0 May 30 b.txt
```

所以要记住：

```text
普通创建：所有者是当前用户
sudo 创建：所有者通常是 root
```

------

## 3. 文件所属组是谁？

一般情况下，文件所属组是：

> **<span style="background:#00FF80;">创建该文件的用户的当前有效用户组。</span>**

比如你当前用户是 `book`，默认主组也是 `book`，那么：

```bash
touch a.txt
```

得到：

```bash
-rw-r--r-- 1 book book a.txt
```

如果用户 `tom` 的主组是 `student`，那么 `tom` 创建文件可能是：

```bash
-rw-r--r-- 1 tom student a.txt
```

你可以用这个命令查看当前用户和所属组：

```bash
id
```

可能输出：

```bash
uid=1000(book) gid=1000(book) groups=1000(book),27(sudo)
```

这里：

```text
uid=1000(book)：当前用户是 book
gid=1000(book)：当前默认用户组是 book
groups=...：当前用户还属于哪些组
```

------

## 4. 但目录的 setgid 会影响新文件所属组

有一种特殊情况：如果父目录设置了 **setgid**，新文件会继承父目录的所属组。

比如有目录：

```bash
drwxrws--- 2 root project 4096 work
```

注意这里是：

```text
rws
```

这里的 `s` 表示这个目录设置了 setgid。

此时你在 `work` 目录里创建文件：

```bash
touch work/a.txt
```

文件所属组可能不是你的默认组，而是继承目录的组：

```bash
-rw-r--r-- 1 book project a.txt
```

<span style="color:#FF0000; background:#00FF80;">这个常用于多人协作目录。</span>

简单记：

```text
普通目录：新文件所属组通常是创建者的默认组
setgid目录：新文件所属组继承父目录的组
```

------

## 5. 新文件默认权限是什么？

新建普通文件时，理论初始权限一般是：

```bash
666
```

也就是：

```text
rw-rw-rw-
```

但是系统会用 `umask` 去“扣掉”一些权限。

你可以查看当前 `umask`：

```bash
umask
```

常见结果：

```bash
0022
```

那么普通文件默认权限就是：

```text
666 - 022 = 644
```

也就是：

```bash
-rw-r--r--
```

所以你创建：

```bash
touch a.txt
```

常见结果是：

```bash
-rw-r--r-- 1 book book 0 a.txt
```

含义：

```text
所有者 book：可读、可写
同组用户：可读
其他用户：可读
```

------

## 6. 为什么普通文件默认没有 x 执行权限？

新建普通文件默认通常是：

```bash
rw-r--r--
```

而不是：

```bash
rwxr-xr-x
```

因为系统默认认为：

> 普通新文件大多数是文本、数据，不应该一创建就能执行。

所以如果你写了一个脚本：

```bash
touch hello.sh
```

它默认可能是：

```bash
-rw-r--r-- hello.sh
```

你不能直接执行：

```bash
./hello.sh
```

需要手动加执行权限：

```bash
chmod +x hello.sh
```

之后变成：

```bash
-rwxr-xr-x hello.sh
```

------

## 7. 新建目录默认权限是什么？

目录和普通文件不同。

新建目录的理论初始权限一般是：

```bash
777
```

也就是：

```text
rwxrwxrwx
```

再被 `umask 022` 扣掉：

```text
777 - 022 = 755
```

所以：

```bash
mkdir test
```

常见结果是：

```bash
drwxr-xr-x 2 book book 4096 test
```

为什么目录默认有 `x`？

因为目录的 `x` 表示：

```text
能进入目录
能通过目录查找文件
```

如果目录没有 `x`，它就很难正常使用。

------

## 8. 用一张表总结

假设当前用户是 `book`，默认组是 `book`，`umask` 是 `022`。

| 操作                           | 所有者 | 所属组       | 默认权限                  |
| ------------------------------ | ------ | ------------ | ------------------------- |
| `touch a.txt`                  | `book` | `book`       | `rw-r--r--`，也就是 `644` |
| `mkdir test`                   | `book` | `book`       | `rwxr-xr-x`，也就是 `755` |
| `sudo touch b.txt`             | `root` | `root`       | 通常 `rw-r--r--`          |
| 在 setgid 目录里 `touch a.txt` | 创建者 | 继承父目录组 | 受 `umask` 影响           |

## 10. 最核心记忆

你可以这样记：

```text
文件所有者：谁创建，通常就是谁；sudo 创建通常是 root。

文件所属组：通常是创建者的默认组；
如果父目录有 setgid，则继承父目录的组。

文件默认权限：由系统初始权限减去 umask 决定；
普通文件常见是 644，目录常见是 755。
```

最常见例子：

```bash
touch a.txt
ls -l a.txt
```

看到：

```bash
-rw-r--r-- 1 book book 0 a.txt
```

意思就是：

```text
a.txt 是普通文件
所有者 book 可读可写
book 组用户可读
其他用户可读
文件所有者是 book
文件所属组是 book
```
