## 6. 复制与粘贴详解

### 6.1 `yy`：复制当前整行

把光标放在某一行的任意位置，在一般模式中按：

```vim
yy
```

表示<span style="color:#FF0000; background:#00FF80;">复制当前整行。</span>

<span style="color:#FF0000; background:#00FF80;">VI 中复制</span>通常叫作：

```text
yank
```

所以<span style="color:#FF0000; background:#00FF80;">画面底部可能出现：</span>

```text
1 line yanked
```

#### 操作示例

原内容：

```text
第一行
第二行    ← 光标在这里
第三行
```

按：

```vim
yy
```

屏幕上的文本暂时不会变化，因为<span style="color:#FF0000; background:#00FF80;">只是把“第二行”放入 VI 内部的寄存器中。</span>

------

### 6.2 `nyy`：复制多行

教材中的 `nyy` 不是让你真的输入字母 `n`。

这里的 `n` 代表具体数字，例如：

```vim
3yy
```

意思是：

> <span style="color:#FF0000; background:#00FF80;">从当前行开始，复制3行。</span>

假设光标位于第4行：

```vim
3yy
```

复制的是：

```text
第4行
第5行
第6行
```

视频约在 **01:20-01:35** 出现：

```text
3 lines yanked
```

说明讲师执行了类似：

```vim
3yy
```

------

### 6.3 `p`：粘贴

<span style="color:#FF0000; background:#00FF80;">复制完成后，把光标移动到目标位置，按：</span>

```vim
p
```

因为<span style="color:#FF0000; background:#00FF80;"> `yy` 复制的是整行，所以 `p` 会把这些行粘贴到：</span>

> **当前光标所在行的下方。**

例如：

```text
第一行
第二行    ← 光标在这里
第三行
```

之前复制了“测试内容”，按 `p` 后：

```text
第一行
第二行
测试内容
第三行
```

视频约在 **01:35-01:55** 出现：

```text
3 more lines
```

表示3行内容已经被插入。

#### 补充命令：`P`

```vim
P
```

<span style="color:#FF0000; background:#00FF80;">大写 `P` 表示粘贴到当前行的上方。</span>

| 命令 | 整行内容粘贴位置                                             |
| ---- | ------------------------------------------------------------ |
| `p`  | 当前行<span style="color:#FF0000; background:#00FF80;">下方</span> |
| `P`  | 当前行<span style="color:#FF0000; background:#00FF80;">上方</span> |

------

### 6.4 VI复制不是普通的 `Ctrl+C`

这里的：

```vim
yy
p
```

是 VI 内部的复制粘贴机制。

它不完全等于 Windows 中的：

```text
Ctrl+C
Ctrl+V
```

可以这样区分：

```text
yy / p：
在VI内部复制、粘贴文本。

Ctrl+C / Ctrl+V：
通常指图形软件或系统剪贴板操作。
```

在 Ubuntu 终端里，系统剪贴板一般使用：

```text
Ctrl+Shift+C
Ctrl+Shift+V
```

但学习 VI 时，应该优先掌握 `yy` 和 `p`。

------

### 6.5 删除后也可以粘贴

VI 中使用：

```vim
dd
```

<span style="color:#FF0000; background:#00FF80;">删除一行时，被删除的内容通常也会进入内部寄存器。</span>

所以：

```vim
dd
p
```

可以<span style="color:#FF0000; background:#00FF80;">产生类似“剪切后粘贴”的效果。</span>

例如想把当前行向下移动一行：

```vim
dd
p
```

逻辑是：

```text
dd：删除并暂存当前行
p：在下一位置粘贴
```

## 7. 查找命令详解

### 7.1 `/关键词`：向<span style="color:#FF0000; background:#00FF80;">文件后方</span>查找

在<span style="color:#FF0000; background:#00FF80;">一般模式输入：</span>

```vim
/custom
```

然后按回车。

意思是：

> <span style="color:#FF0000; background:#00FF80;">从当前光标位置开始，向文件后面查找 `custom`。</span>

视频约在 **02:20-02:40** 使用了 `custom` 作为查找对象，匹配到的文本被突出显示。

#### 示例

```vim
/error
```

表示<span style="color:#FF0000; background:#00FF80;">向后查找 `error`。</span>

------

### 7.2 `?关键词`：向<span style="color:#FF0000; background:#00FF80;">文件前方</span>查找

输入：

```vim
?custom
```

然后回车。

表示：

> <span style="color:#FF0000; background:#00FF80;">从当前光标位置开始，向文件前面查找 `custom`。</span>

视频约在 **02:40** 左右，底部可以看到：

```text
?custom
```

------

### 7.3 `n` 和 `N`

查找到第一个结果后：

```vim
n
```

表示<span style="color:#FF0000; background:#00FF80;">沿着刚才的查找方向，继续查找下一个匹配。</span>

```vim
N
```

表示<span style="color:#FF0000; background:#00FF80;">沿相反方向查找。</span>

这是更准确的理解：

| 原始查找命令        | `n`      | `N`      |
| ------------------- | -------- | -------- |
| `/custom`，向后查找 | 继续向后 | 改为向前 |
| `?custom`，向前查找 | 继续向前 | 改为向后 |

因此，<span style="color:#FF0000; background:#00FF80;">不能简单地永久记成：</span>

```text
n一定向下
N一定向上
```

<span style="color:#FF0000; background:#00FF80;">应该记成：</span>

```text
n：保持原查找方向
N：反转查找方向
```

## <span style="color:#FF0000; background:#00FF80;">8. 替换命令详解</span>

### 8.1 完整命令

视频使用的结构是：

```vim
:%s/p1/p2/g
```

例如<span style="color:#FF0000;">将所有小写 `custom` 替换为大写开头的 `Custom`：</span>

```vim
:%s/custom/Custom/g
```

------

### 8.2 每一部分分别是什么意思？

把命令拆开：

```text
:   进入命令行模式
%   所有行，即整个文件
s   substitute，替换
custom   被替换的旧内容
Custom   替换后的新内容
g   当前范围内每一行的所有匹配都替换
```

所以：

```vim
:%s/custom/Custom/g
```

完整含义是：

> <span style="color:#FF0000; background:#00FF80;">在整个文件中，把所有出现的 `custom` 替换成 `Custom`。</span>

------

### 8.3 为什么需要 `%`？

#### 只替换当前行

```vim
:s/custom/Custom/g
```

<span style="color:#FF0000; background:#00FF80;">只作用于当前行。</span>

#### 替换整个文件

```vim
:%s/custom/Custom/g
```

<span style="color:#FF0000; background:#00FF80;">`%` 表示整个文件的全部行。</span>

------

#### 8.4 为什么需要 `g`？

假设一行是：

```text
custom abc custom
```

使用：

```vim
:s/custom/Custom/
```

通常只替换这一行中的第一个：

```text
Custom abc custom
```

使用：

```vim
:s/custom/Custom/g
```

则替换这一行中的所有匹配：

```text
Custom abc Custom
```

<span style="color:#FF0000; background:#00FF80;">所以：</span>

```text
g = global
```

<span style="color:#FF0000; background:#00FF80;">在替换命令末尾时，表示该行内所有匹配。</span>

结合 `%`：

```vim
:%s/custom/Custom/g
```

才<span style="color:#FF0000; background:#00FF80;">构成整个文件中的全部匹配替换。</span>

------

## 9. `gc`：替换前逐个确认

视频后半段使用：

```vim
:%s/custom/Custom/gc
```

最后的：

```text
c = confirm
```

表示<span style="color:#FF0000; background:#00FF80;">每遇到一个匹配，都询问你是否替换。</span>

画面约在 **04:20-04:40** 出现：

```text
replace with Custom (y/n/a/q/l/^E/^Y)?
```

常用选择是：

| 按键 | 含义                           |
| ---- | ------------------------------ |
| `y`  | 替换当前这一个                 |
| `n`  | 不替换当前这一个，继续看下一个 |
| `a`  | 替换后面全部匹配，不再询问     |
| `q`  | 停止替换                       |
| `l`  | 替换当前这个，然后停止         |

例如文件中有三个 `custom`：

```text
custom ①
custom ②
custom ③
```

执行：

```vim
:%s/custom/Custom/gc
```

然后依次输入：

```text
y
n
y
```

结果是：

```text
Custom ①
custom ②
Custom ③
```

这与视频中部分 `custom` 变成 `Custom`、部分仍保持小写的现象一致。

## 10. 最容易混淆的地方

| 容易混淆                      | 正确理解                             |
| ----------------------------- | ------------------------------------ |
| `nyy` 中的 `n` 是不是字母？   | 不是，代表数字，例如 `3yy`           |
| `yy` 后文字为什么没变化？     | 因为只是复制，还没有粘贴             |
| `p` 粘贴在哪里？              | 整行复制时，粘贴到当前行下方         |
| `/custom` 和 `?custom` 的区别 | `/` 向后查找，`?` 向前查找           |
| `n` 是不是永远向下？          | 不是，`n` 保持刚才的查找方向         |
| `%` 有什么作用？              | 表示整个文件的全部行                 |
| `g` 有什么作用？              | 替换每一行中的全部匹配               |
| `c` 有什么作用？              | 每次替换前询问确认                   |
| `yy/p` 是否等于系统剪贴板？   | 不完全等于，它们主要使用VI内部寄存器 |

## 15. 重点片段精读

### 片段一：00:33-00:58

**表面发生了什么：**
复制一行，再粘贴到其他位置。

**更深层可能意味着：**
`yy` 只是将内容放入VI内部寄存器，不会立即改变文本；必须再执行 `p` 才能看到新内容。

**重要性：**
解决初学者“按了 `yy` 为什么什么都没发生”的疑问。

------

### 片段二：01:20-01:55

**表面发生了什么：**
底部出现 `3 lines yanked`，随后出现 `3 more lines`。

**更深层可能意味着：**
数字可以放在命令前，控制操作数量：

```vim
3yy
```

比连续执行三次 `yy` 更高效。

**重要性：**
体现VI“数字＋命令”的核心操作逻辑。

------

### 片段三：02:04-02:50

**表面发生了什么：**
使用 `/custom` 和 `?custom` 在多个匹配之间跳转。

**更深层可能意味着：**
查找不是简单地“找到一个”，还包括搜索方向以及继续搜索的方向。

**重要性：**
在大型配置文件中，查找比手动翻页有效得多。

------

### 片段四：04:05-04:47

**表面发生了什么：**
底部逐个询问是否将 `custom` 替换为 `Custom`。

**更深层可能意味着：**
全局替换可能误改不应修改的位置，`c` 可以让用户逐个审核。

**重要性：**
这是编辑系统配置文件时更安全的做法。
