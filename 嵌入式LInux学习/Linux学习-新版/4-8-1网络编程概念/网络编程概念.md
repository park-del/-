## 5. IP 和端口到底分别是什么？

这是 **08:30-11:10** 最关键的部分。

课件里明确说到，<span style="color:#FF0000; background:#00FF80;">数据传输有：</span>

```text
源
目的
长度
```

但是，<span style="color:#FF0000; background:#00FF80;">“目的”不能只知道是哪台电脑。</span>

比如：

```text
192.168.1.100
```

只告诉你：

> 去这台机器。

可是<span style="color:#FF0000; background:#00FF80;">这台电脑可能同时运行：</span>

```text
浏览器
SSH服务器
HTTP服务器
FTP服务器
你自己写的网络程序
……
```

到底交给谁？

所以<span style="background:#00FF80;">还需要 **端口号**。</span>

可以把它理解成：

```text
IP地址 = 找到哪栋楼
端口号 = 找到楼里的哪个房间
```

<span style="color:#FF0000; background:#00FF80;">所以：</span>

```text
IP + port
```

<span style="color:#FF0000; background:#00FF80;">才能比较完整地表示网络中的一个通信端点。</span>

例如：

```text
192.168.1.100:80
```

可以理解为：

> 去 192.168.1.100 这台机器上，找到监听 80 端口的程序。

------

### 一个特别容易混淆的地方

课件里浏览器访问 HTTP 服务器的例子非常重要。

假设你电脑同时开两个浏览器窗口：

```text
浏览器A ──────┐
              ├──→ 服务器IP:80
浏览器B ──────┘
```

<span style="color:#FF0000; background:#00FF80;">服务器怎么区分这两条通信？</span>

<span style="background:#00FF80;">不仅仅看：</span>

```text
服务器IP
服务器端口
```

<span style="background:#00FF80;">还会涉及通信另一端的：</span>

```text
客户端IP
客户端端口
```

<span style="color:#FF0000; background:#00FF80;">对于 TCP，一条连接通常可以用这四项理解：</span>

```text
客户端IP
客户端端口
服务器IP
服务器端口
```

所以<span style="color:#FF0000; background:#00FF80;">两个浏览器即使访问同一个：</span>

```text
服务器IP:80
```

<span style="background:#00FF80; color:#FF0000;">它们也可以拥有不同的客户端端口，从而形成不同连接。</span>

## 6. Server 和 Client 到底是什么？

大约 **03:35-07:40** 的板书非常明确：

```text
服务器：被动地响应请求
客户端：主动地发起请求
```

这里非常值得注意：

**server/client 不是根据电脑性能区分的。**

不是说：

```text
性能好的电脑 = Server
性能差的电脑 = Client
```

而是看程序扮演的角色。

<span style="color:#FF0000; background:#00FF80;">例如开发板完全可以运行一个：</span>

```text
TCP Server
```

<span style="color:#FF0000; background:#00FF80;">你的 Windows PC 运行：</span>

```text
TCP Client
```

<span style="color:#FF0000; background:#00FF80;">也完全可以反过来。</span>

<span style="color:#FF0000; background:#00FF80;">所以真正应该理解成：</span>

```text
Server程序  ← 等别人来找自己
Client程序  → 主动去找Server
```

## 7. TCP 和 UDP 在这里扮演什么角色？

视频大约 **04:30-07:40** 开始画：

```text
TCP
UDP
```

板书对 TCP 强调“可靠、连接”，UDP 则对应不可靠这一类特征。

<span style="color:#FF0000; background:#00FF80;">这一层可以理解成：</span>

```text
IP + Port
    │
    │ 解决“跟谁通信”
    ▼

TCP / UDP
    │
    │ 解决“按照什么方式通信”
    ▼

socket API
    │
    │ 程序真正使用的接口
    ▼
应用程序
```

简单记：

### TCP

```text
先建立连接
↓
再通信
↓
强调可靠传输
```

比较像：

> <span style="color:#FF0000; background:#00FF80;">先把电话拨通，再开始讲话。</span>

### UDP

```text
不需要先建立这种 TCP 连接
↓
直接发送数据报
```

更像：

> <span style="color:#FF0000; background:#00FF80;">写好一张纸直接发出去。</span>

<span style="color:#FF0000; background:#00FF80;">这节重点实际上还在 TCP 的整体框架，后面的课程才会分别深入 TCP 和 UDP</span>。

## 8. `socket()` 到底是什么？

这是 **11:10 左右以后**真正进入 Linux 网络编程的地方。

老师甚至打开了：

```bash
man 2 socket
```

手册里的核心含义就是：

> <span style="background:#00FF80; color:#FF0000;">`socket()` 创建一个用于通信的 endpoint，并返回一个描述符。</span>

于是程序里就出现：

```c
fd = socket(...);
```

这<span style="color:#FF0000; background:#00FF80;">里非常值得和你前面学的文件 I/O 联系起来。</span>

你之前看到的是：

```c
fd = open(...);

read(fd, ...);
write(fd, ...);
```

<span style="color:#FF0000; background:#00FF80;">现在网络世界变成：</span>

```c
fd = socket(...);
```

<span style="background:#00FF80; color:#FF0000;">之后也同样围绕这个 **fd** 来进行操作。</span>

所以你<span style="color:#FF0000; background:#00FF80;">可以建立一个很重要的 Linux 思维：</span>

```text
文件
  ↓ open()
file descriptor

网络socket
  ↓ socket()
file descriptor
```

也就是：

> <span style="color:#FF0000; background:#00FF80;">**应用程序并不是自己直接去操作网卡，而是先向 Linux 内核申请一个 socket，由内核返回 fd，程序以后围绕这个 fd 进行网络操作。**</span>

这<span style="color:#FF0000; background:#00FF80;">和你前面学 `open()`、`struct file`、fd 那条线，其实已经开始连起来了。</span>

------

## 9. 为什么服务器要 `bind()`？

视频 **12:10-15:00 左右**板书：

```c
fd = socket(...);

bind(...);
```

旁边明确写了类似：

```text
自己的IP、端口
```

可以这样理解。

<span style="color:#FF0000; background:#00FF80;">`socket()` 只是</span>：

> <span style="background:#00FF80;">给我创建一个网络通信对象。</span>

但<span style="background:#00FF80; color:#FF0000;">别人现在还不知道去哪里找你。</span>

<span style="color:#FF0000; background:#00FF80;">服务器需要告诉内核：</span>

```text
我要使用这个本机 IP
+
我要占用这个端口
```

<span style="color:#FF0000; background:#00FF80;">所以使用：</span>

```c
bind(fd, 本地IP和端口, ...);
```

例如：

```text
服务器：

192.168.1.10:8888
```

<span style="color:#FF0000; background:#00FF80;">于是客户端以后就可以：</span>

```text
connect(192.168.1.10:8888)
```

来<span style="color:#FF0000; background:#00FF80;">找到它。</span>

## 10.`listen()`、`accept()`、`connect()` 是什么关系？

这一部分是 **15:00-19:00** 的重点。

服务器：

```text
socket()
   ↓
bind()
   ↓
listen()
```

`listen()` 可以先粗略理解成：

> <span style="color:#FF0000; background:#00FF80;">我这个 socket 准备开始接受客户端的 TCP 连接请求了。</span>

之后：

```c
accept(...)
```

<span style="color:#FF0000; background:#00FF80;">服务器在这里等待客户端。</span>

<span style="color:#FF0000; background:#00FF80;">客户端这边：</span>

```c
socket(...);
connect(服务器IP + 服务器端口);
```

于是：

```text
Server                         Client

accept()   ◀──────────────   connect()
               建立TCP连接
```

<span style="color:#FF0000; background:#00FF80;">这就是为什么前面说：</span>

```text
Server：被动
Client：主动
```

<span style="color:#FF0000; background:#00FF80;">因为：</span>

```text
客户端主动 connect
服务器等待 accept
```

------

### 有一个以后非常重要的小细节

真正写 TCP Server 时：

```c
listen_fd = socket(...);

bind(listen_fd, ...);

listen(listen_fd, ...);

conn_fd = accept(listen_fd, ...);
```

这里<span style="color:#FF0000; background:#00FF80;">最好从现在就区分：</span>

```text
listen_fd
    ↓
负责“等新的客户端”

conn_fd
    ↓
负责“和已经连接上的某个客户端通信”
```

<span style="color:#FF0000; background:#00FF80;">也就是说 `accept()` 成功以后，实际会得到一个新的连接 socket。</span>

这个概念以后写多客户端服务器时会特别重要。

## 11. 最后为什么又变成 `send()` / `recv()`？

TCP 连接建立以后，复杂的“建连接”阶段基本完成。

之后双方就可以：

```text
Server                    Client

send()  ───────────────→ recv()

recv()  ←─────────────── send()
```

所以你可以把 TCP 编程分成两个阶段：

```text
第一阶段：想办法建立通信关系

Server:
socket
bind
listen
accept

Client:
socket
connect
```

建立之后：

```text
第二阶段：真正传数据

send
recv
send
recv
……
```

这就是视频最后几分钟画那几条箭头的意义。

# 问题1

也就是说 `accept()` 成功以后，实际会得到一个新的连接 socket。  这句话是什么意思，我不太懂，你能够给我解释下吗。



对，这句话一开始确实很容易绕。你先抓住一个最核心的区别：

> <span style="color:#FF0000; background:#00FF80;">**服务器其实会同时保留两类 socket：一个专门“接客”，另一个专门“聊天”。**</span>

假设服务器这样写：

```c
int listen_fd;
int client_fd;

listen_fd = socket(...);

bind(listen_fd, ...);

listen(listen_fd, 5);

client_fd = accept(listen_fd, ...);
```

这里<span style="background:#00FF80;">其实出现了 **两个不同的 fd**：</span>

```text
listen_fd
    ↓
监听 socket
    ↓
专门负责：
“有没有新的客户端要连接我？”


client_fd
    ↓
连接 socket
    ↓
专门负责：
“和这个已经连接成功的客户端收发数据”
```

也就是说，`accept()` **不是把 `listen_fd` 变成连接 socket**。

<span style="color:#FF0000; background:#00FF80;">而是：</span>

```text
原来的监听 socket 继续保留

listen_fd
   │
   │ accept()
   │
   ├────────→ 返回一个新的 client_fd
   │
   ▼
继续等待其他客户端
```

可以把它想象成一个酒店前台。

```text
                 酒店前台
                listen_fd
                    │
         “有没有新客人来？”
                    │
        ┌───────────┴───────────┐
        │                       │
      客户A                   客户B
        │                       │
     accept()                accept()
        │                       │
        ▼                       ▼
   client_fd=4             client_fd=5
        │                       │
    服务客户A                服务客户B
```

**`listen_fd` 就像前台。**

前台的任务不是一直陪某个客人聊天，而是：

> 不断接待新客人。

<span style="color:#FF0000; background:#00FF80;">而 `accept()` 每成功接待一个客户端，就给这个客户端分配一个新的“专属通信窗口”。</span>

------

举一个更具体的例子。

服务器：

```c
int listen_fd = socket(...);

bind(listen_fd, ...);

listen(listen_fd, 5);
```

<span style="color:#FF0000; background:#00FF80;">假设这时候：</span>

```text
listen_fd = 3
```

它<span style="color:#FF0000; background:#00FF80;">可能一直都是：</span>

```text
fd 3
↓
监听 192.168.1.10:8888
```

<span style="color:#FF0000; background:#00FF80;">现在客户端 A：</span>

```text
192.168.1.20:50001
```

<span style="color:#FF0000; background:#00FF80;">连接服务器：</span>

```text
192.168.1.10:8888
```

<span style="color:#FF0000; background:#00FF80;">服务器执行：</span>

```c
int client_fd = accept(listen_fd, ...);
```

<span style="color:#FF0000; background:#00FF80;">假设返回：</span>

```text
client_fd = 4
```

<span style="color:#FF0000; background:#00FF80;">现在：</span>

```text
fd 3
↓
监听 socket
↓
继续等别人连接


fd 4
↓
连接 socket
↓
专门对应客户端 A
192.168.1.20:50001
```

<span style="color:#FF0000; background:#00FF80;">服务器以后和客户端 A 通信：</span>

```c
recv(4, ...);
send(4, ...);
```

**不是：**

```c
recv(3, ...);   // 不是拿监听fd收客户端正常数据
```

------

<span style="color:#FF0000; background:#00FF80;">这时候又来了客户端 B：</span>

```text
客户端B
192.168.1.30:50002
```

<span style="color:#FF0000; background:#00FF80;">服务器再次：</span>

```c
client_fd2 = accept(listen_fd, ...);
```

<span style="color:#FF0000; background:#00FF80;">假设返回：</span>

```text
client_fd2 = 5
```

<span style="color:#FF0000; background:#00FF80;">现在服务器里面就是：</span>

```text
fd 3
│
└── 监听 socket
    继续接受新连接


fd 4
│
└── 已连接 socket
    ↔ 客户端A


fd 5
│
└── 已连接 socket
    ↔ 客户端B
```

<span style="background:#00FF80;">这个图特别重要：</span>

```text
                    Server

             fd=3  listen socket
                    │
             192.168.1.10:8888
                    │
           ┌────────┴────────┐
           │                 │
       accept()          accept()
           │                 │
           ▼                 ▼
        fd=4               fd=5
           │                 │
           │                 │
     Client A            Client B
192.168.1.20:50001  192.168.1.30:50002
```

所以你现在应该能看出：**为什么一定要产生新的 socket。**

假如 `accept()` 不创建新的连接 socket，而是直接把 `listen_fd` 拿去跟客户端 A 通信：

```text
listen_fd
   ↓
跟A聊天去了
```

那问题来了：

> 客户端 B 再来连接，谁负责接待 B？

没人了。

所以 <span style="color:#FF0000; background:#00FF80;">Linux 的设计是：</span>

```text
监听socket：
只负责不断接收新连接

连接socket：
一个客户端对应一个，用来真正通信
```

------

再和你之前学过的 **fd → 内核对象** 联系起来，就更清楚了。

可以先粗略理解成：

```text
进程的 fdtable

fd 0 → stdin
fd 1 → stdout
fd 2 → stderr

fd 3 → 监听 socket
fd 4 → 与客户端A连接的 socket
fd 5 → 与客户端B连接的 socket
```

所以<span style="background:#00FF80;"> `accept()` 返回的那个整数，比如：</span>

```c
4
```

<span style="background:#00FF80; color:#FF0000;">并不是“网络连接本身”，它仍然是一个 **文件描述符 fd**。</span>

<span style="color:#FF0000; background:#00FF80;">大概关系是：</span>

```text
client_fd = 4
     ↓
fdtable[4]
     ↓
内核中的一个 socket 对象
     ↓
代表服务器 ↔ 客户端A 的 TCP 连接
```

这跟你前面学的：

```text
fd
↓
fdtable
↓
struct file
```

那个思路非常像。<span style="color:#FF0000; background:#00FF80;">网络 socket 在 Linux 中同样能够通过文件描述符提供给用户程序操作。</span>

------

还有一个特别容易误解的地方：

### `socket()` 和 `accept()` 都能得到 fd，但意义不一样

服务器一开始：

```c
listen_fd = socket(...);
```

得到：

```text
一个还没有连接任何具体客户端的 socket
```

<span style="color:#FF0000; background:#00FF80;">随后：</span>

```c
bind();
listen();
```

<span style="color:#FF0000; background:#00FF80;">把它变成：</span>

```text
监听 socket
```

而：

```c
client_fd = accept(listen_fd, ...);
```

<span style="color:#FF0000; background:#00FF80;">得到的是：</span>

```text
已经和某个具体客户端建立连接的 socket
```

所以：

```text
socket()
   ↓
创建“监听用”的基础 socket

bind()
   ↓
绑定自己的 IP + Port

listen()
   ↓
让它进入监听状态

accept()
   ↓
有客户端连接成功
   ↓
产生/返回一个新的“已连接 socket”的 fd
```

你最后可以直接记成这句话：

> **`listen_fd` 是总机号码，永远负责接新电话；`accept()` 每接通一个电话，就给你一个新的 `client_fd`，以后你通过这个 `client_fd` 跟这个客户说话。**

所以以后看到这段代码：

```c
int sockfd = socket(...);

bind(sockfd, ...);
listen(sockfd, 5);

int newfd = accept(sockfd, ...);
```

脑子里直接翻译成：

```text
sockfd
= 接待新客户端的监听窗口

newfd
= 与某一个具体客户端通信的专属窗口
```

这就是“**`accept()` 成功以后，会得到一个新的连接 socket**”真正想表达的意思。



# 问题2

socket对象是一个什么东西呢，你能够从底层到系统驱动函数的角度给我讲解下这个通信过程吗？



可以。这个问题非常关键，因为 <span style="background:#00FF80;">**socket 其实正好处在“用户程序 → Linux 内核 → TCP/IP 协议栈 → 网卡驱动 → 硬件”这条链路的中间位置**</span>。

你之前已经学过：

```text
进程
 ↓
fd
 ↓
fdtable
 ↓
struct file
```

现在我们只需要继续往下走：

```text
用户程序
   ↓
socket fd
   ↓
fdtable
   ↓
struct file
   ↓
struct socket
   ↓
struct sock
   ↓
struct tcp_sock       ← 如果是 TCP
   ↓
TCP/IP 协议栈
   ↓
struct sk_buff
   ↓
struct net_device
   ↓
网卡驱动
   ↓
DMA / 网卡硬件
   ↓
网线
```

这就是今天最重要的一张总图。

------

## 一、先回答：socket 对象到底是什么？

“socket 对象”这个说法其实有两层含义。

<span style="color:#FF0000; background:#00FF80;">Linux 内核里最重要的是两个结构：</span>

```text
struct socket
struct sock
```

它们名字特别像，但职责不同。

<span style="color:#FF0000; background:#00FF80;">可以先这么记：</span>

```text
struct socket
    ↓
偏“系统调用/VFS接口层”

struct sock
    ↓
偏“网络协议栈内部”
```

也就是：

> `struct socket` 是<span style="color:#FF0000;">给 Linux 文件/socket 接口这一层使用的包装对象</span>；
> `struct sock` 才是<span style="background:#00FF80;">真正保存网络协议状态的核心对象。</span>

<span style="color:#FF0000;">如果是 TCP，还会继续具体化成：</span>

```text
struct tcp_sock
```

因此<span style="color:#FF0000; border:1px solid #330000; background:#00FF80;"> TCP socket 可以粗略理解成：</span>

```text
fd
 ↓
struct file
 ↓
struct socket
 ↓
struct sock
 ↓
struct tcp_sock
```

------

## 二、从 `socket()` 开始看

用户程序写：

```c
int fd;

fd = socket(AF_INET, SOCK_STREAM, 0);
```

<span style="color:#FF0000; background:#00FF80;">这里：</span>

```text
AF_INET
```

<span style="color:#FF0000; background:#00FF80;">表示 IPv4。</span>

```text
SOCK_STREAM
```

通常<span style="background:#00FF80; color:#FF0000;">意味着 TCP。</span>

<span style="color:#FF0000; background:#00FF80;">程序执行 `socket()` 后，会从用户态进入内核。</span>

大概过程是：

```text
用户态

socket(AF_INET, SOCK_STREAM, 0)
        │
        │ system call
        ▼
════════════════════════════════
内核态

__sys_socket()
        ↓
sock_create()
        ↓
__sock_create()
        ↓
inet_create()
        ↓
分配 socket / sock
        ↓
sock_map_fd()
        ↓
分配 struct file
        ↓
放入当前进程 fdtable
        ↓
返回 fd
```

所以：

```c
fd = socket(...);
```

假设得到：

```text
fd = 3
```

<span style="color:#FF0000; background:#00FF80;">绝对不要理解成：</span>

> “3 就是 socket。”

不是。

<span style="color:#FF0000; background:#00FF80;">`3` 只是一个整数索引。</span>

<span style="color:#FF0000; background:#00FF80;">真正关系更像：</span>

```text
current
  ↓
task_struct
  ↓
files_struct
  ↓
fdtable

┌──────────┬────────────────────┐
│ fd       │ 指向                │
├──────────┼────────────────────┤
│ 0        │ stdin              │
│ 1        │ stdout             │
│ 2        │ stderr             │
│ 3        │ struct file ──────┐│
└──────────┴───────────────────┘│
                                ↓
                         struct socket
                                ↓
                         struct sock
                                ↓
                         TCP协议状态
```

这<span style="color:#FF0000; background:#00FF80;">和你之前学文件 I/O 的思路完全一致。</span>

------

## 三、`struct socket` 是干什么的？

可以简化理解成：

```c
struct socket {
    ...
    struct file *file;
    struct sock *sk;
    const struct proto_ops *ops;
    ...
};
```

注意这是简化示意，不是完整定义。

<span style="color:#FF0000; background:#00FF80;">最重要的就是：</span>

```text
struct socket
    │
    ├── file
    │
    ├── ops
    │
    └── sk ─────→ struct sock
```

其中：

### `file`

<span style="color:#FF0000; background:#00FF80;">把 socket 和 Linux 的文件系统/VFS 世界连接起来。</span>

所以<span style="color:#FF0000; background:#00FF80;"> socket fd 甚至可以：</span>

```c
write(fd, buf, len);
read(fd, buf, len);
```

<span style="color:#FF0000; background:#00FF80;">当然网络程序更多使用：</span>

```c
send();
recv();
```

------

### `ops`

表示：

> 这个 socket 支持什么操作，以及这些操作应该调用谁。

例如：

```text
bind
listen
accept
connect
sendmsg
recvmsg
```

对于 IPv4 TCP socket，会进入 `inet_*` 这一层。

------

### `sk`

这个特别重要：

```c
struct sock *sk;
```

它指向真正的网络协议对象。

------

## 四、那 `struct sock` 又是什么？

这个就<span style="background:#00FF80; color:#FF0000;">真正进入网络协议栈了。</span>

它会保存诸如：

```text
socket 当前状态
发送缓冲区
接收缓冲区
等待队列
协议类型
源地址
目的地址
回调函数
路由信息
各种网络状态
```

<span style="color:#FF0000; background:#00FF80;">如果是 TCP，因为 TCP 需要保存更多东西，例如：</span>

```text
序列号
ACK号
发送窗口
接收窗口
拥塞窗口
重传定时器
RTT
TCP状态
```

所以<span style="background:#00FF80;">普通 `struct sock` 还不够。</span>

<span style="color:#FF0000; background:#00FF80;">Linux 会使用更具体的：</span>

```text
struct tcp_sock
```

<span style="color:#FF0000; background:#00FF80;">其关系大致是：</span>

```text
struct tcp_sock
      ↓
struct inet_connection_sock
      ↓
struct inet_sock
      ↓
struct sock
```

可以理解为一层层扩展：

```text
sock
│
│ 网络socket公共信息
▼
inet_sock
│
│ IPv4/IPv6相关信息
▼
inet_connection_sock
│
│ 面向连接协议的信息
▼
tcp_sock
│
│ TCP专属信息
▼
TCP序号、窗口、拥塞控制、重传……
```

------

## 五、所以<span style="background:#00FF80; color:#FF0000;">一个 TCP socket 内核里其实“记了很多东西”</span>

比如<span style="color:#FF0000; background:#00FF80;">服务器已经和客户端建立连接：</span>

```text
Server
192.168.1.10:8888

        ↕

Client
192.168.1.20:50001
```

<span style="color:#FF0000; background:#00FF80;">这个连接对应的 TCP socket 内部会保存：</span>

```text
本地IP：
192.168.1.10

本地Port：
8888

远端IP：
192.168.1.20

远端Port：
50001

TCP状态：
ESTABLISHED

发送序列号：
xxxx

接收序列号：
xxxx

发送缓冲区：
...

接收缓冲区：
...

拥塞控制：
...

重传状态：
...
```

所以 <span style="color:#FF0000; background:#00FF80;">socket 并不仅仅是一个“接口”。</span>

<span style="background:#00FF80;">它还是：</span>

> <span style="color:#FF0000; background:#00FF80;">**内核用来记录某条网络通信状态的一整套数据结构。**</span>

------

## 六、现在来看服务器 `socket → bind → listen`

服务器：

```c
int listen_fd;

listen_fd = socket(AF_INET, SOCK_STREAM, 0);

bind(listen_fd, ...);

listen(listen_fd, 5);
```

<span style="color:#FF0000; background:#00FF80;">内部可以理解为：</span>

```text
socket()
  ↓
创建 socket 对象

bind()
  ↓
给 socket 填上本地地址
例如：
192.168.1.10:8888

listen()
  ↓
让 TCP socket 进入 LISTEN 状态
```

于是：

```text
struct tcp_sock
      ↓
TCP状态 = LISTEN
```

它现在的任务就变成：

> 等别人连接。

------

## 七、客户端 `connect()` 后，底层发生了什么？

客户端：

```c
connect(fd, &server_addr, ...);
```

大概进入：

```text
用户态
connect()
   ↓
════════════════════
内核态
__sys_connect()
   ↓
sock->ops->connect()
   ↓
inet_stream_connect()
   ↓
tcp_v4_connect()
   ↓
TCP协议栈
```

<span style="color:#FF0000; background:#00FF80;">然后 TCP 开始执行我们熟悉的三次握手。</span>

------

## 八、TCP 三次握手在 socket 层是什么感觉？

假设：

```text
Client                    Server

192.168.1.20:50001      192.168.1.10:8888
```

第一步：

```text
Client

connect()
   │
   │ SYN
   ▼
Server
```

第二步：

```text
Client
   ▲
   │ SYN + ACK
   │
Server
```

第三步：

```text
Client
   │
   │ ACK
   ▼
Server
```

<span style="color:#FF0000; background:#00FF80;">最终：</span>

```text
Client socket
TCP状态 = ESTABLISHED

Server连接socket
TCP状态 = ESTABLISHED
```

------

## 九、这时候重新理解 `accept()`

这里我稍微把我们上一轮说法再精确一点。

我们之前说：

> `accept()` 成功后得到新的连接 socket。

从应用程序角度这是完全正确的。

但是从内核底层角度，更精确地说：

> **TCP 三次握手完成时，内核实际上已经为这个连接准备好了对应的 child socket，并放进服务器的 accept queue；应用调用 `accept()` 时，把这个已建立连接取出来，然后包装成一个新的 fd 返回给应用。**

这点特别重要。

------

### 假设服务器监听

```text
listen_fd = 3
```

客户端 A 连上来了。

<span style="color:#FF0000; background:#00FF80;">内核大致变成：</span>

```text
监听 socket
fd = 3
TCP = LISTEN
        │
        │
        ▼
   accept queue
┌─────────────────────┐
│ 已完成连接：Client A │
└─────────────────────┘
```

<span style="color:#FF0000; background:#00FF80;">服务器：</span>

```c
client_fd = accept(listen_fd, ...);
```

<span style="color:#FF0000; background:#00FF80;">进入：</span>

```text
accept()
   ↓
从 accept queue
拿出一个已建立连接
   ↓
创建对应的 struct file
   ↓
分配新 fd
   ↓
返回给应用
```

<span style="color:#FF0000; background:#00FF80;">比如：</span>

```text
client_fd = 4
```

<span style="color:#FF0000; background:#00FF80;">现在：</span>

```text
fd 3
 ↓
监听 socket
 ↓
LISTEN


fd 4
 ↓
连接 socket
 ↓
ESTABLISHED
 ↓
192.168.1.20:50001
```

<span style="color:#FF0000; background:#00FF80;">所以：</span>

```text
listen_fd
```

<span style="color:#FF0000; border:1px solid #330000; background:#00FF80;">负责继续接新客户。</span>

```text
client_fd
```

<span style="color:#FF0000; background:#00FF80;">负责和 Client A 通信。</span>

------

## 十、真正精彩的部分：`send()` 到网卡到底经历什么？

假设：

```c
char buf[] = "hello";

send(client_fd, buf, 5, 0);
```

我们一层层往下走。

------

### 第一层：用户态

```text
APP
 │
 │ send(fd, "hello", 5)
 ▼
```

<span style="color:#FF0000; background:#00FF80;">CPU 此时运行的是用户代码。</span>

<span style="color:#FF0000; background:#00FF80;">执行系统调用后：</span>

```text
User Mode
────────────
Kernel Mode
```

<span style="color:#FF0000; border:1px solid #330000; background:#00FF80;">进入内核。</span>

------

## 十一、系统调用层

大致经过：

```text
send()
 ↓
__sys_sendto()
 ↓
根据 fd 找到 socket
 ↓
sock_sendmsg()
```

其中<span style="color:#FF0000; background:#00FF80;">有一个非常重要的步骤：</span>

```text
fd
 ↓
struct file
 ↓
struct socket
```

也就是说：

> <span style="color:#FF0000; background:#00FF80;">内核先根据你传进来的 `fd=4`，找到到底是哪一个 socket。</span>

------

## 十二、进入 IPv4/TCP 层

对于 TCP：

```text
sock_sendmsg()
      ↓
socket->ops->sendmsg()
      ↓
inet_sendmsg()
      ↓
sk->sk_prot->sendmsg()
      ↓
tcp_sendmsg()
```

你<span style="color:#FF0000;">可以发现 Linux 设计得非常有意思。</span>

有<span style="color:#FF0000; background:#00FF80;">两套“函数表”：</span>

```text
struct socket
     ↓
proto_ops
```

负责：

```text
bind
connect
accept
sendmsg
recvmsg
```

<span style="color:#FF0000;">下面：</span>

```text
struct sock
     ↓
struct proto
```

<span style="color:#FF0000; background:#00FF80;">负责真正具体的：</span>

```text

tcp_recvmsg
tcp_close
...
```

所以<span style="color:#FF0000; background:#00FF80;">可以理解成：</span>

```text
用户API层
      ↓
struct socket
      ↓
协议无关接口
      ↓
struct sock
      ↓
具体TCP实现
```

## 十三、`tcp_sendmsg()` 做什么？

现在 `"hello"` 还只是：

```text
用户空间内存

"hello"
```

TCP 需要把它拿进内核。

简化来说：

```text
用户buffer
     │
     │ copy
     ▼
内核发送缓冲区
     │
     ▼
TCP组织数据
```

<span style="color:#FF0000; background:#00FF80;">最终会涉及一个极其重要的 Linux 网络结构：</span>

```text
struct sk_buff
```

<span style="color:#FF0000; background:#00FF80;">简称：</span>

```text
skb
```

<span style="color:#FF0000; background:#00FF80;">以后学 Linux 网络驱动，这个东西你会天天见。</span>

------

## 十四、`sk_buff` 是什么？

可以把它理解成：

> <span style="color:#FF0000; background:#00FF80;">**Linux 内核里装网络数据包的“包裹”。**</span>

例如最开始：

```text
hello
```

TCP 给它加信息：

```text
┌─────────────────┐
│ TCP Header      │
├─────────────────┤
│ hello           │
└─────────────────┘
```

IP 层：

```text
┌─────────────────┐
│ IP Header       │
├─────────────────┤
│ TCP Header      │
├─────────────────┤
│ hello           │
└─────────────────┘
```

再到以太网：

```text
┌─────────────────┐
│ Ethernet Header │
├─────────────────┤
│ IP Header       │
├─────────────────┤
│ TCP Header      │
├─────────────────┤
│ hello           │
└─────────────────┘
```

Linux 内核就通过 `skb` 来描述这些数据。

```text
     ↓

     ↓
IP层
     ↓
ip_queue_xmit()
     ↓
ip_local_out()
     ↓
ip_output()
```

<span style="color:#FF0000; background:#00FF80;">TCP 层负责：</span>

```text
序列号
ACK
重传
窗口
拥塞控制
```

<span style="color:#FF0000; background:#00FF80;">IP 层负责：</span>

```text
源IP
目标IP
路由
下一跳
```

## 十七、`struct net_device` 是什么？

例如：

```text

```

<span style="color:#FF0000;">背后通常都有对应的：</span>

```text

```

## 十八、真正进入网卡驱动

内核发送数据大概会来到：

```text
dev_queue_xmit()
```

然后经过：

```text
qdisc
```

也就是网络发送队列/调度层。

最后调用网卡驱动注册的：

```text
net_device_ops
        ↓
ndo_start_xmit()
```

这句话特别关键：

> **`ndo_start_xmit()` 就是协议栈真正进入具体网卡驱动的重要接口之一。**

于是：

```text
TCP/IP协议栈
       ↓
dev_queue_xmit()
       ↓
net_device
       ↓
ndo_start_xmit()
       ↓
具体网卡driver
```

## 十九、如果放到你现在学的 i.MX6ULL

i.MX6ULL 常见 Ethernet 控制器是 **FEC**。

因此在对应 Linux BSP 的 FEC 驱动里，最终会进入类似：

```text

```

这样的发送函数。

具体函数名和细节可能随 BSP/内核版本变化，但整体模型不变：

```text
ndo_start_xmit
     ↓
FEC驱动发送函数
     ↓
TX Descriptor
     ↓
DMA
     ↓
FEC Ethernet Controller
```

## 二十、DMA 出现了

这是底层特别重要的一步。

<span style="color:#FF0000; background:#00FF80;">CPU 不会自己：</span>

```text
一个字节
一个字节
一个字节
```

<span style="color:#FF0000; background:#00FF80;">搬到网卡。</span>

<span style="color:#FF0000; background:#00FF80;">通常是：</span>

```text
CPU
 ↓
告诉DMA：

“数据在这块内存里，
你自己搬到网卡发送。”
```

<span style="color:#FF0000; background:#00FF80;">于是：</span>

```text
RAM
│
│ DMA
▼
网卡 TX FIFO / Descriptor
│
▼
MAC
│
▼
PHY
│
▼
网线
```

可以画成：

```text
用户程序
   │
 send()
   ▼
内核 socket
   │
   ▼
TCP
   │
   ▼
IP
   │
   ▼
Ethernet
   │
   ▼
网卡 Driver
   │
   ▼
TX Descriptor Ring
   │
   ▼
DMA
   │
   ▼
Ethernet MAC
   │
   ▼
PHY
   │
   ▼
网线
```

到这里 `"hello"` 才真正离开你的机器。

## 二十一、对方收到数据又是完全反方向

现在客户端/服务器另一边的网卡收到以太网信号：

```text
网线
 ↓
PHY
 ↓
MAC
 ↓
DMA
 ↓
RAM中的 RX Buffer
```

<span style="color:#FF0000; background:#00FF80;">这时网卡告诉 CPU：</span>

> 有数据到了。

<span style="color:#FF0000; background:#00FF80;">传统理解上会产生中断。</span>

<span style="color:#FF0000; background:#00FF80;">现代 Linux 网络通常会结合：</span>

```text
IRQ
+
NAPI
```

------

## 二十二、为什么有 NAPI？

<span style="background:#00FF80; color:#FF0000;">如果每来一个网络包都：</span>

```text
中断
中断
中断
中断
中断
```

<span style="color:#FF0000; background:#00FF80;">高速网络下 CPU 会被中断打爆。</span>

所以<span style="color:#FF0000; background:#00FF80;"> Linux 网络驱动常使用：</span>

```text
第一次数据到达
 ↓
触发 IRQ
 ↓
调度 NAPI
 ↓
暂时批量 poll 数据包
```

于是：

```text
网卡
 ↓
IRQ
 ↓
driver IRQ handler
 ↓
NAPI poll
 ↓
收取一批 packet
```

------

## 二十三、驱动把数据交给协议栈

<span style="color:#FF0000; background:#00FF80;">驱动收到数据以后，通常会构造/处理：</span>

```text

```

然后类似：

```text

```

再往上传：

```text

       ↓
Ethernet层
       ↓
IP层
       ↓
TCP层
```

所以接收路径大体是：

```text

 ↓

 ↓

 ↓
NAPI
 ↓
skb
 ↓
Ethernet
 ↓
IP
 ↓
TCP
```

## 二十四、TCP 又怎么知道数据属于哪个 socket？

这时候数<span style="color:#FF0000; background:#00FF80;">据包里有：</span>

```text

Destination IP
Destination Port
```

例如：

```text

        ↓

```

<span style="color:#FF0000; background:#00FF80;">TCP 会根据这些信息查找对应连接。</span>

<span style="color:#FF0000; background:#00FF80;">最后找到：</span>

```text
某个 struct sock
```

<span style="color:#FF0000; background:#00FF80;">也就是：</span>

```text

        ↕
192.168.1.20:50001
```

<span style="color:#FF0000; background:#00FF80;">所对应的那个连接 socket。</span>

<span style="color:#FF0000; background:#00FF80;">然后把数据放到：</span>

```text
socket 接收队列
```

## 二十五、假设应用正在 `recv()`

服务器：

```c
recv(client_fd, buf, 100, 0);
```

<span style="color:#FF0000; background:#00FF80;">如果现在没有数据：</span>

```text
recv()
 ↓
接收队列为空
 ↓
当前进程睡眠
```

注意：

CPU 不会傻等：

```text
while(1)
    一直检查有没有数据
```

而是把这个进程挂到等待队列。

可以理解为：

```text
Process A
   ↓
recv()
   ↓
没数据
   ↓
TASK_INTERRUPTIBLE
   ↓
schedule()
   ↓
CPU去运行别的进程
```

## 二十六、数据到达后发生什么？

```text
 ↓

 ↓

 ↓

 ↓

```

<span style="color:#FF0000; background:#00FF80;">然后：</span>

```text

```

<span style="color:#FF0000; background:#00FF80;">于是：</span>

```text

      │
      │ copy
      ▼
用户空间 buf
```

```c

```

<span style="color:#FF0000; background:#00FF80;">返回：</span>

```text

```

```text
 ↓

 ↓

 ↓
```

## 三十、现在重新回答“socket 对象是什么”

你现在可以把 socket 看成三层。

### 第一层：用户眼里

```text

```

例如：

```text

```

------

### 第二层：Linux 系统调用眼里

```text
fd
 ↓
struct file
 ↓
struct socket
```

<span style="color:#FF0000; background:#00FF80;">`struct socket` 负责把：</span>

```text

```

<span style="color:#FF0000; background:#00FF80;">这些 API 接起来。</span>

------

### 第三层：网络协议栈眼里

```text
struct socket
 ↓
struct sock
 ↓

```

<span style="color:#FF0000; background:#00FF80;">它是真正记录：</span>


> <span style="color:#FF0000; background:#00FF80;">**Socket 是 Linux 内核中表示一个网络通信端点的对象。应用程序通过 fd 找到它；它内部关联具体的 TCP/UDP 协议状态；协议栈再通过网络设备和网卡驱动把数据真正发送到硬件。**</span>
