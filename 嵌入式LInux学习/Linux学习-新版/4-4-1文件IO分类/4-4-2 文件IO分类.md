# 问题1

Linux 文件 IO 里有两类函数：标准 IO 和系统调用 IO；标准 IO 通过 C 库和用户态 buffer 间接调用系统调用，系统调用 IO 则直接进入内核，因此两者的核心差异是“有没有用户态缓冲”和“进入内核的次数”。

<span style="color:#FF0000; background:#00FF80;">这里我不是太懂，你能够给我详细解释下吗，最好能够举个例子来让我彻底弄明白。</span>



你可以把这句话拆成 3 层来理解：

```text
标准 IO：fopen / fread / fwrite / fclose
系统调用 IO：open / read / write / close

标准 IO 不是不进内核，
而是：先经过 C 库自己的 buffer，必要时再调用系统调用进入内核。

系统调用 IO 是：你每调用一次 read/write，基本就直接进入一次内核。
```

------

## 1. 先用生活例子理解

假设你要从仓库里拿 100 个苹果。

### 系统调用 IO 的做法

你每次只去仓库拿 1 个苹果：

```text
去仓库一次 → 拿 1 个
去仓库一次 → 拿 1 个
去仓库一次 → 拿 1 个
……
去 100 次 → 拿 100 个
```

仓库很远，所以来回很耗时间。

对应到代码就是：

```c
read(fd, buf, 1);
read(fd, buf, 1);
read(fd, buf, 1);
...
```

<span style="color:#FF0000; background:#00FF80;">每次 `read` 都要从用户态进入内核态，相当于“去仓库一趟”</span>。

------

### 标准 IO 的做法

你第一次去仓库，不是只拿 1 个，而是直接拿一箱，比如 100 个，先放到你身边的小箱子里。

```text
去仓库一次 → 拿 100 个 → 放到身边的小箱子 buffer

之后：
从小箱子里拿 1 个
从小箱子里拿 1 个
从小箱子里拿 1 个
……
```

<span style="color:#FF0000; background:#00FF80;">这样你只需要去仓库 1 次。</span>

对应到标准 IO：

```c
fread(...)
fgetc(...)
fgets(...)
```

它们表面上可能是一点一点读，但 C 库底层可能一次性从内核多读一些，放进用户态 buffer。

## 2. 用户态和内核态是什么意思？

你可以这样理解：

```text
用户态：普通程序运行的地方，比如你写的 C 程序
内核态：操作系统核心运行的地方，比如真正管理文件、磁盘、驱动的地方
```

<span style="color:#FF0000; background:#00FF80;">你的程序不能直接碰硬盘、网卡、驱动这些资源。</span>

所以<span style="color:#FF0000;">你要读文件时，必须请求操作系统帮你读。</span>

这件事就叫：

```text
系统调用
```

比如：

```c
read(fd, buf, 100);
```

意思是：

```text
我的程序请求 Linux 内核：
请帮我从 fd 对应的文件中读取 100 字节，放到 buf 里面。
```

------

## 3. 系统调用 IO 是怎么走的？

比如你写：

```c
int fd = open("a.txt", O_RDONLY);

char buf[10];
read(fd, buf, 10);

close(fd);
```

它的大致路径是：

```text
你的程序
  ↓
open/read/close
  ↓
进入 Linux 内核
  ↓
内核找到文件系统
  ↓
文件系统从磁盘/缓存中拿数据
  ↓
把数据复制到你的 buf
  ↓
回到你的程序
```

重点是：

```text
每调用一次 read/write，通常都要进入一次内核。
```

所以如果你这样写：

```c
for (int i = 0; i < 100; i++) {
    read(fd, buf, 1);
}
```

大概就是：

```text
进入内核 100 次，每次读 1 字节。
```

这就像：

```text
跑仓库 100 次，每次拿 1 个苹果。
```

------

## 4. 标准 IO 是怎么走的？

比如你写：

```c
FILE *fp = fopen("a.txt", "r");

char ch;
for (int i = 0; i < 100; i++) {
    ch = fgetc(fp);
}

fclose(fp);
```

表面上你调用了 100 次 `fgetc`，好像也是读了 100 次。

但重点来了：

```text
fgetc 不一定每次都真正进入内核。
```

标准 IO 的大致路径是：

```text
你的程序
  ↓
fgetc / fread / fgets
  ↓
C库的 FILE 结构体
  ↓
C库用户态 buffer
  ↓
buffer 不够时，才调用 read 进入内核
  ↓
内核读取一大块数据
  ↓
先放到 C库 buffer
  ↓
你的程序每次从 buffer 里拿一点
```

所以可能发生的是：

```text
第一次 fgetc：
C库发现 buffer 是空的
于是调用 read，一次读 4096 字节
放进 C库 buffer
然后返回第 1 个字符

第二次 fgetc：
不进内核，直接从 buffer 拿第 2 个字符

第三次 fgetc：
不进内核，直接从 buffer 拿第 3 个字符

……

直到 buffer 用完，才再次调用 read 进入内核。
```

------

## 5. 所以“有没有用户态缓冲”到底是什么意思？

这里要特别注意一个容易混的点：

### 系统调用 IO 也有你自己定义的 `buf`

例如：

```c
char buf[100];
read(fd, buf, 100);
```

这里的 `buf` 是你自己传给 `read` 的接收数组。

但是它不是 C 库帮你管理的长期缓冲区。

------

### 标准 IO 里的 buffer 是 C 库内部维护的

比如：

```c
FILE *fp = fopen("a.txt", "r");
```

这个 `fp` 不是普通的文件描述符，它是一个 `FILE *`。

`FILE` 里面通常会维护一些信息：

```text
文件描述符 fd
当前读到哪里
buffer 的起始位置
buffer 里面还有多少数据
错误标志
文件结束标志 EOF
```

所以标准 IO 的 buffer 是：

```text
C库帮你维护的用户态缓冲区
```

不是你手动传进去的那个 `char buf[100]`。

------

## 6. 用一张对比图记住

### 系统调用 IO

```text
你的程序
  ↓
read(fd, buf, 1)
  ↓
进入内核
  ↓
读文件
  ↓
返回用户程序
```

如果循环 100 次：

```text
read 100 次 = 进入内核 100 次
```

------

### 标准 IO

```text
你的程序
  ↓
fgetc(fp)
  ↓
C库 buffer 有数据？
  ↓
有：直接从 buffer 拿，不进内核
  ↓
没有：C库调用 read，一次读一大块进 buffer
```

如果循环 100 次：

```text
fgetc 100 次 ≠ 进入内核 100 次
可能只进入内核 1 次
```

------

## 7. 举一个具体例子

假设 `a.txt` 里面有 100 个字符：

```text
abcdefghijklmnopqrstuvwxyz...
```

你想一个字符一个字符读取。

------

### 写法一：系统调用 IO

```c
#include <unistd.h>
#include <fcntl.h>
#include <stdio.h>

int main() {
    int fd = open("a.txt", O_RDONLY);

    char ch;
    for (int i = 0; i < 100; i++) {
        read(fd, &ch, 1);
        printf("%c", ch);
    }

    close(fd);
    return 0;
}
```

这段代码的特点：

```text
每次 read 只读 1 字节。
循环 100 次，就调用 read 100 次。
调用 read 100 次，就可能进入内核 100 次。
```

缺点：

```text
太频繁进入内核，效率低。
```

------

### 写法二：标准 IO

```c
#include <stdio.h>

int main() {
    FILE *fp = fopen("a.txt", "r");

    char ch;
    for (int i = 0; i < 100; i++) {
        ch = fgetc(fp);
        printf("%c", ch);
    }

    fclose(fp);
    return 0;
}
```

这段代码表面上也是读 100 次。

但是底层可能是：

```text
第 1 次 fgetc：
C库调用 read，一次读 4096 字节到 FILE 的内部 buffer。

第 2 次到第 100 次 fgetc：
直接从 C库 buffer 里取，不再进入内核。
```

所以它可能只进入内核 1 次。

------

## 8. 再举一个写文件的例子

## 系统调用 IO 写法

```c
int fd = open("a.txt", O_WRONLY | O_CREAT, 0666);

for (int i = 0; i < 100; i++) {
    write(fd, "A", 1);
}

close(fd);
```

意思是：

```text
写 1 个 A
写 1 个 A
写 1 个 A
……
写 100 次
```

可能进入内核 100 次。

------

### 标准 IO 写法

```c
FILE *fp = fopen("a.txt", "w");

for (int i = 0; i < 100; i++) {
    fputc('A', fp);
}

fclose(fp);
```

表面上 `fputc` 也是调用 100 次。

但是 C 库可能先把这些字符放到用户态 buffer 里：

```text
A A A A A A A ...
```

等 buffer 满了，或者你调用：

```c
fflush(fp);
```

或者：

```c
fclose(fp);
```

它才真正调用 `write` 把一大块数据写给内核。

所以标准 IO 写文件时，可能是：

```text
fputc 100 次
但 write 只调用 1 次
```

------

## 9. 为什么进入内核次数越少越好？

因为从用户态切换到内核态不是普通函数调用。

普通函数调用：

```text
main → test → return
```

成本比较低。

系统调用：

```text
用户程序 → CPU 切换状态 → 进入内核 → 检查参数 → 操作文件系统 → 返回用户态
```

成本更高。

所以：

```text
一次读 1000 字节
通常比
读 1000 次，每次 1 字节
效率高很多。
```

------

## 10. 标准 IO 和系统调用 IO 的核心区别

| 对比点                   | 标准 IO                     | 系统调用 IO                        |
| ------------------------ | --------------------------- | ---------------------------------- |
| 常见函数                 | `fopen/fread/fwrite/fclose` | `open/read/write/close`            |
| 操作对象                 | `FILE *fp`                  | `int fd`                           |
| 是否经过 C 库            | 经过                        | 基本直接进入内核                   |
| 是否有 C 库用户态 buffer | 有                          | 没有自动的 C 库 buffer             |
| 进入内核次数             | 可能较少                    | 你调用几次，通常就进入几次         |
| 使用难度                 | 更方便                      | 更底层                             |
| 适合场景                 | 普通文件读写、文本处理      | 设备文件、驱动、底层控制、精确控制 |

------

## 11. 但是要注意：标准 IO 最后也会调用系统调用

很多人容易误解成：

```text
标准 IO 不用系统调用
```

这是错的。

正确理解是：

```text
标准 IO 最终也要靠 open/read/write 这类系统调用完成真正的文件读写。
```

只是它中间多了一层：

```text
C库 + 用户态 buffer
```

所以路径是：

```text
标准 IO：
fopen/fread/fwrite
  ↓
C库 buffer
  ↓
open/read/write
  ↓
内核
  ↓
文件系统/驱动
```

而系统调用 IO 是：

```text
open/read/write
  ↓
内核
  ↓
文件系统/驱动
```

------

## 12. 最容易混淆的 3 个点

## 第一个：`fopen` 和 `open` 有什么区别？

```c
FILE *fp = fopen("a.txt", "r");
```

返回的是：

```text
FILE *
```

这是<span style="color:#FF0000; background:#00FF80;"> C 库封装出来的对象，里面有 buffer。</span>

------

```c
int fd = open("a.txt", O_RDONLY);
```

返回的是：

```text
int fd
```

这是<span style="color:#FF0000; background:#00FF80;">文件描述符，是内核用来标识打开文件的编号。</span>

记法：

```text
fopen：f 开头，属于标准 IO，返回 FILE *
open：没有 f，属于系统调用 IO，返回 fd
```

------

### 第二个：`fread` 和 `read` 有什么区别？

```c
fread(buf, 1, 100, fp);
```

标准 IO，走 C 库，可能从 C 库 buffer 里拿。

------

```c
read(fd, buf, 100);
```

系统调用 IO，直接请求内核读。

记法：

```text
fread：从 FILE * 里读
read：从 fd 里读
```

------

### 第三个：`fflush` 是干什么的？

标准 IO 写文件时，数据可能先放在 C 库 buffer 里，不一定马上写进内核。

比如：

```c
fprintf(fp, "hello");
```

这句话执行后，`hello` 可能还在用户态 buffer 里。

调用：

```c
fflush(fp);
```

意思是：

```text
别等了，现在立刻把 C库 buffer 里的数据写出去。
```

所以：

```text
fflush = 刷新 C库缓冲区
```

------

## 13. 最终记忆版

你就这样记：

```text
系统调用 IO：
我每次都亲自去找内核办事。
open/read/write/close
对象是 fd。

标准 IO：
我先找 C库，C库帮我攒一攒、缓一缓，
需要的时候再去找内核。
fopen/fread/fwrite/fclose
对象是 FILE *。
```

最短一句话：

```text
系统调用 IO 是“直接找内核”；
标准 IO 是“先找 C库 buffer，必要时再找内核”。
```
