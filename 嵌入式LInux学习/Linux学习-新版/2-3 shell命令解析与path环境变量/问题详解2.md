# 1.shell去哪里找应用程序

<span style="color:#FF0000; background:#00FF80;">这里用户在终端中输入了一串命令之后，shell会去哪里去找应用程序呢，我不是太懂，你能够给我详细解释下吗？</span>

可以。你可以先记住一句话：

```text
用户输入命令后，shell 不会“到处乱找”，而是按照一定规则去找。
如果命令里写了路径，就按路径找；
如果命令里没写路径，就去 PATH 环境变量指定的目录里找。
```

------

## 1. 用户输入命令后，shell 大概做什么？

比如你输入：

```bash
ls -l /home/book
```

shell 会先把它拆开：

```text
ls          命令名
-l          选项
/home/book  参数
```

然后 shell 会问自己：

```text
我要执行的程序是 ls，那么 ls 在哪里？
```

<span style="color:#FF0000; background:#00FF80;">找到 `ls` 这个程序后，shell 才会把 `-l /home/book` 这些内容交给 `ls` 程序去处理。</span>

------

## 2. 如果命令本身带路径，shell 就按路径找

### 情况一：绝对路径

比如：

```bash
/bin/ls
```

这里 `/bin/ls` 是一个完整路径。

shell 不需要去 `PATH` 里面搜索，它直接去：

```bash
/bin/ls
```

这个位置找程序。

如果这个文件存在，并且有执行权限，就运行它。

------

### 情况二：相对路径

比如：

```bash
./hello
```

这里的 `./` 表示当前目录。

所以：

```bash
./hello
```

意思是：

```text
执行当前目录下的 hello 程序
```

假设你当前在：

```bash
/home/book/Desktop
```

那么：

```bash
./hello
```

实际相当于：

```bash
/home/book/Desktop/hello
```

所以只要当前目录下真的有 `hello`，并且它有执行权限，就可以运行。

------

再比如：

```bash
../hello
```

这里 `../` 表示上一级目录。

如果你当前在：

```bash
/home/book/Desktop/test
```

那么：

```bash
../hello
```

表示执行：

```bash
/home/book/Desktop/hello
```

------

## 3. 如果命令没有路径，shell 就去 PATH 里找

比如你输入：

```bash
ls
```

这里没有 `/`，也没有 `./`，只是单独一个命令名 `ls`。

这时 shell 会去 `PATH` 环境变量里面找。

可以用这个命令查看 `PATH`：

```bash
echo $PATH
```

可能看到类似：

```bash
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

<span style="color:#FF0000; background:#00FF80;">这里面有很多目录，用冒号 `:` 分隔。</span>

<span style="color:#FF0000; background:#00FF80;">shell 会按照顺序查找：</span>

```text
1. /usr/local/sbin
2. /usr/local/bin
3. /usr/sbin
4. /usr/bin
5. /sbin
6. /bin
```

也就是说，当你输入：

```bash
ls
```

shell 会依次尝试找：

```bash
/usr/local/sbin/ls
/usr/local/bin/ls
/usr/sbin/ls
/usr/bin/ls
/sbin/ls
/bin/ls
```

<span style="color:#FF0000; background:#00FF80;">找到第一个能执行的 `ls`，就运行它。</span>

------

## 4. 为什么当前目录下有 hello，却不能直接输入 hello？

假设你当前目录下有一个程序：

```bash
hello
```

你输入：

```bash
hello
```

结果 shell 可能提示：

```bash
hello: command not found
```

原因是：

```text
shell 默认不会在当前目录找程序。
```

它只会去 `PATH` 里面列出的目录找。

如果你的 `PATH` 里面没有当前目录 `.`，shell 就不会自动找当前目录下的 `hello`。

所以你必须写：

```bash
./hello
```

明确告诉 shell：

```text
我要执行当前目录下的 hello。
```

------

## 5. 为什么 Linux 不默认搜索当前目录？

这是为了安全。

假设当前目录下有人放了一个假的 `ls` 程序，内容是恶意的。

如果 Linux 默认优先搜索当前目录，那么你输入：

```bash
ls
```

可能运行的不是系统真正的 `/bin/ls`，而是当前目录下那个假的 `ls`。

这很危险。

所以 Linux 一般要求你明确写：

```bash
./hello
```

意思是：

```text
我知道我要运行当前目录下这个程序。
```

------

## 6. PATH 可以理解成什么？

你可以把 `PATH` 理解成：

```text
shell 查找命令时的“搜索目录列表”。
```

比如：

```bash
echo $PATH
```

输出：

```bash
/usr/local/bin:/usr/bin:/bin
```

就表示 shell 找命令时，会按顺序去这三个目录找：

```text
先找 /usr/local/bin
再找 /usr/bin
最后找 /bin
```

比如输入：

```bash
gcc
```

shell 可能会找：

```bash
/usr/local/bin/gcc
/usr/bin/gcc
/bin/gcc
```

如果在 `/usr/bin/gcc` 找到了，就运行：

```bash
/usr/bin/gcc
```

------

## 7. 可以用 which 查看命令在哪里

比如：

```bash
which ls
```

可能输出：

```bash
/bin/ls
```

说明你输入 `ls` 时，实际执行的是：

```bash
/bin/ls
```

再比如：

```bash
which gcc
```

可能输出：

```bash
/usr/bin/gcc
```

说明你输入 `gcc` 时，实际执行的是：

```bash
/usr/bin/gcc
```

如果输入：

```bash
which hello
```

没有输出，或者提示找不到，就说明：

```text
hello 不在 PATH 能找到的目录里。
```

------

## 8. shell 查找命令不只是 PATH

更完整一点说，当你输入：

```bash
ls
```

shell 通常会按这样的顺序判断：

```text
1. 是不是别名 alias
2. 是不是 shell 函数
3. 是不是 shell 内置命令
4. 是不是 PATH 里面的外部程序
```

不过初学时先重点理解第 4 点就够了。

------

### 例子：cd 为什么找不到文件路径？

比如：

```bash
cd Desktop
```

`cd` 通常不是外部程序，而是 shell 内置命令。

<span style="color:#FF0000; background:#00FF80;">因为 `cd` 要改变当前 shell 的工作目录，如果它是外部程序，就无法真正改变当前终端所在目录。</span>

所以像这些命令经常是 shell 内置的：

```bash
cd
echo
pwd
export
history
```

而这些通常是外部程序：

```bash
ls
cp
rm
mkdir
gcc
vim
python
```

可以用这个命令查看类型：

```bash
type cd
type ls
type gcc
```

可能输出：

```bash
cd is a shell builtin
ls is /bin/ls
gcc is /usr/bin/gcc
```

------

## 9. 用一个例子完整走一遍

假设你输入：

```bash
gcc -o hello hello.c
```

shell 会这样处理：

第一步，拆分命令：

```text
gcc
-o
hello
hello.c
```

第二步，判断 `gcc` 是什么：

```text
gcc 没有带路径，所以去 PATH 中查找
```

第三步，在 PATH 中依次找：

```bash
/usr/local/sbin/gcc
/usr/local/bin/gcc
/usr/sbin/gcc
/usr/bin/gcc
/sbin/gcc
/bin/gcc
```

第四步，假设找到：

```bash
/usr/bin/gcc
```

第五步，运行它，并把后面的内容传给它：

```text
-o hello hello.c
```

于是 `gcc` 程序自己解释：

```text
-o hello    输出文件名叫 hello
hello.c     要编译的源文件
```

最终生成：

```bash
hello
```

------

## 10. 再用 hello 程序举例

假设你当前目录是：

```bash
/home/book/Desktop
```

当前目录下有：

```bash
hello
```

你输入：

```bash
hello
```

shell 会去 `PATH` 里面找：

```bash
/usr/local/bin/hello
/usr/bin/hello
/bin/hello
```

但它不会自动找：

```bash
/home/book/Desktop/hello
```

所以找不到。

你输入：

```bash
./hello
```

shell 看到里面有 `/`，就不会去 PATH 搜索，而是直接找：

```bash
/home/book/Desktop/hello
```

这时就可以运行。

------

## 11. 如果我想直接输入 hello 就能运行怎么办？

有两种常见方法。

### 方法一：把程序放到 PATH 已有目录里

比如放到：

```bash
/usr/local/bin
```

之后你就可以直接输入：

```bash
hello
```

不过这种目录通常需要管理员权限。

------

### 方法二：把程序所在目录加入 PATH

比如你的程序在：

```bash
/home/book/Desktop
```

可以临时执行：

```bash
export PATH=$PATH:/home/book/Desktop
```

然后再输入：

```bash
hello
```

shell 就能找到了。

不过这种方式只对当前终端有效。

如果想永久生效，一般把这句话写到：

```bash
~/.bashrc
```

里面。

------

## 12. 最重要的总结

你可以这样记：

```text
如果命令里面带 /，shell 就按你写的路径找。
如果命令里面不带 /，shell 就去 PATH 里面找。
```

例如：

```bash
/bin/ls
```

按绝对路径找。

```bash
./hello
```

按当前目录找。

```bash
ls
```

去 `PATH` 里找。

```bash
hello
```

也去 `PATH` 里找，不会默认找当前目录。

所以：

```bash
hello
```

找不到时，不代表当前目录没有 `hello`，而是说明：

```text
hello 所在目录不在 PATH 中。
```

正确运行当前目录程序，一般写：

```bash
./hello
```



# 2.命令行输入的给应用程序传递的参数个数

<span style="color:#FF0000; background:#00FF80;">我有个问题，就是我输入 ./hello weidongshan的话，此时传递给hello应用程序的两个参数应该一个是./hello，一个是weidongshan吧。另外如果我输入的是 ls -l，此时传递给ls应用程序的也是两个参数，一个是ls，一个是-l吗，还有如果我输入的是gcc -o hello hello.c，此时我传递给gcc应用程序的是4个参数吗，分别是gcc，-o，hello，hello.c对吗。我的理解对吗？</span>

你的理解**基本完全正确**，只需要补充一个关键点：

```text
从 C 程序 argc/argv 的角度看：
argv[0] 也是一个参数，通常是程序名或执行时写的命令名。

但从日常说法看：
“参数”有时候只指命令名后面的内容，不包括 argv[0]。
```

所以你现在的问题，其实要分成两种理解方式。

------

## 1. `./hello weidongshan` 传给 hello 的是什么？

你输入：

```bash
./hello weidongshan
```

shell 会把它拆成：

```text
./hello
weidongshan
```

然后执行当前目录下的 `hello` 程序。

如果 `hello.c` 里面是：

```c
int main(int argc, char *argv[])
```

那么程序收到的是：

```text
argc = 2

argv[0] = "./hello"
argv[1] = "weidongshan"
```

所以你说得对：

```text
传递给 hello 应用程序的两个参数：
一个是 ./hello
一个是 weidongshan
```

不过更准确地说：

```text
argv[0] 是程序名/启动方式
argv[1] 才是你真正想让程序处理的普通参数
```

------

## 2. `ls -l` 传给 ls 的是什么？

你输入：

```bash
ls -l
```

shell 会拆成：

```text
ls
-l
```

然后 shell 去 `PATH` 里面找到真正的 `ls` 程序，比如：

```bash
/bin/ls
```

但是传给 `ls` 程序时，通常是：

```text
argc = 2

argv[0] = "ls"
argv[1] = "-l"
```

所以你的理解也是对的：

```text
传递给 ls 应用程序的是两个内容：
ls
-l
```

这里要注意一个细节：

虽然真正运行的程序文件可能是：

```bash
/bin/ls
```

<span style="color:#FF0000; background:#00FF80;">但是 `argv[0]` 通常仍然是你输入的命令名：</span>

```text
argv[0] = "ls"
```

<span style="color:#FF0000; background:#00FF80;">而不是一定等于：</span>

```text
argv[0] = "/bin/ls"
```

<span style="color:#FF0000; background:#00FF80;">如果你直接输入：</span>

```bash
/bin/ls -l
```

<span style="color:#FF0000; background:#00FF80;">那么可能就是：</span>

```text
argc = 2

argv[0] = "/bin/ls"
argv[1] = "-l"
```

所以 `argv[0]` 跟你怎么启动它有关。

------

## 3. `gcc -o hello hello.c` 传给 gcc 的是什么？

你输入：

```bash
gcc -o hello hello.c
```

shell 会拆成四个部分：

```text
gcc
-o
hello
hello.c
```

所以从 `argc/argv` 的角度看，传给 `gcc` 的确是四个参数：

```text
argc = 4

argv[0] = "gcc"
argv[1] = "-o"
argv[2] = "hello"
argv[3] = "hello.c"
```

你的理解是对的。

但是从 `gcc` 自己的语义角度看，它会进一步解释：

```text
-o hello    表示输出文件名叫 hello
hello.c     表示要编译的源文件
```

也就是说，<span style="color:#FF0000; background:#00FF80;">shell 只是把字符串拆开并传过去，真正理解 `-o` 是什么意思的是 `gcc` 程序自己。</span>

------

## 4. 最容易混的点：shell 不负责理解选项含义

比如：

```bash
gcc -o hello hello.c
```

shell 只负责把它拆成：

```text
gcc
-o
hello
hello.c
```

然后传给 `gcc`。

至于：

```text
-o 后面要跟一个输出文件名
hello 是 -o 的值
hello.c 是源文件
```

<span style="color:#FF0000; background:#00FF80;">这些不是 shell 判断的，而是 `gcc` 自己判断的。</span>

再比如：

```bash
grep -n hello a.txt
```

传给 `grep` 的是：

```text
argc = 4

argv[0] = "grep"
argv[1] = "-n"
argv[2] = "hello"
argv[3] = "a.txt"
```

但是 <span style="color:#FF0000; background:#00FF80;">`grep` 自己解释成：</span>

```text
-n       显示行号
hello    要查找的内容
a.txt    要查找的文件
```

------

## 5. 用一句话总结你的理解

你的理解可以整理成这样：

```text
shell 会把命令按照规则拆成多个字符串，然后把这些字符串作为 argv[] 传给程序。
argv[0] 通常是程序名或启动方式。
argv[1]、argv[2]、argv[3]……才是命令后面真正写的选项、选项值、普通参数。
```

所以：

```bash
./hello weidongshan
```

对应：

```text
argc = 2
argv[0] = "./hello"
argv[1] = "weidongshan"
ls -l
```

对应：

```text
argc = 2
argv[0] = "ls"
argv[1] = "-l"
gcc -o hello hello.c
```

对应：

```text
argc = 4
argv[0] = "gcc"
argv[1] = "-o"
argv[2] = "hello"
argv[3] = "hello.c"
```

你现在这个理解已经很接近 shell 命令执行的本质了。<span style="background:#00FF80;">重点记住：**shell 负责拆分和启动程序，程序自己负责解释这些参数的含义。**</span>



# 3.为什么直接在终端执行设置的只对当前终端有效

直接在当前终端执行：

```bash
export PATH=$PATH:/home/book
```

这种方式只对当前终端有效。关闭终端后，设置就失效了。

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF33FF;">上面这里为什么只对当前终端有效呢，我不是太懂，你能够给我详细解释下吗。</span>

这里的关键是：**`export PATH=...` 改的是“<span style="background:#00FF80;">当前 shell 进程里的环境变量</span>”，<span style="background:#00FF80;">不是永久写入系统配置文件。</span>**

所以<span style="background:#00FF80;">它只对当前终端有效。</span>

------

## 1. 先理解：每打开一个终端，就会启动一个 shell

你打开一个终端窗口，系统通常会启动一个 shell，比如 `bash`：

```text
终端窗口
  └── bash shell
```

这个 `bash` 里面有自己的环境变量，比如：

```bash
PATH
HOME
USER
PWD
SHELL
```

你<span style="background:#00FF80;">执行：</span>

```bash
echo $PATH
```

看到的就是<span style="background:#00FF80;">**当前这个 shell 里面保存的 PATH 值**。</span>

------

## 2. `export PATH=$PATH:/home/book` 做了什么？

这条命令：

```bash
export PATH=$PATH:/home/book
```

可以拆成两步理解。

第一步：

```bash
PATH=$PATH:/home/book
```

意思是：

```text
把原来的 PATH 拿出来，在后面追加 /home/book
```

假设原来是：

```bash
/usr/local/bin:/usr/bin:/bin
```

执行后变成：

```bash
/usr/local/bin:/usr/bin:/bin:/home/book
```

第二步：

```bash
export
```

表示：

```text
把这个变量导出给当前 shell 后面启动的子程序使用。
```

比如你执行：

```bash
hello
```

或者：

```bash
gcc
```

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF33FF;">这些程序都是当前 shell 启动出来的子进程，它们可以继承当前 shell 的环境变量。</span>

------

## 3. 为什么只对当前终端有效？

因为<span style="background:#00FF80;">你只是修改了**当前 shell 进程内存里的 PATH**。</span>

可以这样想：

```text
当前终端 A
  └── bash A
        PATH = 原来的 PATH + /home/book
```

这个修改只存在于 `bash A` 这个进程里。

如果你再打开一个新终端，会启动另一个新的 shell：

```text
当前终端 A
  └── bash A
        PATH = 原来的 PATH + /home/book

新终端 B
  └── bash B
        PATH = 原来的 PATH
```

新终端 B 是另一个 shell 进程，它不会自动知道你刚才在终端 A 里临时改过 PATH。

所以在终端 A 中：

```bash
hello
```

可能能运行。

但在终端 B 中：

```bash
hello
```

可能还是提示：

```bash
command not found
```

因为终端 B 的 `PATH` 里面没有 `/home/book`。

------

## 4. 为什么关闭终端后设置会失效？

因为关闭终端时，对应的 shell 进程也结束了。

也就是：

```text
终端窗口关闭
  └── bash 进程结束
        └── 它内存里的 PATH 也消失
```

你之前执行的：

```bash
export PATH=$PATH:/home/book
```

<span style="color:#FF0000; background:#00FF80;">只是存在这个 shell 的内存里。</span>

它没有写入：

```bash
~/.bashrc
```

也没有写入：

```bash
/etc/environment
```

所以 shell 结束后，这个修改自然就没了。

------

## 5. 用一个生活例子理解

你可以把 `PATH` 理解成 shell 手里的一张“找命令的地图”。

你在当前终端执行：

```bash
export PATH=$PATH:/home/book
```

相当于你只是在**当前这张地图**上临时加了一条路：

```text
以后找命令时，也去 /home/book 找一找。
```

但是你没有把这条路写进正式地图册。

所以：

```text
当前终端还开着：这张临时地图还在，可以用
当前终端关闭了：这张临时地图被丢掉
新开终端：重新拿一张默认地图，没有你刚才手写的那条路
```

------

## 6. `export` 不是“永久保存”的意思

很多初学者会误会：

```bash
export
```

是不是“导出保存”的意思？

不是。

在 Linux shell 里，`export` 的意思更接近：

```text
让当前 shell 的子进程也能看到这个变量。
```

比如你执行：

```bash
export PATH=$PATH:/home/book
```

之后，在当前终端中运行的程序都可以继承这个新的 `PATH`。

但是它不会自动永久保存到系统配置文件。

所以：

```text
export：让子进程继承
不是：永久保存
```

------

## 7. 什么是父进程和子进程？

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF33FF;">打开终端后，shell 是一个进程。</span>

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF33FF;">当你在 shell 中执行命令</span>，比如：

```bash
ls
```

<span style="color:#FF0000; background:#00FF80;">shell 会启动一个新的程序进程：</span>

```text
bash
  └── ls
```

这里：

```text
bash 是父进程
ls 是子进程
```

环境变量通常是：

```text
父进程可以传给子进程
子进程不能反过来修改父进程
兄弟进程之间也不会互相影响
```

这就是为什么：

```bash
export PATH=$PATH:/home/book
```

会影响当前 shell 后续启动的程序，但不会影响别的终端。

------

## 8. 为什么写入 `~/.bashrc` 就可以长期生效？

因为<span style="background:#00FF80;">每次打开新的 bash 终端时，系统会读取：</span>

```bash
~/.bashrc
```

里面的命令。

如果你把下面这句写进去：

```bash
export PATH=$PATH:/home/book
```

那么每次新开终端，bash 都会自动执行它。

过程是：

```text
打开新终端
  └── 启动 bash
        └── 读取 ~/.bashrc
              └── 执行 export PATH=$PATH:/home/book
                    └── 新终端的 PATH 也包含 /home/book
```

所以它看起来就像“永久生效”了。

------

## 9. 临时设置和永久设置的区别

## 临时设置

```bash
export PATH=$PATH:/home/book
```

特点：

```text
只影响当前终端
关闭终端后失效
新终端不一定有这个设置
适合临时测试
```

------

### 用户级永久设置

把这句加入：

```bash
~/.bashrc
```

例如：

```bash
export PATH=$PATH:/home/book
```

特点：

```text
只影响当前用户
每次打开新终端都会生效
适合普通用户自己配置
```

修改后可以执行：

```bash
source ~/.bashrc
```

让当前终端立即重新读取配置。

------

### 系统级永久设置

修改：

```bash
/etc/environment
```

特点：

```text
影响范围更大
可能影响所有用户
通常需要管理员权限
不建议初学者随便改
```

------

## 10. 再用一个完整例子说明

假设你现在有一个程序：

```bash
/home/book/hello
```

当前 PATH 是：

```bash
/usr/bin:/bin
```

这时候你输入：

```bash
hello
```

shell 只会去这些地方找：

```bash
/usr/bin/hello
/bin/hello
```

所以找不到。

然后你执行：

```bash
export PATH=$PATH:/home/book
```

当前终端里的 PATH 变成：

```bash
/usr/bin:/bin:/home/book
```

这时候你再输入：

```bash
hello
```

shell 会找：

```bash
/usr/bin/hello
/bin/hello
/home/book/hello
```

于是就能找到并运行。

但是你关闭终端后，这个 shell 消失。

再次打开终端时，PATH 可能又回到：

```bash
/usr/bin:/bin
```

所以 `hello` 又找不到了。

------

## 11. 最后总结

你可以这样记：

```text
export PATH=$PATH:/home/book
```

这句话的作用是：

```text
临时修改当前 shell 的 PATH，并让当前 shell 后续启动的程序继承这个 PATH。
```

它只对当前终端有效，是因为：

```text
每个终端都有自己的 shell 进程；
你修改的是当前 shell 进程里的 PATH；
关闭终端后，这个 shell 进程结束，临时修改也就消失了；
新终端会重新读取配置文件，而不是继承旧终端的临时修改。
```

最重要的一句：

```text
想临时测试，用 export；
想长期生效，写进 ~/.bashrc。
```



# 4.shell进程与bash进程的关系

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF33FF;">打开终端后，shell 是一个进程。</span>

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF33FF;">当你在 shell 中执行命令</span>，比如：

```bash
ls
```

<span style="color:#FF0000; background:#00FF80;">shell 会启动一个新的程序进程：</span>

```text
bash
  └── ls
```

这里：

```text
bash 是父进程
ls 是子进程
```
<span style="color:#FF0000; background:#00FF80;">这里好像提到了shell进程，又提到了bash进程，这两者之间是什么关系呢，你能够给我详细解散解释下吗，我不是太懂</span>

你这个问题问得非常关键。这里的关系可以一句话概括：

```text
shell 是一类程序的统称；
bash 是 shell 的一种具体实现。
```

所以：

```text
shell 进程 ≈ bash 进程
```

在你的视频例子里，<span style="color:#FF0000;">说“shell 进程”和说“bash 进程”，大多数情况下指的是同一个东西。</span>

------

## 1. shell 和 bash 的关系

### shell 是“总称”

`shell` 不是某一个固定程序的名字，而是<span style="color:#FF0000; background:#00FF80;">一类程序的名字。</span>

它的作用是：

```text
接收用户输入的命令
解析命令
查找程序
启动程序
把结果显示给用户
```

所以 shell 可以理解成：

```text
命令解释器
```

------

### bash 是一种具体的 shell

`bash` 是 shell 的一种。

完整名字是：

```text
Bourne Again Shell
```

Linux 中常见的 shell 有很多种：

```text
sh       一种比较基础的 shell
bash     Linux 中非常常见的 shell
zsh      macOS 和很多开发者常用的 shell
fish     交互体验比较友好的 shell
dash     Ubuntu 中常见的轻量 shell
```

所以它们之间的关系类似于：

```text
水果：苹果、香蕉、橘子
shell：bash、zsh、fish、sh
```

也就是说：

```text
bash 是 shell，但 shell 不一定是 bash。
```

------

## 2. 为什么有时候说 shell 进程，有时候说 bash 进程？

因为在很多 Linux 系统中，你打开终端后，默认启动的 shell 就是 `bash`。

所以打开终端后，实际进程结构可能是：

```text
gnome-terminal
  └── bash
```

<span style="background:#00FF80; color:#FF0000;">这里的 `bash` 就是当前终端里的 shell。</span>

所以当我说：

```text
打开终端后，shell 是一个进程
```

在你的环境里，很可能具体就是：

```text
打开终端后，bash 是一个进程
```

因此：

```text
shell 进程：强调它的功能身份，它是命令解释器
bash 进程：强调它的具体程序名字，它叫 bash
```

这两个说法看的是同一个东西的不同角度。

------

假设有一句话：

```text

```

如果你用的是 Chrome，那么也可以说：

```text
打开浏览器后，Chrome 是一个进程。
```

这里：

```text
浏览器 = 一类软件
Chrome = 具体的浏览器软件
```

```text
shell = 一类命令解释器
bash = 具体的 shell 程序
```

如果你的默认 shell 是 bash，就等价于：

## 4. 终端、shell、bash 之间又是什么关系？

这个也很容易混。

可以这样分：


```text

  └── bash
```

终端窗口负责：


bash 负责：

所以你在终端中输入：

不是终端窗口自己去理解 `ls`，而是终端里的 `bash` 去理解和执行。

## 5. 执行 `ls` 时，进程关系是什么？

假设你打开终端后，里面运行的是 bash。

此时进程结构是：

```text
终端程序
  └── bash
```

然后你输入：

```bash

```

bash 会启动一个新的 `ls` 进程：

```text
终端程序
  └── bash
        └── ls
```

这里：

```text

```

也可以说：

```text

ls 是子进程
```

等 `ls` 执行完之后，`ls` 进程结束，控制权回到 bash：

```text
终端程序
  └── bash
```

所以你又能继续输入下一条命令。

在你的例子里，基本可以认为是一样的。

所以不要把 shell 理解成某个固定程序名。

# 5. export PATH=\$ PATH : /home/book 符号含义

export PATH=\$ PATH : /home/book，<span style="background:#00FF80; color:#FF0000;">这里的这个命令要怎么理解呢，这里的 “ $ ” 符号以及 “:” 符号代表的含义是什么呢</span>

这条命令：

```bash
export PATH=$PATH:/home/book
```

可以分成 4 个部分理解：

```text
export   PATH   =   $PATH:/home/book
导出     变量名  赋值  原来的PATH + 新增目录
```

它的意思是：

```text
在原来的 PATH 后面，再追加一个 /home/book 目录，
并把修改后的 PATH 导出给当前 shell 后面启动的程序使用。
```

------

## 1. `PATH` 是什么？

`PATH` 是一个环境变量，里面保存着 shell 查找命令时要去搜索的目录。

比如你输入：

```bash
echo $PATH
```

可能看到：

```bash
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

这表示 shell 找命令时，会依次去这些目录找：

```text
/usr/local/sbin
/usr/local/bin
/usr/sbin
/usr/bin
/sbin
/bin
```

例如你输入：

```bash
ls
```

shell 会在这些目录里找 `ls` 程序，可能最终找到：

```bash
/bin/ls
```

------

## 2. `$PATH` 里的 `$` 是什么意思？

<span style="background:#00FF80;">这里的 `$` 表示：</span>

```text
取出变量的值
```

所以：

```bash
PATH
```

只是变量名。

而：

```bash
$PATH
```

表示<span style="color:#FF0000; background:#00FF80;">取出 `PATH` 变量里面保存的内容。</span>

举个例子，假设当前 `PATH` 是：

```bash
/usr/bin:/bin
```

那么：

```bash
$PATH
```

就会被 shell 替换成：

```bash
/usr/bin:/bin
```

所以这条命令：

```bash
export PATH=$PATH:/home/book
```

会<span style="color:#FF0000;">先变成类似：</span>

```bash
export PATH=/usr/bin:/bin:/home/book
```

也就是说：

```text
新的 PATH = 原来的 PATH + :/home/book
```

------

## 3. `:` 符号是什么意思？

在 `PATH` 里面，冒号 `:` 是**分隔符**。

它<span style="color:#FF0000; background:#00FF80;">用来分隔多个目录。</span>

比如：

```bash
/usr/bin:/bin:/home/book
```

不是一个目录，而是三个目录：

```text
/usr/bin
/bin
/home/book
```

所以：

```bash
PATH=$PATH:/home/book
```

里面的 `:` 表示：

```text
在原来的 PATH 后面，再追加一个新的目录 /home/book
```

如果没有这个冒号，写成：

```bash
PATH=$PATH/home/book
```

那就错了，因为它会把路径粘在一起，变成一个很奇怪的路径。

------

## 4. `PATH=$PATH:/home/book` 怎么一步步理解？

假设原来的 PATH 是：

```bash
/usr/bin:/bin
```

现在执行：

```bash
PATH=$PATH:/home/book
```

第一步，shell 看到 `$PATH`，取出原来的值：

```bash
/usr/bin:/bin
```

第二步，把 `/home/book` 拼接到后面，中间用 `:` 分隔：

```bash
/usr/bin:/bin:/home/book
```

第三步，把这个新值重新赋给 `PATH`：

```bash
PATH=/usr/bin:/bin:/home/book
```

所以最终结果是：

```text
shell 以后找命令时，除了去 /usr/bin 和 /bin 找，也会去 /home/book 找。
```

------

## 5. `export` 是什么意思？

`export` 的意思是：

```text
把这个变量导出成环境变量，让当前 shell 后面启动的子程序也能看到它。
```

比如你执行：

```bash
export PATH=$PATH:/home/book
```

之后，在当前终端里再执行：

```bash
hello
```

shell 就会去这些地方找：

```text
原来 PATH 里的目录
/home/book
```

如果 `/home/book` 里面有 `hello` 这个可执行程序，那么就可以直接运行：

```bash
hello
```

而不需要写：

```bash
/home/book/hello
```

或者：

```bash
./hello
```

------

## 6. 这条命令可以翻译成中文

```bash
export PATH=$PATH:/home/book
```

可以翻译为：

```text
把 PATH 设置为：原来的 PATH 加上 /home/book，
并导出这个 PATH，让当前终端后续运行的程序都能使用它。
```

更口语一点：

```text
shell 原来会去一些固定目录找命令；
现在我告诉 shell：以后找命令时，也顺便去 /home/book 这个目录找一找。
```

------

## 7. 为什么不是直接写 `PATH=/home/book`？

如果你写：

```bash
export PATH=/home/book
```

意思是：

```text
把 PATH 完全改成 /home/book
```

这样原来的路径就没了。

比如原来的：

```bash
/usr/bin:/bin
```

会被覆盖掉。

这样可能导致很多命令找不到，比如：

```bash
ls
gcc
cat
mkdir
```

因为它们原本在 `/usr/bin` 或 `/bin` 里面。

所以一般不要直接写：

```bash
export PATH=/home/book
```

而是写：

```bash
export PATH=$PATH:/home/book
```

意思是：

```text
保留原来的 PATH，再追加 /home/book。
```

------

## 8. 前面追加和后面追加有什么区别？

你现在写的是：

```bash
export PATH=$PATH:/home/book
```

表示把 `/home/book` 加到最后。

也可以写成：

```bash
export PATH=/home/book:$PATH
```

表示把 `/home/book` 加到最前面。

区别是查找顺序不同。

### 加到后面

```bash
export PATH=$PATH:/home/book
```

shell 会先找系统目录，最后才找 `/home/book`。

### 加到前面

```bash
export PATH=/home/book:$PATH
```

shell 会先找 `/home/book`，再找系统目录。

一般学习时，加到后面更安全：

```bash
export PATH=$PATH:/home/book
```

因为不会轻易覆盖系统原有命令的优先级。

------

## 9. 注意：这里的 `$` 和终端提示符里的 `$` 不是一回事

终端提示符里的 `$`：

```bash
book@ubuntu:~$
```

表示：

```text
当前是普通用户
```

而命令里的 `$PATH` 中的 `$`：

```bash
echo $PATH
```

表示：

```text
取出变量 PATH 的值
```

所以这两个 `$` 含义不同。

| 位置     | 例子             | 含义           |
| -------- | ---------------- | -------------- |
| 终端最后 | `book@ubuntu:~$` | 普通用户提示符 |
| 变量前面 | `$PATH`          | 取出变量的值   |

------

## 10. 最后总结

```bash
export PATH=$PATH:/home/book
```

拆开理解就是：

```text
export              导出环境变量
PATH                要修改的变量名
=                   赋值
$PATH               取出原来 PATH 的值
:                   PATH 中多个目录之间的分隔符
/home/book          新增加的命令搜索目录
```

所以整句话的核心意思是：

```text
保留原来的命令搜索路径，再额外加入 /home/book，
让 shell 以后也能到 /home/book 里面查找命令。
```
