# 1.对linux命令的理解

command      命令名
-options     选项，可以没有
parameter    参数，也可以没有

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">这里linux中的每一个命令都是一个应用程序（可以看成一个函数）吗，然后 -options可以看成是这个函数的参数，那个参数又该怎么理解呢，我不是太懂，你能够给我详细解释下吗，最好能够举些例子来让我彻底弄明白。</span>



可以这样理解：**Linux 中很多命令确实可以看成一个“程序”或者“函数调用”**，但是要稍微修正一下：

```text
command      命令名，本质上通常是一个程序 / shell 内置命令 / 脚本
-options     选项，用来改变命令的执行方式
parameter    参数，也叫操作对象，用来说明命令要处理谁、处理什么内容
```

最核心的一句话是：

```text
选项回答“怎么做”
参数回答“对谁做 / 用什么做”
```

------

## 1. Linux 命令能不能看成函数？

可以大致看成函数。

比如：

```bash
ls -l /home/book
```

可以类比成：

```c
ls(显示详细信息, 查看 /home/book 目录)
```

或者更像这样：

```python
ls(long_format=True, target="/home/book")
```

其中：

```text
ls              命令名，相当于函数名
-l              选项，控制 ls 怎么显示
/home/book      参数，告诉 ls 要查看哪个目录
```

所以你可以把它理解成：

```text
命令 = 函数名
选项 = 控制函数行为的参数
普通参数 = 函数真正要处理的对象
```

------

## 2. 但不是每个命令都是“外部应用程序”

Linux 里的命令大体有几类：

### ① 外部程序

比如：

```bash
ls
cp
rm
gcc
```

它们通常对应系统里的某个可执行文件。

例如：

```bash
which ls
```

可能会看到：

```bash
/bin/ls
```

这说明 `ls` 真的是一个程序文件。

------

### ② shell 内置命令

比如：

```bash
cd
echo
pwd
export
```

这些很多是 shell 自己内置的，不一定是单独的应用程序。

例如 `cd` 不是普通外部程序，因为它要改变当前 shell 的工作目录，所以一般由 shell 自己处理。

------

### ③ 脚本或用户自己写的程序

比如你自己写了一个：

```bash
./hello
```

它也是命令，因为 shell 可以执行它。

所以更准确地说：

```text
Linux 命令不一定全都是外部应用程序，但都可以看成 shell 能识别并执行的一种“操作”。
```

------

## 3. options 和 parameter 到底有什么区别？

先看这个格式：

```bash
command [-options] [parameter]
```

你可以把它理解成：

```text
command：我要做什么事
-options：这件事用什么方式做
parameter：这件事作用在哪个对象上
```

比如：

```bash
ls -l /home/book
```

拆开是：

```text
command：ls
意思：列出文件

option：-l
意思：用详细格式显示

parameter：/home/book
意思：查看 /home/book 这个目录
```

所以整体意思是：

```text
用详细格式，列出 /home/book 目录下的文件。
```

------

## 4. 用“函数”的方式理解 options 和 parameter

### 例子 1：ls 命令

```bash
ls
```

意思是：

```text
列出当前目录下的文件
```

类比函数：

```python
ls()
```

------

```bash
ls -l
```

意思是：

```text
用详细格式列出当前目录下的文件
```

类比函数：

```python
ls(long_format=True)
```

这里 `-l` 是选项，表示显示方式变了。

------

```bash
ls /home/book
```

意思是：

```text
列出 /home/book 目录下的文件
```

类比函数：

```python
ls(target="/home/book")
```

这里 `/home/book` 是参数，表示要查看的对象变了。

------

```bash
ls -l /home/book
```

意思是：

```text
用详细格式列出 /home/book 目录下的文件
```

类比函数：

```python
ls(long_format=True, target="/home/book")
```

所以：

```text
-l 是“怎么显示”
/home/book 是“显示谁”
```

------

## 5. 再看 cp 命令

```bash
cp a.txt b.txt
```

意思是：

```text
把 a.txt 复制成 b.txt
```

拆开：

```text
cp       命令名，复制
a.txt    参数1，源文件
b.txt    参数2，目标文件
```

类比函数：

```python
cp(source="a.txt", target="b.txt")
```

这里没有选项，只有参数。

------

如果写成：

```bash
cp -i a.txt b.txt
```

意思是：

```text
复制 a.txt 到 b.txt，如果目标文件已经存在，先询问用户是否覆盖
```

拆开：

```text
cp       命令名
-i       选项，交互式确认
a.txt    参数1，源文件
b.txt    参数2，目标文件
```

类比函数：

```python
cp(interactive=True, source="a.txt", target="b.txt")
```

这里：

```text
-i 是“怎么复制”
a.txt 和 b.txt 是“复制谁，复制到哪里”
```

------

## 6. 再看 rm 命令

```bash
rm a.txt
```

意思是：

```text
删除 a.txt
```

类比函数：

```python
rm(target="a.txt")
```

------

```bash
rm -i a.txt
```

意思是：

```text
删除 a.txt，但是删除前先询问确认
```

类比函数：

```python
rm(interactive=True, target="a.txt")
```

这里：

```text
-i 是选项，表示删除前询问
a.txt 是参数，表示要删除的文件
```

------

```bash
rm -r test
```

意思是：

```text
递归删除 test 目录
```

这里：

```text
-r 是选项，表示递归处理目录
test 是参数，表示要删除的对象
```

这个命令有危险，学习时不要随便对重要目录使用。

------

## 7. 再看 grep 命令

`grep` 是用来查找文本内容的。

```bash
grep hello a.txt
```

意思是：

```text
在 a.txt 文件中查找 hello
```

拆开：

```text
grep      命令名，查找文本
hello     参数1，要查找的内容
a.txt     参数2，要查找的文件
```

类比函数：

```python
grep(pattern="hello", file="a.txt")
```

------

```bash
grep -n hello a.txt
```

意思是：

```text
在 a.txt 中查找 hello，并显示行号
```

类比函数：

```python
grep(show_line_number=True, pattern="hello", file="a.txt")
```

这里：

```text
-n       选项，显示行号
hello    参数，要查找的内容
a.txt    参数，要在哪个文件里查
```

所以：

```text
-n 是“怎么显示结果”
hello 和 a.txt 是“查什么、在哪里查”
```

------

## 8. 再看 gcc 命令

你视频里有这个命令：

```bash
gcc -o hello hello.c
```

意思是：

```text
把 hello.c 编译成可执行程序 hello
```

拆开：

```text
gcc       命令名，调用 C 编译器
-o        选项，指定输出文件名
hello     -o 这个选项对应的值
hello.c   参数，要编译的源代码文件
```

类比函数：

```python
gcc(output="hello", input_file="hello.c")
```

这里要注意：

```bash
-o hello
```

是一组，意思是：

```text
输出文件名叫 hello
```

所以有些选项后面还会跟一个值。

## 9. 选项也可以分几种

### ① 短选项

通常是一个 `-` 加一个字母。

例如：

```bash
ls -l
ls -a
grep -n
rm -i
```

------

### ② 多个短选项可以合并

比如：

```bash
ls -l -a
```

可以写成：

```bash
ls -la
```

意思是：

```text
-l    详细格式
-a    显示隐藏文件
```

所以：

```bash
ls -la
```

等价于：

```bash
ls -l -a
```

------

### ③ 长选项

通常是两个 `--`。

例如：

```bash
ls --all
```

和下面这个类似：

```bash
ls -a
```

都表示显示隐藏文件。

再比如：

```bash
rm --help
```

表示查看 `rm` 命令的帮助信息。

------

### ④ 带值的选项

有些选项后面需要跟一个值。

比如：

```bash
gcc -o hello hello.c
```

其中：

```text
-o hello
```

表示输出文件名是 `hello`。

再比如：

```bash
grep -n hello a.txt
```

这里 `-n` 不需要额外的值，它只是一个开关。

所以选项有两种常见类型：

```text
开关型选项：打开或关闭某个功能
带值型选项：后面还要跟一个具体值
```

------

## 10. parameter 参数到底怎么理解？

在初学 Linux 时，可以把 parameter 理解成：

```text
命令真正要操作的对象。
```

比如：

```bash
ls /home/book
```

`/home/book` 是参数，因为它告诉 `ls`：

```text
你要查看哪个目录？
```

------

```bash
cat a.txt
```

`a.txt` 是参数，因为它告诉 `cat`：

```text
你要显示哪个文件？
```

------

```bash
cp a.txt b.txt
```

`a.txt` 和 `b.txt` 是参数，因为它们告诉 `cp`：

```text
从哪里复制？
复制到哪里？
```

------

```bash
grep hello a.txt
```

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">`hello` 和 `a.txt` 是参数</span>，因为它们告诉 `grep`：

```text
查找什么内容？
在哪个文件里面查？
```

------

## 11. option 和 parameter 的区别总结

可以用下面这个表理解：

| 类型      | 作用                 | 回答的问题        | 例子                             |
| --------- | -------------------- | ----------------- | -------------------------------- |
| command   | 要执行什么命令       | 做什么事          | `ls`、`cp`、`grep`               |
| option    | 改变命令的执行方式   | 怎么做            | `-l`、`-a`、`-n`、`-r`           |
| parameter | 命令操作的对象或内容 | 对谁做 / 用什么做 | `/home/book`、`a.txt`、`hello.c` |

------

## 12. 最好记的理解方式

你可以这样记：

```text
command 是动作
option 是动作的方式
parameter 是动作的对象
```

比如：

```bash
ls -l /home/book
```

翻译成中文就是：

```text
动作：列出文件
方式：详细格式
对象：/home/book 目录
```

------

```bash
cp -i a.txt b.txt
```

翻译成中文就是：

```text
动作：复制
方式：如果覆盖就询问
对象：从 a.txt 复制到 b.txt
```

------

```bash
grep -n hello a.txt
```

翻译成中文就是：

```text
动作：查找
方式：显示行号
对象：在 a.txt 中查找 hello
```

## 13. 从 shell 角度看，它们其实都是字符串

比如你输入：

```bash
ls -l /home/book
```

shell 一开始看到的只是字符串：

```text
"ls -l /home/book"
```

然后 <span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">shell 按空格拆开：</span>

```text
argv[0] = "ls"
argv[1] = "-l"
argv[2] = "/home/book"
```

再把这些东西交给 `ls` 程序。

也就是说，<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">shell 不一定真的知道 `-l` 是什么意思，真正解释 `-l` 的是 `ls` 程序自己。</span>

对于 `ls` 来说：

```text
-l 表示详细格式
```

但是对于别的命令，`-l` 可能是别的意思。

所以：

```text
选项的具体含义由每个命令自己决定。
```

------

## 14. 最关键的一句话

你可以把 Linux 命令理解成函数调用：

```bash
command -options parameter
```

大致等价于：

```python
command(options, parameters)
```

但是更准确地说：

```text
options 也是参数的一种，只不过它们是“控制命令行为的特殊参数”；
普通 parameter 是“命令真正要处理的对象”。
```

例如：

```bash
ls -l /home/book
```

可以理解成：

```python
ls(mode="long", target="/home/book")
```

其中：

```text
-l              控制怎么显示
/home/book      指定显示谁
```

这样你就能区分了。





# 2. 长选项 与 短选项 关系 以及 带值选项的值与参数区分

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">长选项和短选项之间的关系是什么，以及带值的选项后面的值感觉很容易和参数给搞混乱，比如grep -n  hello a.txt，这里的hello应该不是选项，因为不是以-开头，它也不属于选项-n的值，故这里的hello就只能够是参数吧。</span>

你的理解是对的：

```bash
grep -n hello a.txt
```

这里：

```text
grep    命令名
-n      选项，表示显示行号
hello   普通参数，表示要查找的内容
a.txt   普通参数，表示在哪个文件里查
```

`hello` 不是 `-n` 的值，因为<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;"> `-n` 这个选项本身不需要值，它只是一个“开关型选项”。</span>

------

## 1. 长选项和短选项是什么关系？

短选项一般是：

```bash
-l
-a
-n
-r
-o
```

长选项一般是：

```bash
--all
--help
--version
--output
--recursive
```

它们<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">很多时候是同一个功能的两种写法。</span>

比如：

```bash
ls -a
```

等价于：

```bash
ls --all
```

意思都是：

```text
显示隐藏文件
```

再比如：

```bash
grep -n hello a.txt
```

等价于：

```bash
grep --line-number hello a.txt
```

意思都是：

```text
查找 hello，并显示行号
```

所以可以这样理解：

```text
短选项：简洁，适合熟练使用
长选项：清楚，适合阅读和脚本
```

------

## 2. 短选项和长选项不一定总是一一对应

有些短选项有对应的长选项：

```bash
ls -a
ls --all
```

有些可能没有明显对应关系。

有些长选项也不一定有短选项。

所以不能机械地认为：

```text
所有 -x 都一定有一个 --xxx
所有 --xxx 都一定有一个 -x
```

具体要看这个命令自己的规定，可以用：

```bash
命令 --help
```

或者：

```bash
man 命令
```

查看。

------

## 3. 短选项可以合并，长选项一般不能合并

比如：

```bash
ls -l -a
```

可以合并成：

```bash
ls -la
```

意思是：

```text
-l    使用详细格式
-a    显示隐藏文件
```

所以：

```bash
ls -la
```

等价于：

```bash
ls -l -a
```

但是长选项一般不能这样合并。

你不能写成：

```bash
ls --alllong
```

来表示：

```bash
ls --all --long
```

长选项通常要分开写：

```bash
ls --all -l
```

或者：

```bash
ls --all --format=long
```

具体看命令支持什么。

------

## 4. 选项后面的值为什么容易和参数混？

因为<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">从 shell 的角度看，它们本质上都是字符串。</span>

比如：

```bash
gcc -o hello hello.c
```

shell 拆开以后是：

```text
argv[0] = "gcc"
argv[1] = "-o"
argv[2] = "hello"
argv[3] = "hello.c"
```

这里 `hello` 看起来不像选项，因为它不以 `-` 开头。

但是它是 `-o` 这个选项的值。

为什么？

因为 `gcc` 规定：

```text
-o 后面必须跟一个值，用来表示输出文件名。
```

所以：

```bash
gcc -o hello hello.c
```

应该理解成：

```text
gcc       命令名
-o hello  选项 + 选项的值，表示输出文件名是 hello
hello.c   普通参数，表示输入源文件
```

类比成函数：

```python
gcc(output="hello", input_file="hello.c")
```

------

## 5. 怎么判断某个单词是“选项的值”还是“普通参数”？

核心规则是：

```text
看它前面的选项需不需要值。
```

比如：

```bash
grep -n hello a.txt
```

`-n` 不需要值，所以后面的 `hello` 不是 `-n` 的值，而是普通参数。

含义是：

```text
-n       显示行号
hello    查找的内容
a.txt    查找的文件
```

------

但是：

```bash
grep -e hello a.txt
```

这里就不一样了。

`-e` 需要一个值，表示要查找的模式。

所以：

```text
grep      命令名
-e hello  选项 + 选项的值，表示查找 hello
a.txt     普通参数，表示文件
```

也就是说：

```bash
grep -n hello a.txt
```

里面的 `hello` 是普通参数。

```bash
grep -e hello a.txt
```

里面的 `hello` 是 `-e` 的值。

------

## 6. 同样是 hello，身份可能不同

看这三个例子：

### 例子 1：hello 是普通参数

```bash
grep -n hello a.txt
```

解释：

```text
-n       显示行号
hello    要查找的内容
a.txt    要查找的文件
```

这里 `hello` 是普通参数。

------

### 例子 2：hello 是选项的值

```bash
grep -e hello a.txt
```

解释：

```text
-e hello    指定查找模式为 hello
a.txt       要查找的文件
```

这里 `hello` 是 `-e` 的值。

------

### 例子 3：hello 是输出文件名

```bash
gcc -o hello hello.c
```

解释：

```text
-o hello    输出文件名叫 hello
hello.c     输入源文件
```

第一个 `hello` 是 `-o` 的值。

`hello.c` 是普通参数。

------

## 7. 带值选项常见写法

有些带值选项可以这样写：

```bash
gcc -o hello hello.c
```

也可以写成：

```bash
gcc -ohello hello.c
```

不过初学时建议写第一种，更清楚。

长选项带值常见两种写法：

```bash
command --output hello
```

或者：

```bash
command --output=hello
```

比如：

```bash
grep --regexp=hello a.txt
```

大致等价于：

```bash
grep -e hello a.txt
```

意思是：

```text
指定查找模式为 hello
```

------

## 8. 选项、选项的值、普通参数的关系

可以这样分：

```text
命令名：做什么事
选项：怎么做
选项的值：这个选项需要的具体配置
普通参数：命令真正处理的对象
```

例如：

```bash
gcc -o hello hello.c
```

可以拆成：

```text
做什么事：gcc，编译
怎么做：-o，指定输出文件名
选项的值：hello，输出文件名
处理对象：hello.c，要编译的源文件
```

------

再例如：

```bash
grep -n hello a.txt
```

可以拆成：

```text
做什么事：grep，查找文本
怎么做：-n，显示行号
处理对象1：hello，要查找的内容
处理对象2：a.txt，要查找的文件
```

这里没有“选项的值”。

------

再例如：

```bash
grep -n -e hello a.txt
```

可以拆成：

```text
grep        命令名
-n          选项，显示行号
-e hello    选项 + 选项的值，指定查找内容是 hello
a.txt       普通参数，要查找的文件
```

------

## 9. 一个很好用的判断口诀

你可以这样判断：

```text
以 - 开头的，通常是选项；
不以 - 开头的，可能是普通参数，也可能是前一个选项的值；
关键看前一个选项需不需要值。
```

比如：

```bash
grep -n hello a.txt
```

`-n` 不需要值，所以 `hello` 是普通参数。

```bash
grep -e hello a.txt
```

`-e` 需要值，所以 `hello` 是 `-e` 的值。

```bash
gcc -o hello hello.c
```

`-o` 需要值，所以第一个 `hello` 是 `-o` 的值。

------

## 10. 更准确地说：选项的值其实也是一种“参数”

这里有一个术语容易让人混乱。

从 C 程序的角度看，命令后面的所有内容都是参数：

```bash
gcc -o hello hello.c
```

传给程序的是：

```text
argv[0] = gcc
argv[1] = -o
argv[2] = hello
argv[3] = hello.c
```

所以从广义上说：

```text
-o、hello、hello.c 都是传给 gcc 的参数。
```

但是从命令格式的角度，我们会细分成：

```text
-o          选项
hello       选项 -o 的值
hello.c     普通参数 / 操作对象
```

所以你可以分成两层理解：

```text
广义参数：命令后面所有传给程序的字符串
狭义参数：不属于选项、也不属于选项值的普通操作对象
```

你前面说的 `parameter`，一般更接近“狭义参数”，也就是命令真正处理的对象。

------

## 11. 用几个例子彻底区分

### `ls -l /home/book`

```text
ls              命令名
-l              选项，详细显示
/home/book      普通参数，要查看的目录
```

------

### `ls -la /home/book`

```text
ls              命令名
-l              选项，详细显示
-a              选项，显示隐藏文件
/home/book      普通参数，要查看的目录
```

`-la` 等价于 `-l -a`。

------

### `cp -i a.txt b.txt`

```text
cp              命令名
-i              选项，覆盖前询问
a.txt           普通参数，源文件
b.txt           普通参数，目标文件
```

------

### `gcc -o hello hello.c`

```text
gcc             命令名
-o hello        选项 + 选项的值
hello.c         普通参数，要编译的源文件
```

------

### `grep -n hello a.txt`

```text
grep            命令名
-n              选项，显示行号
hello           普通参数，要查找的内容
a.txt           普通参数，要查找的文件
```

------

### `grep -n -e hello a.txt`

```text
grep            命令名
-n              选项，显示行号
-e hello        选项 + 选项的值，指定查找模式
a.txt           普通参数，要查找的文件
```

------

## 12. 最后总结

你这句话理解得很准确：

> `grep -n hello a.txt` 中的 `hello` 不是选项，因为不是以 `-` 开头；它也不属于选项 `-n` 的值，因为 `-n` 不需要值；所以它只能是普通参数。

可以再补充一句：

```text
判断一个非 - 开头的内容是“普通参数”还是“选项的值”，关键看它前面的选项是否需要值。
```

最简单的模型就是：

```text
command：做什么
option：怎么做
option value：这个选项具体设置成什么
parameter：对谁做 / 处理什么
```

例如：

```bash
grep -n hello a.txt
```

就是：

```text
做什么：查找
怎么做：显示行号
查什么：hello
在哪查：a.txt
```



# 3.终端提示符组成的理解

book               			 当前登录用户名
www.100ask.org       主机名
~                   				当前所在目录，~ 表示用户家目录
$                		   		普通用户提示符

root 			 				管理员提示符

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">这里终端提示符的组成应该如何理解呢，这里的主机名是个什么东西呢，还有这里的家目录又是个什么东西呢，我不是太懂，你能够给我详细解释下吗？</span>

可以<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">把 Linux 终端提示符理解成一句话</span>：

```bash
book@www.100ask.org:~$
```

它不是你输入的命令，而是 **终端提前显示给你看的“当前位置和身份信息”**。

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">它大概在告诉你：</span>

```text
当前是谁，在哪台机器上，当前处于哪个目录，用什么权限在操作。
```

也就是：

```text
book @ www.100ask.org : ~ $
用户    主机名          当前目录  权限提示符
```

------

## 1. 终端提示符整体怎么理解？

比如：

```bash
book@www.100ask.org:~$
```

可以读成一句中文：

```text
当前用户 book，正在 www.100ask.org 这台电脑上，当前位置是自己的家目录，并且当前是普通用户权限。
```

拆开来看：

| 部分             | 含义                                                |
| ---------------- | --------------------------------------------------- |
| `book`           | 当前登录用户名                                      |
| `@`              | 分隔符，表示“谁在某台机器上”（补充：@为at，在……上） |
| `www.100ask.org` | 主机名，也就是这台电脑/系统的名字                   |
| `:`              | 分隔符，后面接当前目录                              |
| `~`              | 当前所在目录，表示用户的家目录                      |
| `$`              | 普通用户提示符                                      |

所以：

```bash
book@www.100ask.org:~$
```

本质上是在显示：

```text
用户@主机名:当前目录 权限符号
```

------

## 2. 主机名是什么？

主机名英文叫 **hostname**。

你可以把它理解成：

```text
这台 Linux 电脑在系统里的名字。
```

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">就像每个人有名字一样，每台电脑也可以有一个名字。</span>

比如你家里有几台电脑：

```text
电脑1：desktop-pc
电脑2：ubuntu-server
电脑3：raspberrypi
```

这些就可以是主机名。

在视频里：

```bash
www.100ask.org
```

就是这台 Linux 系统的主机名。

------

### 举个生活例子

假设有三个人都叫 `book` 这个用户：

```text
book 用户登录在 A 电脑上
book 用户登录在 B 电脑上
book 用户登录在 C 电脑上
```

如果终端只显示：

```bash
book:~$
```

你可能不知道自己正在操作哪台机器。

所以终端显示成：

```bash
book@ubuntu:~$
book@server:~$
book@raspberrypi:~$
```

这样你就能知道：

```text
当前是 book 用户，正在 ubuntu/server/raspberrypi 这台机器上操作。
```

------

### 为什么主机名重要？

<span style="color:#FF0000; background:#00FF80;">如果你只是本地用 Linux，主机名感觉不明显。</span>

<span style="color:#FF0000; background:#00FF80;">但是如果你通过 SSH 远程登录服务器，主机名就很重要。</span>

比如：

```bash
book@my-laptop:~$
```

说明<span style="color:#FF0000; background:#00FF80;">你在自己的电脑上。</span>

而：

```bash
book@aliyun-server:~$
```

说明<span style="color:#FF0000; background:#00FF80;">你可能正在操作云服务器。</span>

<span style="color:#FF0000;">这时如果你误删文件，影响的可能不是本机，而是远程服务器。所以主机名是用来提醒你：</span>

```text
你现在到底在哪台机器上操作。
```

------

## 3. 家目录是什么？

家目录英文叫 **home directory**。

你可以把它理解成：

```text
每个用户自己的私人文件夹。
```

<span style="color:#FF0000; background:#00FF80;">在 Linux 中，每个普通用户一般都有自己的家目录。</span>

比如用户叫 `book`，那么它的家目录通常是：

```bash
/home/book
```

用户叫 `zhangsan`，家目录通常是：

```bash
/home/zhangsan
```

用户叫 `lisi`，家目录通常是：

```bash
/home/lisi
```

所以：

```text
/home/用户名
```

<span style="color:#FF0000; background:#00FF80;">通常就是这个用户的家目录。</span>

------

## 4. `~` 为什么表示家目录？

在 Linux 中：

```bash
~
```

是一个简写，表示当前用户的家目录。

如果当前用户是 `book`，那么：

```bash
~
```

就等价于：

```bash
/home/book
```

所以这两个命令意思一样：

```bash
cd ~
cd /home/book
```

都表示回到 `book` 用户的家目录。

------

## 举个例子

如果终端显示：

```bash
book@www.100ask.org:~$
```

说明你当前所在目录是：

```bash
/home/book
```

如果你输入：

```bash
pwd
```

可能会显示：

```bash
/home/book
```

这里 `pwd` 的意思是显示当前所在目录。

------

## 5. 家目录有什么用？

家目录可以理解成 Linux 里属于你的个人空间。

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">比如用户 `book` 的很多文件都可以放在：</span>

```bash
/home/book
```

里面可能有：

```bash
/home/book/Desktop
/home/book/Documents
/home/book/Downloads
/home/book/Music
/home/book/Pictures
```

<span style="color:#FF0000; background:#00FF80;">类似 Windows 里的：</span>

```text
C:\Users\你的用户名
```

例如 Windows 中的：

```text
C:\Users\Arley\Desktop
C:\Users\Arley\Downloads
C:\Users\Arley\Documents
```

Linux 中大概对应：

```bash
/home/book/Desktop
/home/book/Downloads
/home/book/Documents
```

所以你可以这样类比：

```text
Linux 的 /home/book ≈ Windows 的 C:\Users\book
```

------

## 6. 当前目录是什么意思？

终端里的命令通常都在“当前目录”下执行。

比如终端显示：

```bash
book@www.100ask.org:~$
```

说明你当前在家目录。

如果你输入：

```bash
ls
```

它默认列出的是当前目录，也就是：

```bash
/home/book
```

里面的文件。

------

如果你切换目录：

```bash
cd Desktop
```

提示符可能变成：

```bash
book@www.100ask.org:~/Desktop$
```

意思是：

```text
当前用户 book
当前主机 www.100ask.org
当前目录 /home/book/Desktop
普通用户权限
```

这里：

```bash
~/Desktop
```

等价于：

```bash
/home/book/Desktop
```

------

如果你继续进入某个文件夹：

```bash
cd test
```

提示符可能变成：

```bash
book@www.100ask.org:~/Desktop/test$
```

意思是你现在位于：

```bash
/home/book/Desktop/test
```

------

## 7. `$` 和 `#` 是什么？

终端最后的符号一般表示当前权限身份。

### `$`：普通用户

比如：

```bash
book@www.100ask.org:~$
```

最后是 `$`，说明当前是普通用户。

普通用户权限相对较低，不能随便修改系统关键文件。

例如普通用户一般不能直接修改：

```bash
/etc/passwd
/etc/environment
/bin
/usr/bin
```

这些系统级位置。

------

### `#`：root 用户

如果终端显示：

```bash
root@www.100ask.org:~#
```

或者：

```bash
root@www.100ask.org:/home/book#
```

最后是 `#`，说明当前是 root 用户。

root 是 Linux 中的超级管理员。

它的<span style="color:#FF0000; background:#00FF80;">权限非常高，几乎可以修改系统中的任何东西。</span>

所以：

```text
$ 表示普通用户
# 表示 root 管理员用户
```

------

## 8. root 和普通用户有什么区别？

可以这样理解：

```text
普通用户：只能主要管理自己的文件
root 用户：可以管理整个系统
```

比如<span style="color:#FF0000; background:#00FF80;">普通用户 `book` 主要能操作：</span>

```bash
/home/book
```

<span style="color:#FF0000; background:#00FF80;">里面的文件。</span>

但是 root 可以操作：

```bash
/home/book
/etc
/bin
/usr
/var
/root
```

几乎整个系统。

------

### 举个例子

普通用户执行：

```bash
rm /etc/passwd
```

通常会失败，因为权限不够。

但 root 用户执行某些危险命令可能真的会影响系统。

所以看到提示符从 `$` 变成 `#` 时，要特别小心。

------

## 9. root 的家目录和普通用户不一样

普通用户 `book` 的家目录通常是：

```bash
/home/book
```

<span style="color:#FF0000; background:#00FF80;">但是 root 用户的家目录通常是：</span>

```bash
/root
```

所以：

```bash
book@www.100ask.org:~$
```

这里的 `~` 表示：

```bash
/home/book
```

而：

```bash
root@www.100ask.org:~#
```

这里的 `~` 表示：

```bash
/root
```

注意：`~` 不是永远等于 `/home/book`。

它表示的是：

```text
当前用户的家目录
```

当前用户是谁，`~` 就代表谁的家目录。

# 4.主机名 与 用户名 命名规则 与用户名作用

<span style="color:#FF0000; background:#00FF80;">www.100ask.org这里的主机名是这个，这里主机名有没有什么命名规则或者限制那，还有用户名有没有什么命名规则或者限制呢，用户名的作用是什么呢，我不是太懂，你能够给我详细解释下吗？</span>

可以，先给你一个总的理解：

```text
主机名 hostname：给“这台电脑/这台 Linux 系统”起的名字。
用户名 username：给“使用这台系统的人/账户”起的名字。
```

所以终端提示符：

```bash
book@www.100ask.org:~$
```

可以理解成：

```text
book 这个用户，正在 www.100ask.org 这台机器上操作，当前目录是自己的家目录，权限是普通用户。
```

------

## 1. 主机名是什么？

主机名英文是：

```text
hostname
```

它是这台 Linux 系统的名字。

比如你有三台 Linux 机器，可以分别叫：

```text
ubuntu
server01
raspberrypi
my-laptop
```

那么终端可能显示：

```bash
book@ubuntu:~$
book@server01:~$
book@raspberrypi:~$
book@my-laptop:~$
```

这样你就知道自己现在正在操作哪一台机器。

------

## 2. `www.100ask.org` 为什么也能作为主机名？

因为<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">主机名可以写成类似域名的形式。</span>

```bash
www.100ask.org
```

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">看起来像一个网站域名，但在这里它作为主机名出现，意思是：</span>

```text
这台 Linux 机器的名字叫 www.100ask.org
```

主机名<span style="border:1px solid #FF00FF; background:#00FF80; color:#FF0000;">可以比较简单：</span>

```text
ubuntu
book-pc
server01
```

也可以比较完整，像域名一样：

```text
www.100ask.org
linux.example.com
dev.server.local
```

这种带点号的完整名字，也可以叫：

```text
FQDN，Fully Qualified Domain Name，完全限定域名
```

不过初学阶段你可以简单理解成：

```text
www.100ask.org 就是这台机器的名字。
```

------

## 3. 主机名有什么作用？

主机名主要有几个作用。

### 作用 1：区分不同电脑

如果你只用一台电脑，主机名感觉没啥用。

但是<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">如果你同时管理多台服务器，就很重要。</span>

比如：

```bash
book@ubuntu:~$
```

说明你在本地 Ubuntu 上。

```bash
book@aliyun-server:~$
```

说明你在阿里云服务器上。

```bash
book@test-server:~$
```

说明你在测试服务器上。

这样你不会把命令敲错地方。

比如删除文件时，如果你以为自己在测试机，结果其实在正式服务器，那就很危险。

------

### 作用 2：网络中识别这台机器

在局域网或者服务器环境中，主机名可以帮助其他机器识别它。

比如有三台机器：

```text
db-server       数据库服务器
web-server      网站服务器
file-server     文件服务器
```

看到名字就大概知道这台机器是干什么的。

------

### 作用 3：终端提示符中提醒你当前位置

比如：

```bash
root@production-server:/var/www#
```

这个提示符就很危险。

它告诉你：

```text
当前用户是 root
当前机器是 production-server，可能是生产服务器
当前目录是 /var/www
当前权限是管理员权限
```

看到这个你就要小心，不要随便执行删除、覆盖、重启之类的命令。

------

## 4. 主机名有没有命名规则？

有。

一般建议主机名遵守这些规则：

```text
可以使用英文字母、数字、短横线 -
通常不要使用空格
通常不要使用下划线 _
不要以短横线开头或结尾
大小写一般不敏感，但建议全小写
```

常见合法写法：

```text
ubuntu
server01
web-server
book-pc
raspberrypi
www.100ask.org
```

不推荐或可能有问题的写法：

```text
my server       有空格，不推荐
_server         有下划线，不推荐
server_01       有下划线，不推荐
-server         以短横线开头，不推荐
server-         以短横线结尾，不推荐
中文主机        不推荐，兼容性不好
```

------

## 5. 主机名可以随便起吗？

本机自己用的话，基本可以自己起。

比如你可以把主机名设置成：

```text
my-ubuntu
arley-pc
linux-study
```

<span style="color:#FF0000; background:#00FF80;">但是如果是在公司、学校、服务器环境中，通常会有统一规则。</span>

例如：

```text
web01
web02
db01
test-server
prod-server
```

这些名字一般有含义：

```text
web      网站服务器
db       数据库服务器
test     测试环境
prod     正式环境
01/02    编号
```

## 6. 怎么查看主机名？

可以使用：

```bash
hostname
```

比如输出：

```bash
www.100ask.org
```

说明当前机器的主机名就是：

```text
www.100ask.org
```

也可以用：

```bash
hostnamectl
```

查看更详细的信息。

## 7. 用户名是什么？

用户名英文是：

```text
username
```

它是 Linux 系统中一个账户的名字。

比如：

```text
book
root
zhangsan
lisi
arley
```

终端中的：

```bash
book@www.100ask.org:~$
```

前面的 `book` 就是当前登录用户的用户名。

也就是：

```text
现在是谁在使用这台 Linux 系统。
```

------

## 8. 用户名有什么作用？

用户名非常重要。它不是单纯显示用的，而是<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">系统管理权限和文件归属的基础。</span>

### 作用 1：区分不同使用者

比如一台 Linux 电脑上有三个用户：

```text
book
zhangsan
lisi
```

每个人都有自己的账户。

登录后终端可能分别显示：

```bash
book@ubuntu:~$
zhangsan@ubuntu:~$
lisi@ubuntu:~$
```

<span style="color:#FF0000; background:#00FF80; border:1px solid #FF00FF;">表示不同的人正在使用同一台机器。</span>

------

### 作用 2：决定你的家目录

<span style="color:#FF0000; background:#00FF80;">普通用户通常有自己的家目录。</span>

比如：

```text
book      -> /home/book
zhangsan  -> /home/zhangsan
lisi      -> /home/lisi
```

所以如果当前用户是 `book`，那么：

```bash
~
```

通常表示：

```bash
/home/book
```

如果当前用户是 `zhangsan`，那么：

```bash
~
```

通常表示：

```bash
/home/zhangsan
```

所以 `~` 不是固定等于 `/home/book`，而是：

```text
当前用户的家目录。
```

------

### 作用 3：决定文件属于谁

Linux 中每个文件都有所属用户。

比如你执行：

```bash
ls -l
```

可能看到：

```bash
-rw-r--r-- 1 book book 1234 May 28 a.txt
```

这里的 `book book` 里面，第一个 `book` 表示：

```text
这个文件属于 book 用户。
```

也就是说，<span style="color:#FF0000; background:#00FF80;">文件是有“主人”的。</span>

------

### 作用 4：决定你有没有权限操作某些文件

比如文件 `a.txt` 属于 `book`。

那么 `book` 用户可能可以修改它：

```bash
vim a.txt
```

但另一个用户 `lisi` 可能没有权限修改它。

所以<span style="color:#FF0000; background:#00FF80;">用户名和权限系统是绑定的。</span>

<span style="color:#FF0000; background:#00FF80;">Linux 会根据你是谁，判断你能不能：</span>

```text
读取文件
修改文件
删除文件
执行程序
进入目录
修改系统配置
```

------

### 作用 5：区分普通用户和管理员用户

Linux 中最特殊的用户是：

```text
root
```

`root` 是超级管理员。

普通用户提示符通常是：

```bash
$
```

root 用户提示符通常是：

```bash
#
```

例如：

```bash
book@ubuntu:~$
```

表示普通用户。

```bash
root@ubuntu:~#
```

表示管理员用户。

------

## 9. 用户名有没有命名规则？

有。

<span style="color:#FF0000; background:#00FF80;">Linux 用户名一般建议遵守：</span>

```text
使用小写英文字母开头
可以包含小写字母、数字、下划线 _、短横线 -
不要使用空格
不要使用中文
不要使用特殊符号
不要和已有用户名重复
```

常见合法用户名：

```text
book
arley
zhangsan
user01
test_user
linux-student
```

不推荐或可能有问题的用户名：

```text
User        有大写，不推荐
my user     有空格，不行
张三         中文，不推荐
123user     数字开头，不推荐，有些系统不允许
root        已经是系统管理员名，不能随便用
bin         系统已有用户，不适合作普通用户名
```

不同 Linux 发行版对用户名规则可能略有不同，但初学时你记住：

```text
普通用户名尽量用小写字母、数字、下划线、短横线。
```

最稳妥的格式是：

```text
小写字母开头 + 小写字母/数字
```

例如：

```text
book
arley
student01
linuxuser
```

## 10. 用户名和主机名的区别

这个最容易混。

看这个提示符：

```bash
book@www.100ask.org:~$
```

其中：

```text
book             用户名
www.100ask.org   主机名
```

你可以把它读成：

```text
谁 @ 哪台机器
```

也就是：

```text
book 用户 @ www.100ask.org 这台机器
```

<span style="color:#FF0000; background:#00FF80;">类似邮箱格式：</span>

```text
用户名@机器名
```

但它不是邮箱，只是终端提示符的显示格式。

### 例子 1

```bash

```

含义：

```text
当前用户：arley
当前机器：ubuntu
当前目录：arley 的家目录
当前权限：普通用户
```

### 例子 2

```bash
book@www.100ask.org:~/Desktop$
```

含义：

```text
当前用户：book
当前机器：www.100ask.org
当前目录：/home/book/Desktop
当前权限：普通用户
```

### 例子 3

```bash

```

```text
当前用户：root

当前目录：/etc

```

这个就要格外小心，因为：

```text

/etc 是系统配置目录
# 表示管理员权限
```

## 12. 用户名和主机名可以一样吗？

可以，但不建议。

比如：

```bash
ubuntu@ubuntu:~$
```

前面的 `ubuntu` 是用户名，后面的 `ubuntu` 是主机名。

它表示：

```text
ubuntu 用户正在 ubuntu 这台机器上操作。
```

虽然两个名字一样，但含义完全不同。

再比如：

```bash
book@book:~$
```

第一个 `book` 是用户，第二个 `book` 是机器名。

结构还是：

```text
用户名@主机名
```

------

## 13. 用户名和主机名跟文件路径有什么关系？

用户名经常会影响家目录路径。

比如当前用户是 `book`：

```bash
book@ubuntu:~$
```

那么：

```bash
~
```

一般就是：

```bash
/home/book
```

当前用户是 `arley`：

```bash
arley@ubuntu:~$
```

那么：

```bash
~
```

一般就是：

```bash
/home/arley
```

但是主机名一般不直接决定你的路径。

主机名主要表示：

```text
你在哪台机器上。
```

用户名主要表示：

```text
你是谁，你有什么权限，你的家目录在哪里。
```

## 14. 可以用命令验证

查看当前用户名：

```bash
whoami
```

输出可能是：

```bash
book
```

查看当前用户信息：

```bash
id
```

输出可能类似：

```bash
uid=1000(book) gid=1000(book) groups=1000(book),27(sudo)
```

这里说明当前用户是 `book`，并且属于一些用户组。

查看主机名：

```bash
hostname
```

输出可能是：

```bash
www.100ask.org
```

查看当前目录：

```bash
pwd
```

输出可能是：

```bash
/home/book
```

## 15. 一句话总结

你可以这样记：

```text
用户名：说明“谁在操作系统”
主机名：说明“正在操作哪台机器”
家目录：说明“这个用户自己的默认文件夹”
```

所以：

```bash
book@www.100ask.org:~$
```

可以翻译成：

```text
book 用户，正在 www.100ask.org 这台 Linux 机器上，当前位于 book 的家目录，并且是普通用户权限。
```

再压缩成一个公式：

```text
用户名 @ 主机名 : 当前目录 权限符号
```

也就是：

```text
谁 @ 哪台机器 : 在哪个目录 用什么权限
```
