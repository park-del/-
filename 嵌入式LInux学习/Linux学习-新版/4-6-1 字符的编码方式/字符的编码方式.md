# 视频分析：P49《字符的编码方式》

这节和你前面学的 Framebuffer 其实能接起来：**Framebuffer解决“像素怎么存”，这一节解决“字符怎么变成数字，再怎么存进内存/文件”。**

先给你最核心的一句话：

> <span style="color:#FF0000; background:#00FF80;">**计算机并不直接保存“A”“中”这些字符，而是先给字符规定一个数字编号，再按照某种编码格式把这个编号转换成若干个字节存下来。**</span>

------

## 1. 视频类型判断

- **主要类型：** 讲解类、科普类
- **次要类型：** 原理分析类、编码实验类

判断依据：

1. 先解释 ASCII、ANSI、Unicode 这些“字符和数字的对应关系”。
2. 再讲 UTF-16 LE、UTF-16 BE、UTF-8 如何把 Unicode 编号真正存成字节。
3. 后面结合十六进制编辑器直接观察文件内部字节，属于非常典型的“原理 + 实验验证”。

------

## 2. 一句话总结

这个视频主要讲：

```text
字符
↓
先对应一个数字编号
↓
Unicode / ASCII 等字符集
↓
再选择一种实际编码方式
↓
UTF-8 / UTF-16LE / UTF-16BE
↓
转换成若干字节
↓
存入文件 / 内存
```

例如： 

```text
字符 A
↓
Unicode码点 U+0041
↓
UTF-8
↓
0x41
```

而：

```text
字符 中
↓
Unicode码点 U+4E2D
↓
UTF-8
↓
E4 B8 AD
```

这两条非常值得记。

## 4. 这节最重要的第一层：字符 ≠ 数字 ≠ 字节

这里非常容易混。

拿：

```text
中
```

来说。

### 第一步：字符

这是人看到的：

```text
中
```

它本身只是一个抽象字符。

### 第二步：<span style="background:#00FF80; color:#FF0000;">给字符编号</span>

Unicode 规定：

```text
中
↓
U+4E2D
```

也就是：

```text
十六进制编号：0x4E2D
```

这个叫：

> **Unicode code point，Unicode 码点。**

### 第三步：<span style="color:#FF0000; background:#00FF80;">真正存储成字节</span>

例如采用 UTF-8：

```text
U+4E2D
↓ UTF-8编码
E4 B8 AD
```

所以：

```text
字符：中
码点：U+4E2D
UTF-8字节：E4 B8 AD
```

三者一定要分开。

------

## 5. ASCII 到底是什么？

大约 **01:30-03:20**。

<span style="color:#FF0000; background:#00FF80;">ASCII 本质上就是一张表：</span>

```text
字符 ↔ 数字
```

比如：

```text
'A' → 65 → 0x41
'B' → 66 → 0x42
'a' → 97 → 0x61
```

所以：

```c
char c = 'A';
```

底层其实保存的就是：

```text
0x41
```

CPU根本不知道：

> “这是字母A。”

CPU只看到：

```text
0100 0001
```

<span style="color:#FF0000; background:#00FF80;">是软件根据 ASCII 规则解释成：</span>

```text
A
```

------

## 6. Unicode 又是什么？

<span style="color:#FF0000; background:#00FF80;">ASCII最大的问题是：</span>

```text
能表示的字符太少
```

<span style="color:#FF0000; background:#00FF80;">英语还行，但：</span>

```text
中文
日文
韩文
阿拉伯文
各种符号
emoji
...
```

<span style="color:#FF0000; background:#00FF80;">就不够了。</span>

于是 <span style="background:#00FF80;">Unicode 的思想是：</span>

> <span style="color:#FF0000; background:#00FF80;">**全世界字符统一编号。**</span>

例如：

```text
A
→ U+0041

中
→ U+4E2D
```

所以你<span style="color:#FF0000; background:#00FF80;">可以把 Unicode 想象成一本超级大的“字符身份证号码表”。</span>

```text
字符             Unicode编号

A        →       0x0041
中       →       0x4E2D
...
```

------

## 7. 一个很重要的纠正：<span style="background:#00FF80;">Unicode不是UTF-8</span>

这个以后特别容易说错。

很多人会说：

> “这个文件是 Unicode 编码。”

这句话其实不够精确。

更好的理解：

```text
Unicode
↓
规定字符编号

UTF-8 / UTF-16 / UTF-32
↓
规定这个编号如何变成字节
```

所以：

```text
Unicode
≈ 字符编号标准

UTF
≈ 编码/存储方式
```

你可以类比：

```text
身份证号码
↓
Unicode码点

身份证号码怎么打印/存文件
↓
UTF-8 / UTF-16
```

------

## 8. 为什么不能直接把 Unicode 编号原样保存？

视频大约 **07:20-10:50** 就是在引这个问题。

假设：

```text
A = 0x41
```

<span style="color:#FF0000; background:#00FF80;">如果强行固定使用多个字节来保存：</span>

```text
00 41
```

甚至更多字节，那么：

```text
A
```

这种本来 ASCII 只要：

```text
1 Byte
```

的字符就会浪费空间。

所以<span style="background:#00FF80;">需要更合理的编码方案。</span>

这也是 <span style="color:#FF0000; background:#00FF80;">UTF-8 很重要的原因：</span>

> <span style="background:#00FF80;">**英文字符仍然只占1字节，中文等字符再使用更多字节。**</span>

------

## 9. UTF-16 LE 是什么？

视频 **10:50以后** 展示得很直观。

例如：

```text
A中
```

<span style="color:#FF0000; background:#00FF80;">Unicode码点：</span>

```text
A   → 0x0041
中  → 0x4E2D
```

<span style="color:#FF0000; background:#00FF80;">UTF-16 Little Endian 下：</span>

```text
A：
0x0041
↓ 小端
41 00

中：
0x4E2D
↓ 小端
2D 4E
```

文件里还可能有 BOM：

```text
FF FE
```

于是视频展示：

```text
FF FE 41 00 2D 4E
```

可以拆成：

```text
FF FE     → UTF-16 LE BOM

41 00     → A

2D 4E     → 中
```

------

## 10. 为什么“小端”会变成 `41 00`？

你之前学过大小端的话，这里正好能接起来。

数值：

```text
0x0041
```

两个字节：

```text
高字节 = 0x00
低字节 = 0x41
```

小端：

> 低有效字节放低地址。

所以：

```text
低地址 → 高地址

41 00
```

同理：

```text
0x4E2D
```

拆成：

```text
高 = 4E
低 = 2D
```

小端：

```text
2D 4E
```

------

## 11. UTF-16 BE 又是什么？

<span style="color:#FF0000; background:#00FF80;">BE：</span>

```text
Big Endian
大端
```

<span style="color:#FF0000; background:#00FF80;">就是高字节先放。</span>

所以：

```text
A = 0x0041
↓
00 41

中 = 0x4E2D
↓
4E 2D
```

视频里对应：

```text
FE FF 00 41 4E 2D
```

其中：

```text
FE FF
→ UTF-16 BE BOM
```

于是：

```text
UTF-16 LE：
FF FE 41 00 2D 4E

UTF-16 BE：
FE FF 00 41 4E 2D
```

这一组最好成对记。

------

## 12. BOM 是什么？

BOM：

```text
Byte Order Mark
```

可以粗略理解成：

> <span style="background:#00FF80; color:#FF0000;">**文件开头的“编码提示标记”。**</span>

例如视频中的：

```text
UTF-16 LE
FF FE
UTF-16 BE
FE FF
```

UTF-8 有时也会出现：

```text
EF BB BF
```

所以视频 **14分钟左右** 展示：

不带 UTF-8 BOM：

```text
41 E4 B8 AD
```

带 BOM：

```text
EF BB BF 41 E4 B8 AD
```

其中：

```text
EF BB BF
```

不是正文字符“A中”。

它只是编码标记。

------

## 13. <span style="background:#00FF80;">UTF-8为什么最常见？</span>

因为它是<span style="color:#FF0000; background:#00FF80;">**变长编码**。</span>

意思是：

> <span style="background:#00FF80; color:#FF0000;">不同字符可以占不同字节数。</span>

比如：

```text
ASCII字符
→ 1 Byte

部分字符
→ 2 Byte

中文等常见字符
→ 3 Byte

部分更高码点字符
→ 4 Byte
```

比如：

```text
A
↓
0x41
```

UTF-8仍然：

```text
41
```

只需要1字节。

而：

```text
中
```

需要：

```text
E4 B8 AD
```

3字节。

所以：

```text
"A中"
```

UTF-8存储就是：

```text
41 E4 B8 AD
```

一共：

```text
4 Byte
```

------

## 14. 为什么 `中` 会变成 `E4 B8 AD`？

这是视频后半段最重要的原理。

`中`：

```text
Unicode：
U+4E2D
```

二进制表示以后，把有效位按照 UTF-8 三字节格式装进去：

```text
1110xxxx 10xxxxxx 10xxxxxx
```

最终得到：

```text
11100100 10111000 10101101
```

转十六进制：

```text
E4 B8 AD
```

所以：

```text
U+4E2D
↓ UTF-8
E4 B8 AD
```

反过来软件看到：

```text
E4 B8 AD
```

<span style="color:#FF0000; background:#00FF80;">也能按 UTF-8 规则还原出：</span>

```text
U+4E2D
↓
中
```

------

## 15. UTF-8为什么能知道一个字符用了几个字节？

这也是它设计得很巧的地方。

看第一个字节的高位。

例如：

```text
0xxxxxxx
```

表示：

```text
1字节字符
```

例如：

```text
41
=
01000001
```

所以直接知道：

```text
这是单字节
```

------

如果：

```text
110xxxxx
```

表示：

```text
总共2字节
```

后续字节形如：

```text
10xxxxxx
```

------

如果：

```text
1110xxxx
```

表示：

```text
总共3字节
```

例如：

```text
E4
=
11100100
```

开头：

```text
1110
```

说明：

> 后面还要再取两个字节。

于是：

```text
E4 B8 AD
```

三个字节一起解析成：

```text
中
```

## 16. 所以文件里根本不存在“中”这个东西

这个理解很重要。

假设你创建：

```text
test.txt
```

里面写：

```text
A中
```

如果是 UTF-8：

硬盘里真正保存：

```text
41 E4 B8 AD
```

不是：

```text
A 中
```

所谓：

```text
A
中
```

只是文本编辑器读取字节后：

```text
读取
↓
按照UTF-8解释
↓
得到Unicode码点
↓
再去字体库找到字形
↓
显示在屏幕
```

完整过程其实是：

```text
文件中的字节
41 E4 B8 AD
        ↓
UTF-8解码
        ↓
U+0041
U+4E2D
        ↓
字体库
        ↓
A 和 中 的字形
        ↓
转换成像素
        ↓
Framebuffer
        ↓
LCD
```

你看，这一下甚至和上一节 Framebuffer 接起来了。

## 17. 字符编码和字体还不是一回事

这节虽然重点是编码，但你马上会遇到：

```text
编码
≠
字体
```

比如：

```text
U+4E2D
```

只是告诉系统：

> 我要显示字符“中”。

但屏幕最终要显示的是像素：

```text
████
  ██
████
...
```

<span style="color:#FF0000; background:#00FF80;">这些像素长什么样，要靠：</span>

```text
字体文件
```

比如宋体、黑体等。

所以完整关系：

```text
字符
↓
Unicode码点
↓
UTF-8字节
↓
程序解码
↓
Unicode码点
↓
字体库查字形
↓
得到像素矩阵
↓
Framebuffer
↓
LCD
```

这是你接下来“文字显示到 LCD”最重要的一条链。

## 18. ANSI 该怎么理解？

视频前面还提到了 ANSI。

这里你最好不要把 ANSI 理解成：

```text
一种全世界统一的固定编码
```

在 Windows 语境里所谓“ANSI文本”，往往是：

> 根据系统当前代码页选择的一套本地编码。

比如中文 Windows 历史上常见：

```text
GBK / CP936
```

而其他语言环境可能完全不同。

所以：

```text
ASCII
→ 固定基础字符集

ANSI
→ Windows语境下常指当前本地代码页编码

Unicode
→ 全球字符编号标准

UTF-8/UTF-16
→ Unicode的具体编码方式
```

这样理解更准确。

## 24. 你这节最应该重点掌握的不是“背编码表”

真正需要弄清楚的是下面这四层：

```text
第一层：字符
A
中

第二层：码点
A   → U+0041
中  → U+4E2D

第三层：编码方式
UTF-8
UTF-16LE
UTF-16BE

第四层：实际字节
A UTF-8   → 41
中 UTF-8  → E4 B8 AD
```

只要这四层不混，以后乱码问题就好理解很多。

## 25. 和你前面学习的“内存”概念连起来

比如 C 程序：

```c
char str[] = "A中";
```

假设源文件是 UTF-8，并且编译后字符串保持 UTF-8：

内存里可能就是：

```text
地址        数据

0x1000      41
0x1001      E4
0x1002      B8
0x1003      AD
0x1004      00
```

最后：

```text
00
```

是 C 字符串结束符：

```c
'\0'
```

所以：

```c
strlen("A中")
```

在 UTF-8 情况下很可能得到：

```text
4
```

而不是：

```text
2
```

为什么？

因为 `strlen()` 数的是：

> **字节数**

不是：

> **人眼看到的字符数量**

这会是你以后 C/Linux 字符处理特别容易踩的坑。

### 一句话记忆

> **Unicode回答“这个字符编号是多少”，UTF-8/UTF-16回答“这个编号到底用哪些字节存进内存或文件”。**

而如果再和上一节 Framebuffer 连起来，整个文字显示过程就是：

```text
文件中的 UTF-8 字节
↓
解码得到 Unicode
↓
根据 Unicode 找字体里的字形
↓
把字形转换成像素
↓
写入 Framebuffer
↓
LCD显示字符
```

这其实就是后面“在 LCD 上显示文字”的完整底层逻辑。
