linux中对内核的移植与裁剪其实就是对Kconfig、config、Makefile这三个文件的改变。

linux内核（linux内核就是为linux操作系统的）的源码是可以在网上下载的，去网上下载的是为一个压缩包的，这个压缩包里面的东西就是为linux内核的源码的。在网上下载的linux内核是有多个版本的，其中2.4.10--zip、2.6.11--zip中的4和6表示的是所下载的linux内核的版本号（偶数表示的是为稳定的版本的，故一般下载的是为偶数的版本的），而zip表示的是这个内核的压缩包（这个压缩包里面的内容就是为linux内核的源码的目录结构的）。

Windows操作系统与linux操作系统的区别：Windows上下载的一般就是为安装程序的，而在linux上下载的一般是为源码的。

在网上下载的一个linux内核的根目录下是有一个Makefile文件的，进入到这个linux内核的根目录下执行make命令就会执行这个makefile文件生成一个总目标，这总目标就是为linux内核（linux操作系统）的一个镜像文件的，将这个镜像文件加载到一台设备中时就相当于是为这台设备安装了一个linux操作系统（这个镜像文件是为一个二进制文件的，加载到一台设备中后这台设备就可以直接运行这个二进制文件了）。

直接在网上下载的一个linux内核的根目录下通过make命令来执行默认的那个Makefile文件得到的是一个台式机、PC机的linux内核（linux操作系统）的镜像文件的（这个镜像文件是应该下载到PC机上的，即这个镜像文件的运行环境是为PC机的）。
如果我们不是想要生成PC机的linux的镜像文件的话，就需要改变linux默认根目录下的Makefile文件，对这个makefile文件做适当的裁剪，去除掉一些不必要的模块（即是取出掉一些功能）或者增加一些模块（此时需要在makefile文件中添加相应的指令来生成这个模块），这样通过make命令执行这个经过裁剪后的makefile文件所生成的镜像文件就是目标设备的镜像文件，将这个镜像文件下载到目标设备上就相当于是为这个目标设备安装了一个linux操作系统。（这里的目标设备是为除了PC设备的其他设备的，如一些嵌入式的设备，如树莓派，做实验时用到的目标机）
注意：根目录下的Makefile文件一般情况下是改变不了的，这是因为在linux内核的根目录下默认的那个Makefile文件中的执行语句的命令一般都是用变量来代替的，即是在一个makefile文件中是有大量的变量的，而变量的值是定义在“config”文件中的（这个“.config”文件是为linux内核的根目录下的一个隐藏文件的，其中“.”表示的就是为隐藏的意思的），我们是通过改变config文件中的变量来完成对Makefile文件的修改的（如对定义成gcc的变量修改为arm-linux-gcc，将指示某一个文件名称的变量修改为另一个文件的名称）。但是由于大多数的人员对linux的内核都不是非常的清楚，故在我们所下载的这个linux内核的原码中是已经提供了一些已经修改过了的“config”文件的，这些已经修改过了的“config”文件是存放在所下载的linux内核的源码中的“./scrips”目录下面的，这个目录下面的文件就是为对linux内核进行配置的一些脚本文件的，这些脚本文件就是为“config”文件的。我们需要做的就是找到与目标机最适配的那个“config”文件，复制其到linux内核的根目录下面替换掉原来的那个“config”文件就可以了。

注意：如果当前设备的操作系统已经是为linux的操作系统的话，则就不需要再去网上下载linux内核源码的压缩包了，直接在“/user”这个目录的下面就能够找到linux内核的源码了。

linux内核的移植与裁剪其实就牵涉到了三个重要的文件，分别是为Kconfig、.config、Makefile文件的。下面逐个地对这3个文件的作用进行相关的说明：
(1)“Kconfig”文件：
Kconfig文件就是为一个菜单化的图形界面的，这个菜单化的图形界面对应了一个Kconfig文件，
其中Kconfig文件包含了3个部分，分别为config条目（entry）、menu条目、source（打开一个Kconfig文件之后就可以看到这3个部分了）。
在每一个目录的下面都是有一个Kconfig文件的，若这个目录的下面有多个子目录，则在每一个子目录的下面也是都有一个Kconfig文件的。

(2)“.config”文件（前面的“.”表示这个文件是为一个隐藏文件的）：
这个config文件中的内容是为大量的变量的，每一个变量都对应了一个模块（变量名称为“CONFIG_对应模块名称”），每一个变量的取值可能有3个（在Konfig文件中对应的那个config条目中是为tristate，表示3个状态）或者是为2个的（在Kconfig文件中对应的那个config条目中是为bool，表示2个状态）。当为3个状态时，变量的值只能够是从“y”（编译进内核）或者“n”（不进行编译）或者“m”（编译成模块）这3者中选择一个的，当为2个状态时，变量的值是只能够从“y”（编译进内核）或者“m”（编译成模块）这2者中选择一个的。

注意：每一个目录的下面都是有一个“Kconfig”文件和一个“.config”文件的，一个目录下面的“Kconfig”文件就表示了这个目录下面的一些功能模块的菜单化的图形界面（一个功能模块一般是对应了一个.c文件的，这个目录下面有多少个功能模块则在这个Kconfig文件对应的菜单中就会有多少个菜单项的）。

(3)“Makefile”文件：
在linux内核的根目录下面执行make命令会生成一个总目标，这个总目标是为一个.image的镜像文件的，由于这个Makefile文件是由大量的变量所组成的，故在使用“make”命令执行这个Makefile文件的时候会去从config文件中来读取这些变量的值的，根据这些变量的取值来选择编译的情况，如果这个变量的值是为“y”的话则是会将其编译进内核的，成为内核的一部分，如果这个变量的值是为“n”的话则是不会对这个模块来进行编译的，如果这个变量的值是为“m”的话则是会将这个模块编译成为一个模块的（对应生成一个.ko的文件）。一个变量就是对应一个模块的（每一个模块都是有一个名称的，这个名称就是为一个变量的名称的），执行这个Makefile文件的时候是会根据这个变量的取值来决定所对应的模块的编译情况的。(如果有模块要单独的编译成为一个模块的话，即是这个模块对应的变量值被赋值为了m，则此时执行make命令不仅会生成一个.image的镜像文件，还是会生成一个.ko的模块文件的)

Kconfig文件中知识：
(1)config条目的结构如下（所谓的条目的意思就是在这个Kconfig文件中是有很多条类似于这样的语句的）：
config DM9000
	tristate “DM9000 support”
	depend on ARM || BLACKFIN || MIPS
	select CRC32
	select MII
	Help
	Support for DM9000 chipset.
	To compile this driver as a module
	To module will be called dm9000
分析：这是为一个驱动模块DM9000的config条目的，其中tristate设置这个DM9000模块是有3个状态的，分别为y（编译进内核）、n（不进行编译，也就是不选用这个功能）、m（编译成一个模块）
，如果为bool则设置的就是这个模块是由两个状态的，分别为y（编译进内核）、n（不进行编译）。tristate后面的名字就是为这个模块所对应的菜单界面中的菜单项的名字的，对这个“DM9000 support”按空格的可以在那三种状态之间进行切换。depend on表示的是必须后面的“ARM模块”或者“BLACKFIN模块”或者“MIPS模块”三个模块之中有一个被选中这个“DM900”模块才可以被选中，即是只有这3个有一个为“y”或者“m”时这个“DM900”才可以为“y”或者“m”的状态。Select表示的是默认选中的一些模块，这里默认选中的模块是为“CRC32”和“MII”的。Help表示的是对这个模块功能的一些说明的，后面的说明语句是自定义的。

问题：config条目如何影响config文件、config文件是如何影响Makefile文件的、config条目如何影响menu条目？
在一个Kconfig文件中最重要的就是为这个config条目的，在一个Kconfig文件中往往是有多个config条目的，一个config条目就对应了一个模块，在Kconfig文件中增加一个config条目时就会在对应的“config”文件中增加一个变量的（每一个目录的下面都是有一个“Kconfig”文件和一个“.config”文件的，对“Kconfig”文件的改变，准确的说是对“Kconfig”文件中的“config条目”的改变会影响到这个“Kconfig”文件所对应的“.config”文件的，也是会影响到这个“Kconfig”文件中的“menu”条目的），这个变量的名字就是为“CONFIG_对应的模块名”，注意，这里的模块名是为“config”后面的，而不是为“tristate”后面的，这个变量的值被赋值为了“y”（编译进内核）或者“n”（不进行编译）或者“m”（编译成一个模块）的。在Makefile文件中是以追加的方式来引用这个变量的，如 obj_$(CONFIG_DMA9000)+=dm9000，如果CONFIG_DMA9000是为“y”的话则相当于是在obj_y的后面追加了一个“dm9000”的，如果“CONFIG_DMA9000”是为“n”的话则相当于是在obj_m的后面追加了一个“dm9000”的，如果CONFIG_DMA9000是为“m”的话则相当于是在obj_m的后面追加了一个“dm9000”的，即是在Makefile文件中，obj_y就列出来了所有要编译进内核的模块的，obj_n就列出来了所有不需要进行编译的模块的，obj_m就列出了所有要编译成为一个单独的模块（即是独立于linux内核，这个模块被单独的编译成了一个.ko的文件）的模块的，此时Makefile文件就可以根据obj_y、obj_n、obj_m这三个变量来对linux内核提供的一些模块进行有选择性的编译了，编译这个Makefile文件后最终会生成一个“zimage”的内核的镜像文件，以及若干个“.ko”文件的（obj_m中列出来了多少个模块就会生成多少个“.ko”文件的，每一个“.ko”文件就对应了一个模块）。修改Kconfig文件中的config条目时可能是会影响这个Kconfig条目中的menu条目的，在一个Kconfig文件中也是若干个menu条目的，每一个menu条目对应了菜单界面中的一个菜单项，每一个菜单项都是有一个名字的，一个Konfig文件中的menu条目就是用来列举一个菜单界面中的所有菜单项的，每一个“menu：”后面的内容就是为所对应的那个菜单项的名字的，这个菜单项的名字就是所对应的那个config条目中的tristate后面的字符串的（每一个菜单项就是为一个模块的，故每一个菜单项都是对应有一个config条目以及menu条目的）就是为这个菜单项的名字，也即是所对应的“menu：”后面的内容的，故当修改了一个Konfig文件中的“tristate”后面的内容时是会修改对应的那个“menu：”后面的内容的。
注意：一个菜单化的图形界面中的每一个菜单项都是对应有一个模块的，但是这个菜单项的名字和所对应的那个模块的名字却是不一样的，菜单项的名字为config条目中tristate后面的字符串，为meun条目后面的内容，但是模块的名字是为一个config条目中的config后面的内容的（在一个config文件中生成的变量名称是与模块名称向对应的，而不是与这个模块所对应的菜单项的名称相对应的，这一点要注意）。

(2)menu条目：
在一个Kconfig文件中是有若干个menu条目的，这个Kconfig文件对应了一个菜单化的图形界面，这个菜单化的图形界面是有若干个菜单项的，每一个菜单项都是有一个名字的，而一个Kconfig文件中的menu条目就相当于是列出了这个菜单化的图形界面中的每一个菜单项并指明了每一个菜单项的名字。

(3)source条目:
在一个Kconfig文件中是有若干个source条目的，由于这个Kconfig文件所在的目录下是有若干个子目录的，每一个子目录的下面都是有一个Kconfig文件的，表示了一个图形话的菜单界面，可以认为当前目录下面的这个Kconfig文件是为一个总的菜单图形化的界面的，其是由若干个子菜单图形化界面组成的每一个子菜单的图形化界面所在的子目录都是不一样的，这个source条目就是用来指明每一个子Kconfig文件（子菜单图形化界面）的目录的，这样就相当于是这个Kconfig文件包含了所有的子Kconfig文件的，即是这个菜单式的图形化界面包含进了若干个子菜单式的图形化界面。

linux内核的运行说明：
（1）在linux内核的根目录下执行“make menuconfig”命令时会生成一个菜单界面，通过对这个菜单界面中的一些菜单项（条目）进行选择性的勾选就能够对linux的内核进行相关的配置了（linux内核中的一个功能就是为一个模块的，一个模块就对应了菜单界面中的一个菜单项，将需要编译进linux内核的功能模块所对应的菜单界面中的菜单项勾选上，这样在执行“make”命令时就会将所勾选上的菜单项所对应的功能编译进linux内核中了）。
（2）在linux内核的根目录下执行“make menuconfig”命令生成一个菜单界面时有一些菜单项是会被默认选中的（执行“make menuconfig”命令时会根据linux内核根目录下面的“.config”文件来确定出菜单界面中的哪些菜单项被选中，哪些菜单项没有被选中），即是“.config”文件会影响所生成的菜单界面；当对菜单界面中的菜单项进行勾选或者取消勾选时反过来也是会影响“.config”文件的，会自动的删除掉“.config”文件中的一些变量或者增加一些变量的（当勾选了菜单界面中的某一个菜单时就会在“.config”文件中增加一个变量，当取消勾选菜单界面中的某一个菜单时就会在“.config”文件中删除掉一个变量）。
（3）在linux内核的根目录下面的Makefile文件中是有大量的变量的，在linux内核的根目录下面通过“make”命令执行这个Makefile文件的时候是会自动的去“.config”文件中来查找相应的变量的值的，这样通过改变“.config”文件就间接的完成了修改“Makefile”文件的任务了，在linux内核的根目录下面执行“make”命令就会执行这个Makefile文件生成一个“zimage”的镜像文件。

图示：
     Kconfig -----（make menuconfig）-----> menu<------（read）-------  config  -------（read）-------->Makefile -----（make）-----> zimage
                                                                                   -------（write）------>
分析：在linux内核的每一个目录的下面都是有一个Kconfig文件的（用来表示当前目录下的文件所提供的一些功能的菜单配置界面），在linux内核的根目录下面的那个Kconfig文件是为总的菜单配置界面的（这个菜单配置界面对应了这个Kconfig文件，菜单配置界面中的菜单项对应了Kconfig文件中的menu条目），在linux内核的根目录的下面运行“make menuconfig”命令会生成一个菜单界面（图形化的界面），这个菜单界面会从linux内核的根目录下面的“config”读取相关的变量来默认选中菜单界面中的一些菜单项（即是在生成这个菜单界面的时候是已经有一些菜单项是被默认给选中的），当在生成的这个菜单界面中勾选某一个菜单项或者取消勾选某一个菜单项的时候会同时的在“config”文件中生成一个变量，Makefile文件会读取到这个变量的值，这样在linux内核的根目录下面执行make命令就会运行这个已经修改过了的Makefile文件生成一个目标文件，这个目标文件就是为一个镜像文件zimage的。
