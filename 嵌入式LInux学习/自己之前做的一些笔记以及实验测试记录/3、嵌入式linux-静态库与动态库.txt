关于库文件的一些知识：
1、开发者把写好的功能代码封装到一个文件里面，提供接口给用户使用，该封装好的文件就是库文件。例如我们熟悉的计算机视觉开源库（OpenCV），里面集成了大量写好的功能函数库，用户可以通过相应接口调用。

2、在Linux系统中看到的所有以 .so 或 .a 结尾的文件都是库文件，其中.so是动态库的库文件，.a是静态库的库文件。

动态库的制作（说明）：
1、编写源代码与接口说明文件，源代码其实就是.c文件，接口说明文件就是.h文件。
用户调用动态库中的一些功能函数其实就是用户在自己所写的程序中调用动态库中的这些功能函数，用户调用动态库中的一些功能函数时必须要有一个接口，动态库提供给用户调用其提供的一些功能函数的接口就是这个动态库所关联的那个头文件，即是用户在自己所编写的程序中包含了该头文件后就能调用这个动态库所提供的一些功能函数了。

2、把若干个.c文件通过linux系统中提供的一些指令编译成若干个.o文件（一个.c文件对应了一个.o文件）。注意，一个.c文件中是可以包含多个功能函数的，即是一个.c文件就可以定义若干个功能模块，在一个.c文件中不只是可以定义功能函数的，也是可以定义若干个类的，这样当在用户自己所写的程序中包含了这个动态库的接口说明文件时就可以利用这个动态库中的类来定义特定的对象了，即是一个.c文件可以包含若干个功能函数，包含若干个类。

3、编译成若干个.o文件的那若干个.c文件中的每一个.c文件都是这个动态库的功能模块的一部分，这若干个.c文件共同组成了这个动态库的完整的功能（由于一个动态库对应了一个接口，用户必须通过这个接口来调用这个动态库中的一些功能，这个接口是唯一的，因此这多个.c文件也是共用同一个接口的，即是这若干个.c文件对应的头文件时唯一的，即是在这若干个 .c文件的开头使用#include所包含的那个文件的名字都是一样的 ）。虽然这若干个.c文件共同组成了这个动态库，但是在linux系统中却并不能直接将这若干个.c文件链接成一个动态库，在linux系统是只能将这若干个.c文件所对应的.o文件链接成一个动态库的。

动态库的制作的指令：
1、编写若干个组成这个动态库的功能模块，即是若干个.c文件（注意在这若个.c文件的开头使用#include包含的是同一个头文件名，即这若干个.c文件对应的是同一个接口）。

add_1.c :
#include "math_1.h"  //add_1模块对应的math.h这个接口（通过这个接口可以调用这个add_1中的一些功能）
int add_1(int a,int b)
{
   return a+b;
}

add_2.c :
#include "math_1.h"  //add_2模块对应的math.h这个接口（通过这个接口可以调用这个add_2中的一些功能）
double add_2(double a,double b)
{
   return a+b;
}

2、编写接口说明文件，即是编写头文件（对于一个动态库来说是只有一个头文件，但是却可以有若干个.c文件的）。
这里编写的是“math_1.h”这个接口说明文件的。
int add_1(int a,int b);
double add_2(double a,double b);

3、将若干个.c文件编译成若干个.o文件。
使用指令：  gcc -fpic -c add_1.c add_2.c -o add_1.o add_2.o（其中-fpic是可以用也可以不用的，目的都是生成.o文件，不过使用-fpic表明所使用的是相对地址，即是可以提高编译的效率的）

4、将这若干个.o文件打包成一个动态库。
使用指令：  gcc -shared -fpic -o libadd.so add_1.o add_2.o（同样-fpic也是可有可无的）
注意：libxxx.so中的xxx是所创建的这个动态库的名称的，这个xxx动态库对应了一个接口，这个接口就是为"math_1.h"的。

5、用户来调用，即是用户在自己所写程序中使用接口#include "math_1.h",然后就能够在用户自己所写的程序中使用动态库libadd.so中的一些函数或者类了。

6、用于编译、链接、运行自己所写的程序host_serial.c。
编译链接时的指令： gcc -c main.c -I ./add -L./add  -ladd -o main
/*
编译链接时指令参数的说明：
注意：源程序.c文件经过-c的编译后会生成一个.o的目标文件，这个目标文件也就是二进制文件，这个二进制文件的后缀名为.o，经过-o的链接后才会生成一个可执行文件。

-L ：指定库文件的所在路径，其中.表示的是当前路径，也可一在后面用 / 来指明某一个路径。（这里所说的库文件所在的路径指的就是打包成的动态库文件，即是libadd..so这个文件所在的路径，即是用户自己的程序中的那个接口所对应的库函数的位置）
-I ：用户在自己的程序中使用接口后，指明用户自己的程序去哪里来寻找这个接口（头文件），当使用 "" 来调用这个接口时，默认是在当前的目录下来查找这个接口（头文件的），当使用<>来调用这个接口时，默认是在系统的目录下（即是linux内核的lib目录中）来查找这个接口的。如果接口文件即不在当前目下,又不在系统默认的目录下的时候，此时可以通过-I 来指明这个接口文件所在的目录，这样当程序编译的时候就会自动的去通过-I所指明的那个目录下去查找接口文件。       

-l（上面那个是大i，这里是小l）：l后面指明要连接的库的名称，这样在编译的时候就会将指明的这个库中的一些功能模块一起编译成目标代码（注意在动态库中所编译成的用户源程序中的目标代码与这个源程序中包含的动态库中的一些目标代码是分开存放的）。

注意：在动态库中是没有将用户程序中的头文件（接口）中的一些东西给编译进目标代码里面的，而是在程序执行的时候当遇到这个库中的一些功能模块时就会去系统中专门存放函数库的目录下去查找，这个目录为/usr/lib，因此要想成功运行使用了动态库的用户的源程序，在这个/usr/lib 下面就必须有用户自己所打包好的那个动态库，可以将这个用户自己所打包好的动态库移动到那个目录下面去或者拷贝一份到那个目录下面去的。
*/

执行时的指令：        ./serial_out（执行时一般要先执行 cp libadd.so /usr/lib）

注意:可以配置动态库的环境变量为 LD_LIBRARY_PATH=. ，即是在终端中输入‘’export  LD_LIBRARY_PATH=.‘’  ,这样的话当在程序中使用动态库时就会自动到所指定的那个目录下去查找这个动态库的文件。

格式说明：一般的话就将动态库专门放到一个文件夹中，配置动态库的环境变量为这个目录，另外接这些动态库所对应的接口（即是头文件）专门放到一个文件中，在编译时使用-I指令来寻找这个目录，这样就可以编写属于自己的库了，在程序中就可以直接调用自己所编写的若干个库中的功能了。

静态库制作的指令：
1、这个静态库的组成中包括了多个.c文件和一个.h文件，将这多个.c文件编译成.o文件。
2、将这多个.o文件打包成一个静态库就行了。
ar  -rc libsub.a sub.o
其中ar表示打包的意思,libxxx.a中的xxx也就是这个静态库的名字的。
3、将用到了该静态库的用户自己的源程序main.c编译成一个main的可执行文件。
gcc -I /add -main.c -L.  -ladd -o main

动态库与静态库的区别：动态库中的一些功能模块（函数）在编译时是没有编译进用户代码里的，而是在执行的时候自动到所指定的目录中去查找这个动态库中的一个功能模块的；静态库在编译时是已经将一些功能模块（函数）给编译进目标代码中了。

动态库的优缺点： 不会影响目标程序的体积，而且同一份库可以被多个程序使用（因为这个原因，动态库也被称作共享库）。同时，编译时才载入的特性，也可以让我们随时对库进行替换，而不需要重                             新编译代码。动态库带来的问题主要是，动态载入会带来一部分性能损失，使用动态库也会使得程序依赖于外部环境。
静态库的优缺点：目标程序没有外部依赖，直接就可以运行。其缺点也很明显，就是会使用目标程序的体积增大。

补充：接口文件（.h头文件）只有define和函数的声明，不能包含有头文件的一些操作，如在头文件中是不能够包含有#include""和#include<>的语句的，这些语句是写在头文件所对应的.c文件中的。
