在linux内核中会自带一些驱动程序的，这些驱动程序是编译进了内核里面的。在购买一些运行linux操作系统的设备时厂商还可能会一些驱动程序，这些驱动程序提供的驱动程序是为一个个.ko文件的，这些驱动程序程序是没有被编译进内核的，要对其进行加载到内核中才能够驱动对应的硬件设备的。（当然也是可以自己编写一些硬件设备的驱动程序，比如说自己编写一个.ko文件，这个.ko文件是为一个键盘的驱动程序，自己再买一个键盘，在需要使用键盘的时候将键盘的驱动程序加载到内核中去，在不需要的时候再将其从内核中给卸载掉就行了）。
在linux中是一切皆文件的，将对各种硬件设备的操作都转换为了对文件的操作，如计算机的屏幕就是为一个硬件设备的，这个硬件设备也是对应有一个文件的，对这个文件的操作就是对屏幕的操作。（如向文件中所写的数据就会在屏幕上锁显示出来）。

1、linux系统的设备分为了3类：字符设备、块设备、网络设备。

<1>字符设备：提供连续的数据流，应用程序可以顺序的从这个设备上来读取数据，但是应用程序通常不能从这个设备上进行随机的读取数据。应用程序可以按字节或者字符的方式从这个设备上来读取数据，或者按字节或者字符（字节和字符是为一个意思的，一个字符占一个字节，因此叫做字符设备）的方式来向这个设备上写数据。简单的说就是，设备与应用程序之间交换数据时以单个字节（字符）为单位，这样的设备称之为字符设备。

注意：上述修改一下，字符设备可以以单个字节为单位来进行读取，也可以是以多个字节为单位来进行读取的。

举例：如串口、并口、USB口都是典型的字符设备，这类设备可以提供连续的数据流（像这些什么口的提供的数据肯定是连续的，数据像水流一样的），应用程序可以从这些设备上来读取数据，且读取数据的时候是按照顺序读取的（数据肯定是按照串口的顺序一个接着一个来进行传输的），应用程序通过串口读取数据时一般都是按照字节为单位来进行读取的（联想到我们学过的单片机的串口通信，每次发送和接收的都是为一个字节的），应用程序也可以向串口中传输数据，向串口中传输数据时也是按照字节为单位来进行传输的（即就是我们单片机上的主机通过串口向单片机来进行通信，主机每次发送的是为一个字节的，因为串口这个设备就是字符类型的设备，每次发送和接收都是为一个字节的）；如键盘也是典型的字符设备的，通过键盘向应用程序中输入数据时也是按照顺序的，且是以字符为单位（一个字符占一个字节），一个字符一个字符的向应用程序传送数据的，就像水流一样，因此，键盘也是为字符设备的。

<2>块设备：块设备支持随机存取，应用程序可以到块设备上的任何一个地方去取数据。块设备通常与应用程序交换数据时通常不是以单个字节为单位的，而是以多个字节为单位的，简单认为就是，不是字符设备的一般就是为块设备（网络设备和字符设备一般是比较好区分的）。
举例：磁盘就是典型的块设备，应用程序可以随机的从磁盘上来读取数据（采用虚拟内存技术），每次磁盘上读取的数据是可以为多个字节的，即应用程序与磁盘之间交换数据是以块为单位的。

2、设备驱动程序的相关说明（设备驱动程序一般是由自己来进行编写的，运行在linux操作系统的环境下的）：

<1>操作硬件简单来说就是操作对应地址的寄存器中的内容，而硬件驱动程序就是和这些寄存器打交道的。硬件驱动程序就是通过操作对应的硬件寄存器来直接的控制硬件设备的。
<2>在linux操作系统中每一种类型的硬件设备都有一个对应的驱动模块（驱动程序），如CPU有一个设备驱动模块、内存有一个设备驱动模块、磁盘有一个设备驱动模块、鼠标有一个设备驱动模块、键盘有一个设备驱动模块、网卡有一个设备驱动模块。
<3>在linux操作系统中每一个.ko文件就是为一个驱动程序，该文件的意义就是把内核的一些功能移动到内核外边， 需要的时候插入内核，不需要时卸载，这样可以简化内核。

<4>通过insmd命令来完成将一台设备的驱动程序加载到内核中的操作（由于这个.ko的驱动程序是编译成模块了，是没有编译进内核的，故要将这个.ko的文件加载到内核中去，这样才能通过这个驱动程序来驱动对应的硬件设备，因为开机的时候运行的是为操作系统程序的，只有将这个程序运行起来，也即是只有将这个程序加载内核中去才能够驱动对应的硬件设备的）。
insmd demo.ko   //实现将demo.ko这个驱动程序加载到内核中的操作。

分析：在所编写的设备驱动程序（.ko文件）中是有一个驱动的入口函数init_module和驱动的出口函数cleanup_module()，其中驱动的入口函数时在驱动模块加载（将.ko文件编译进内核）的时候被调用的，驱动的出口函数是在驱动模块卸载（将内核中的.ko文件给删除掉）的时候被调用的。执行insmd demo.ko是将这个demo.ko的设备驱动程序加载到内核中去，故会自动调用init_module（）函数，在这个函数中又执行了register_chardev（）函数，用来完成对这个设备驱动程序注册的工作，即是指明这个设备驱动程序对应的是为哪一种类型的设备的。执行rmmod demo.ko命令完成的是从内核中卸载这个设备驱动程序的工作的，此时会自动调用cleanup_module()函数，在这个函数中又执行了unregister_chardev()函数，用来完成从内核中卸载的这个设备驱动程序的任务（是通过指明的主设备号和设备名来判断出是要卸载哪一个设备驱动程序的）。

 
int register_chardev(unsigned int major,const char *name,struct file_operations *fops)
第1个参数：这个设备驱动程序向系统所申请的主设备号，如果为0则系统为此驱动程序动态地分配一个主设备号（即是这个设备驱动程序的主设备号由系统自动的进行分配）。
第2个参数：这个设备驱动程序所注册的设备的名称。
第3个参数：为一个结构体对象的地址，这个结构体对象中是有大量的函数指针的，结构体对象中的每一个函数指针都是为一个系统调用的，这些系统调用（为一个函数）是可以提供给用户程序来对设备进行相应的操作的，由于每一个函数指针都是可以指向一个自己定义的函数的，故系统调用（函数指针）需要实现的功能是需要自己来进行定义的（定义好了之后就可以提供给用户程序，用户通过调用这些系统调用，即是调用一些函数来控制设备的功能，如调用系统调用read()、open()、write()等）。
注意：如果为0的话，

int unregister_chardev(unsigned int major,const char *name)
第1个参数：设备驱动程序所定义的主设备号。
第2个参数：设备驱动程序对应的那一类设备的设备名（由于那一类设备的作用都是相同的，故这里为它们指定的设备名都是一样的）。

3、设备文件：
每一个设备都对应有一个设备文件，对这个设备文件的相关操作就是对这台设备的操作，设备文件就是为一个文件的结点（在linux中是一切皆为文件的），可以使用mknod命令来创建一个设备文件，所创建的这个设备文件必须与某一台设备相关联，是通过在使用mknod命令创建设备文件时所指明的主设备号和次设备号来指明这个设备文件是属于哪一台设备的。

主设备号与从设备号的说明：主设备号指明的是为某一类设备的，这一类设备是完全相同的，共享一个驱动程序。如主USB接口，在实验室的目标机上一共有4个，这4个USB接口是属于同一类的设备的。因此这4个设备的主设备号都一样，驱动程序也是都一样的，这4个设备共享一个驱动程序（不可能这4台设备的驱动程序都一样后还为这4台设备每一个装上一个驱动程序）。这4个USB接口是相互独立的，是通过次设备号来进行区分同类设备中的每一个具体的物理设备的。即主设备号表示的是为某一类设备，次设备号表示的是为某一个具体的物理设备。


<1>使用mknod命令创建了一个文件，并且将一个文件与一台设备相关联在了一起之后（通过创建文件的时候指明主设备号和从设备号来将一个文件与一台设备相关联），接下来对这个文件的读写操作就是对这台设备的读写操作了。 
mknod /dev/xxx c 100 0
分析：上述命令是在linux内核的根目录下面来执行的，根目录下面是有一个dev文件夹的，这个文件夹里面的内容就是设备文件的。创建了一个名称为xxx的（名称可以任意指定，而且不一定要放在dev目录下面，可以任意指定）设备文件，这个设备文件是存放在dev这个目录下面的，c表示了这个设备文件关联的是为一个字符设备的，100表示的是为这个设备文件对应的主设备号，0表示的是这个设备文件对应的次设备号，通过这个主设备号和从设备号就可以确定出这个设备文件对应哪台字符设备了。

注意：在linux操作系统中对设备文件的管理是放在“/dev”这个目录下面的，因此所创建的设备文件要放在这个目录的下面。

<2>创建好了一个设备文件之后就可以通过对这个设备文件的操作就是对这个文件对应的设备的操作，用户可以在一个.c文件中通过这些系统调用来对这个xxx文件进行操作，所进行的操作就是在设备驱动程序里面定义好的系统调用的，如open、read、write等，通过这些系统调用来对这个文件进行的操作就是对这个文件所对应的设备进行的操作。

总结：
通insmod命令来将一个.ko的驱动程序加载到内核中去，此时会自动调用init_module()函数，在这个函数中为这个驱动程序注册一台设备，register_chrdev(major, dev_name , &first_drv_fo)函数中的第1个参数就是为这个驱动模块所注册的设备主设备号（通过主设备号来决定为这个驱动模块注册是哪一种类型的设备的），第2个参数是所注册的这一类型的设备的名称的（是自定义的），第3个参数是为一个结构体变量，这个结构体变量中定义了大量的函数指针，这些函数指针是为系统调用的，这些系统调用是用来对设备进行驱动的，这些函数指针（系统调用）都是需要指向一个函数的，故是需要自己定义设备的功能的（通过定义相关的函数，再将结构体对象中的函数指针指向它就行了）；
此时需要使用mknod /dev/xxx c 55 0命令来为这台主设备号为55，次设备号为0的这台设备创建一个文件（那个目录是可以自己随便指定的，只不过一般将设备文件放在/dev/这个目录下），这个文件就会与这台设备相关联，对这个设备文件的操作就是对这台设备的操作了。 （在驱动程序，即.ko文件中注册的时候只指明了主设备号，在设备文件中则是既指明了主设备号，又指明了次设备号的，从这里也能看出所有类型相同的设备是共用一个驱动程序的，每一个设备文件对应了一个设备，对这个设备文件的操作就是对这台设备的操作的）；
在一个.c程序中通过定义的在设备驱动程序中定义的系统调用（一些函数）来控制驱动设备，在这个.c程序中通过系统调用对设备文件xxx的操作就是对设备的操作的；
在完成相应的功能后要进行卸载的任务，就是将内核中设备驱动程序给卸载掉，此时可以通过rmmod demo.ko命令来完成对设备驱动程序demo.ko的卸载工作，此时会自动调用module_exit()函数的，在这个函数中又调用了unregister_char()函数，完成对指明设备号和指明那一类型的设备的驱动程序的卸载的任务。

注意：通过insmod命令将.ko驱动程序编译进内核中的那些增加config条目修改Makefile文件的操作是由系统自动完成的，通过rmmod命令将.ko驱动程序从内核中卸载对config条目和Makefile文件修改的任务也是有系统自动来完成的。

扩展知识：
C语言中的struct是最接近类的概念，但是在C语言的struct中只有成员，不能有函数，但是可以有指向函数的指针，这也就方便了我们使用函数了。
如：
typedef struct student  
{  
    int id;  
    char name[50];   
    void (*initial)();  
    void (*process)(int id, char *name);  
    void (*destroy)();  
}student;  
      
void initial()  
{  
    printf("initialization...\n");  
}  
void process(int id, char *name)  
{  
    printf("process...\n%d\t%s\n",id, name);  
}  
void main()
{
   student s1,*s2;
   s2=(student *)malloc(sizeof(student));  /*结构体指针在使用前必须要使其指向一个对   象或者为其开辟出一段空间的。*/

   s1.initial=initial;                //为结构体对象s1中的函数指针赋值
   s2->process=process;     //为结构体指针s2中的函数指针赋值
  
   s1.inital();                         //执行对象s1中的函数指针inital所指向的函数

   s2->id=42; s2->name="aaaa";
   s2->process(s2->id,s2->name); //执行对象指针s2中的函数指针process所指向的函数
}
说明：在c语言中，定义了一个函数之后就会在内存中开辟出一段堆空间，开辟出的这一段空间所存放的就是为函数的原码的，函数名其实就是为一个常指针的，函数名这个常指针指向了所开辟出的那一段内存空间的起始地址。
执行函数的时候其实就是根据函数名这个指针变量来找到对应的内存空间的起始地址，从起始地址去执行的。
定义了一个函数指针，就可以为这个指针赋值了，给这个函数指针赋的值是为一个函数名的，即是对应函数的起始地址的。在赋值的时候要注意类型的一致性，即是int类型的函数名是只能够赋值给int类型的函数指针的，void类型的函数名是只能够赋值给void类型的函数指针的。
注意：由于定义的函数的函数名是为一个常指针的，常指针是不能够进行赋值的，故是不能够使一个函数名=另一个函数名的。
说明：在一个C语言的函数中如果指明的参数是为一个函数名的话则指明的就是这个函数的位置，执行这个函数就会转到这个函数名常指针指向的位置去执行的，即是去执行这个函数名所指示的那个函数的。
