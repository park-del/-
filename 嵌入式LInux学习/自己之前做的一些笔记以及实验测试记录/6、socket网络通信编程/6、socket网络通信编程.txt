socket网络编程：
socket是一种进程之间的通信机制，通过socket可以实现不同进程之间的通信，这里的进程指的可以是一台计算机上的不同进程之间的通信，也可以是不同计算机上的两个进程之间的通信，此时不同计算机上的两个进程之间的通信必须要通过一个媒介，这个媒介可以是网络，也可以是一些线路（即是必须通过网络来将两台计算机连接起来或者通过物理线路来将两台计算机连接起来）。

实现两台计算机上的进程之间的通信是属于计算机网络的传输层实现的功能，进程之间的通信可以使用端口号来进行，如果是一台主机上的两个进程之间的通信则可以是一个进程将要发送的数据发送到本台主机上的一个端口号中去，然后本台主机上的另一个进程从这个端口号中去取数据，这样就可以实现一台主机上的两个进程之间的通信了；如果是不台主机上的两个进程之间的通信则可以是一台主机上的一个进程根据所指明的ip地址将要发送的数据发送到另一台主机上中，然后根据所指明的端口号将要发送的数据发送到根据ip地址所确定的这台主机上的某一个端口号中去，这个主机上的某一个进程再从本主机的这个端口号中去取数据就行了，这样就实现了不同主机上的两个进程之间的通信了。

注意：一台主机上的前面的端口号一般都被本主机系统的一些进程给占用了，故要实现自己所编写的两个进程之间的通信时所指明的端口号要尽量的大。

关于socke通信的相关函数的说明：
1、创建套接字（文件）的函数socket()
int socket(int family,int type,int protcocol)
函数作用：
这个函数是用来创建一个套接字的，所谓的套接字其实就是为一个文件的，这个函数的返回值是为一个int类型的数据，这个int类型的数据是为这个套接字的标识的，即是为一个文件的文件描述符的（套接字的本质就是为一个文件，这个文件是有一个唯一的文件标识符的）。

函数中的参数的说明：
<1>第1个参数：函数中的第1个参数是用来选择所进行网络传输时所采用的的ip协议的，由于现在主流的还是ipv4协议的，故函数中的第1个参数一般是默认的，就默认选择ipv4协议就行了，对应的参数为AF_INET。
<2>第2个参数：这个参数是用来指明所采用的的套接字类型的，不同的套接字类型所采用的传输层的协议不同、是否支持面向连接、是否是可靠的传输也是不一样的。第2个参数默认采用的是SOCK_DGRAM,这个参数表示的所使用的传输层的协议是为TCP的，此时的套接字是可靠的（即是有差错检测机制），面向连接的（在两个进程进行数据传输之间必须要先建立连接，只有在建立链接之后才能够这两个进程之间才能够进行通信）。
<3>第3个参数：默认是为0。

函数的执行结果：
成功创建了一个套接字之后会返回这个套接字的标识符，这个套接字的标识符是为非负的值的，如果创建失败的话则会返回一个-1。

2、将一个套接字与一个端口绑定在一起的函数bind()
int bind(int sockfd，struct sockaddr *my_addr,int addrlen)
函数作用：
这个函数是用来将一个套接字与一个端口绑定在一起的，将这个套接字与一个端口绑定在一起后这个进程就可以通过这个套接字来与其他的进程进行通信了（第1个参数表示的是为一个套接字的，第2个参数表示的是为一个端口的），绑定之后这个套接字就对应了一个端口，由于套接字的本质是为一个文件的，故是可以对这个文件进行读写操作的，当本进程对这个套接字进行写操作的时候就相当于是
往这个套接字所对应的端口发送数据，当本进程对这个套接字进行读操作的时候就相当于是从这个套接字所对应的端口中来去读数据。(要注意，当某一个进程要与其他的一个进程进行通信时就必须在这个进程中创建一个套接字，并将这个套接字与要进行通信的那个进程的主机上的某一个端口绑定在一起)

两台主机上的进程进行通信时需要两个套接字，这两个套接字绑定了一个端口，这个端口可以是这两台主机上的任意一个空闲的端口，两个进程都是可以向这个端口中发送数据或者向这个端口中读取数据的。（是否会发生冲突？如果冲突的话则需要一个进程需要定义两个套接字，其中一个套接字用来发送数据，另一个套接字用来接收数据，且发送数据的套接字所对应的端口可以是为本台主机上的一个端口，也可以是另外一台主机上的一个端口；而实现接收数据的套接字一般只能够为本台主机上的某一个端口。因为发送数据时是可以将数据发送到另外一台主机上的某一个端口中的，而接收数据时本台主机上的某一个进程是只能够从本台主机上的一个端口中来接收数据的，而不能够从另外一台主机上的某一个端口中来接收数据）

函数中的参数说明：
<1>函数中的第1个参数是为一个套接字的标识符的（即就是一个文件的标识符的）。
<2>函数中的第2个参数是用来确定是哪一台主机上的哪一个端口的，函数中的第2个参数是为一个struct sockaddr类型的结构体指针的，这个结构体指针所指向的一个struct sockaddr类型的对象就是为一个端口的，即这个结构体指针就是指向一个端口的。（结构体struct sockaddr包含了有两个数据成员，其中的一个数据成员是为unsigned short sa_family的，sa_famliy是为一个可选值，是用来选择所采用的ip协议的，当为AF_INET表示所采用的是为ipv4协议的；另一个数据成员是为char sa_data[14]的，sa_data[14]是用来存放一个ip地址和一个端口号的，通过一个ip地址和一个端口号就可以找到某一台主机上的某一个端口了，通过ip地址来找到网络中的某台主机，这台主机上可能是有多个端口的，通过端口号就可以找到这台主机上的某个端口了，因此可以认为一个struct sockaddr的对象就是一个端口，指向了一个struct sockaddr类型的对象的指针就是指向了一个端口的指针）
<3>函数中的第3个参数就是为第2个参数的长度的，准确的说就是为这个struct sockaddr类型的指针所指向的对象的长度的，即函数中的第3个参数就是为sizeof(struct sockaddr)的。

注意：还有一种结构体struct sockaddr_in,这个结构体与struct sockaddr的作用是一样的，只不过struct sockaddr_in这个结构体把char sa_data[14]分为了两部分，其中一部分为unsigned short int
sin_port,是用来表示一个端口号的，另一部分为struct in_addr sin_addr,是用来表示一个ip地址的。将ip地址与端口号分开之后操作会更加的方便，可以通过直接对sin_port和 sin_addr赋值来确定好某一台主机的某一个端口，此时本进程就可以通过对套接字的写操作（这个套接字已经绑定了一个struct sockaddr_in对象，且这个struct sockaddr_in对象已经被赋好了ip地址和端口号）来将数据发送到这个套机字所绑定的这个struct sockaddr_in对象所指明的那台主机上的一个端口中去了，那台主机上的某一个进程就可以通过对套接字的读操作（这个套接字也是已经绑定了一个struct sockaddr_in对象的，且这个对象的ip地址被赋值为本机的ip地址，这个对象的端口号被赋值为接收到数据的那个端口的端口号）来接收另一台主机上的某个进程所发送的数据了。另外，由于使用bind()函数时的第2个参数是为struct sockaddr类型所定义的一个对象的地址的，故在使用struct in_addr sin_addr类型所定义的对象sa作为实参时要进行一个强制类型转换的操作，即是（struct sockaddr *）&sa。

函数执行结果：
函数执行成功，即是成功的将一个套接字与一个进程绑定在一起的话这个函数会返回0，如果出错了的话则这个套接字是会返回-1。

3、本进程请求连接另一个进程的函数connect()
int connect(int sockfd，struct sockadd *serv_addr,int addrlen)
函数的作用：
这个函数中的套接字已经是与一个端口（本机的）绑定过了的，此时这个进程会发送一个连接请求给serv_addr所指明的那一台主机中的某一个端口。 （由于创建套接字sockfd时的第2个参数type指明了是为SOCK_STREAM,表示这个套接字时为面向连接的，故一个进程使用这个套接字来进行通信时必须要先建立连接）

函数参数的作用：
<1>第1个参数:函数中的第1个参数就是为一个套接字的，要注意这个套接字是已经与端口进行绑定过的，只有一个套接字与一个端口进行绑定过后这个进程才能够使用这个套接字来进行通信，否则的话就不能够使用这个套接字来进行通信。（此时本进程对这个套接字进行的读写操作就相当于是从这个套接字对应的端口中接收数据或者发送数据到这个套接字对应的端口中）
<2>第2个参数：函数中的第2个参数是为一个struct sockaddr类型的指针的，这个指针指向了某一台主机的某一个端口，本进程所发送的连接请求就会被发送到对应的那台主机上的对应的端口中。
<3>第3个参数：是为第2个参数的长度的，在使用时直接将其指定为sizeof(struct sockadd)就行了。

函数的执行结果：函数执行成功，即是本进程成功的发送一个连接请求到函数第2个参数所指明的那个端口中去时就会返回0，如果没有成功发送连接请求的话则是会返回-1。

4、监听函数listen()
int listen(servfd,LENGTH_OF_LISTEN_QUEUE); 
函数的作用：这个函数是为这个套接字servfd所对应的端口所允许请求的最大个数的，第2个参数就是用来指明这个请求的个数的，第2个参数可以指明为一个具体的数字来表示请求的个数的。
注意：执行这个函数时是不会被阻塞的，执行会被阻塞的函数只有两个，一个是为accept()函数，一个是为recv()函数的。 

函数执行结果：
函数执行成功，即是成功的为这个套接字servfd所对应的端口设置了允许请求的最大个数时会返回0，设置失败的话会返回-1。


5、本进程响应另一个进程所发送的连接请求的函数accept()
int accept(int sockfd,struct sockaddr *addr,socklen_t *addrlen)
函数的作用：
这个sockfd套接字也是已经与某一个端口绑定过了的（这个套接字所绑定这个端口就是为本台主机上的一个端口），本进程执行这个函数时就会从这个套接字所指明的那个端口（由于这个套接字一般绑定的是为本主机上的一个端口，故是从本主机上的一个端口中去接收连接请求的）中去接收连接请求。函数中的第2个参数会被赋值为发送连接请求的那个进程所绑定的端口的。（要注意这里的第2个参数是没有被事先赋值的，这个参数是在接收连接请求时由系统自动的去为其赋值的，其被赋值为connect函数中的第1个参数所绑定的端口，即其与connect函数中的第1个参数所绑定的端口是一样的）。这个accept函数是用来响应一个进程的连接请求的，建立好了连接请求之后这个函数就会发返回一个新的套接字标识符（相当于是创建了一个新的套接字，且这个新的套接字会与第2个参数，即是端口所绑定在一起，即新创建的这个套接字所绑定的这个端口号是与发送连接请求的那个进程的套接字所绑定的端口号一样），这个套接字会与第2个参数所指明的那个端口号给绑定在一起。 由于新创建的这个套接字与发送连接请求的那个套接字所对应的端口号是一样的，故这两个进程就可以使用这两个套接字来进行通信了。即本进程对这个套接字中写数据就会将数据发送到这个套接字所绑定的那个端口号中去，发送连接请求的进程就可以通过读其所对应套接字从端口中将数据给读取出来，发送连接请求的进程发送数据，本进程读取数据也是一样的。

函数参数的作用：
<1>第1个参数：本进程会从这个套接字所对应的端口中去接收连接请求。
<2>第2个参数：这个参数（端口）会指向发送连接请求的那个套接字所对应的端口。
<3>第3个参数：默认为一个socklen_t类型的变量的地址，这个socklen_t变量的值就是为sizeof(struct sockaddr)的。

函数执行的结果：
函数执行成功，两个进程分别对应有一个套接字，这两个套接字对应的端口是为同一个的，函数的返回值就是所创立的新套接字（用来进行数据通信的套接字）；
函数执行失败，即是本进程没有成功的从指明的那个端口接收到一个连接请求时这个函数就会返回一个-1。

6、本进程发送数据的函数send()
int send(int sockfd,const void *msg,int len,int flags)
函数的作用：
这个套接字已经是与某一个端口绑定过了，本进程执行这个语句就相当于是本进程来向套接字所对应的那个端口发送信息，所发送的信息就是为指针msg所指向的内容的前len个字节的。（这个套接字是为本进程所定义的一个局部变量，只允许本进程使用它来向该套接字所对对应的某一个端口发送数据或者从某一个端口中读取数据）
函数参数的作用:
<1>第1个参数：表明了本进程要向哪一个端口发送信息，即是被这个套接字所绑定的那个端口。
<2>第2个参数：表明了本进程要发送的具体内容。
<3>第3个参数：表明了本进程所发送数据是为msg的前len个字节的。
<4>第4个参数：默认参数，一般为0。

函数的执行结果：
函数执行成功，即是本进程成功地讲数据发送到套接字所对应的那个端口，此时这个函数会返回所发送的数据的字节数；函数执行失败，即是本进程没有成功的将数据发送到套接字所对应的那个端口，此时这个函数会返回-1。

7、本进程接收数据的函数recv()
int recv(int sockfd,void *buf,int len,unsigned int flags)
函数作用：
本进程执行这个函数时会从套接字所绑定的那个端口中接收信息，其中函数中的第3个参数指明了接收多少字节的数据，接收到的数据会放到缓冲区buf中（这个缓冲区就是本进程所定义的一个变量，函数中的第4个参数一般是默认为0的）。
注意：本进程执行到这个函数时会被阻塞，解除阻塞的条件是缓冲区buf中有数据。
函数执行结果：
函数执行成功，即是本进程成功地从套接字所对应的端口中接收数据之后，返回所接收的这个数据的字节数；函数执行失败的话，会返回-1。


注意：每一个用户端一般是只有一个套接字socket的，而服务端确是可以有多个套接字socket的，服务器的每一个套接字用来与一个用户进行通信。
