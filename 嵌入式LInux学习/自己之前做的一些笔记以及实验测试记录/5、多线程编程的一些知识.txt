互斥锁的用法总结：
1、互斥锁的相关函数：
pthread_mutex_t lock；                           //定义了一个lock互斥锁
pthread_mutex_init(&lock, NULL);          //初始化这个lock互斥锁
pthread_mutex_lock(&lock);                   //互斥锁lock的上锁
pthread_mutex_unlock(&lock);               //互斥锁lock的解锁
pthread_mutex_destory(&locx);              //互斥锁lock的销毁
注意：在一个线程终止时会释放掉这个线程所占用的互斥锁的，此时这个被终止的线程释放掉了这个互斥锁但是却并没有进行唤醒阻塞队列中的线程的任务，故此时在阻塞队列中的所有线程都还是被阻塞的，只有使用pthread_mutex_unlock(&lock)解锁语句才会既释放锁又进行唤醒阻塞队列中的一个线程的任务。

2、定义了一个互斥锁后，第一个使用对这个互斥锁进行上锁的线程（当没有进行解锁时）会阻塞其他对这个互斥锁上锁的线程（注意，只是阻塞了其他对这个互斥锁上锁的线程，没有对这个互斥锁进行上锁的的线程则是没有被阻塞的），被阻塞的线程中被阻塞的部分只是该线程中这个上锁语句后面的部分，上锁语句前面的部分是没有被阻塞的。

3、第1个获得互斥锁的线程阻塞其他对该互斥锁上锁的线程，其他的线程会按照其所遇到上锁语句pthread_mutex_lock(&lock)的顺序一次加入到一个阻塞队列中，先遇到的会先被阻塞，会先进入到阻塞队列中，当有一个线程使用了解锁语句后会唤醒一个线程，注意这里并不是唤醒阻塞队列中处于最前面的线程的，而是处于阻塞队列中的一个随机的线程的，即是处于阻塞队列中的所有线程会互相竞争这把互斥锁，竞争得到这把互斥锁的线程将被唤醒，故一个线程释放掉其所占用的互斥锁后所唤醒的那一个线程是不确定的。
。

当没有解锁时，第1个遇到上锁语句的线程不会被阻塞，第2、3、4、5、……遇到上锁语句的线程都是会被阻塞的，进入到阻塞队列中的。
注意：如果将这个互斥锁上锁的语句写在一个线程的循环语句里面的话当当前这个线程第2次执行这个上锁语句时也是会被阻塞的，加入到这个阻塞队列中去。

4、互斥锁的种类：全局互斥锁（定义的互斥锁为全局变量时）、对象互斥锁（封装到了一个结构体中的互斥锁）、局部互斥锁（在一个线程内部定义的互斥锁）的用法都是一样的，即都是在所有的线程中第1次遇到上锁语句的不会被阻塞，第2、3、4、5、……次遇到上锁语句的都是会被阻塞的。（使用对象互斥锁时上锁与解锁都是通过某一个对象来进行的，这个对象也可以包含其他的一些属性，由此就可以实现每次只有一个线程来访问这个对象中的一些数据成员或者调用这个对象中的一些方法了，此时这个结构体所定义的一个对象就相当于是一个临界资源）

5、重点（对象互斥锁的理解）：
(1)互斥锁是用来实现对资源的互斥访问的，只有获得了这个互斥锁的线程才能够使用这个资源，为了满足互斥锁的这种特性，常常是将互斥锁给封装到一个结构体中。这个结构体中有一个互斥锁和各种资源（各种类型的数据成员或者成员函数），用这个结构体定义了一个对象后就完就完成了对互斥锁的和资源的实例化，如果要想访问这个互斥锁中的资源的话就必须先来一个上锁语句获得这个对象的互斥锁，只有在获得了这个对象的互斥锁后才能够访问该对象中的资源，访问完该对象的资源后是要释放掉这个的对象的互斥锁的，不能一直占用。
(2)一个包含了互斥锁的结构体所定义的一个对象就相当于是一个临界资源，在一个程序中是可以有多个不同类型的临界资源的（对应了不同结构体所对应的对象），也是可以有同一类型的多个临界资源的（对应了同一个结构体所对应的多个对象，由于这个多个对象中的数据一般是不同的，故这多个对象也是属于不同的资源的）。

 
6、多线程编程的技巧（自创）：
可以使用while(1) ｛ if(m==) break；｝ 的方式来进行多线程编程，即是一个线程执行到某处时可以使用这个语句来进行阻塞，当另一个线程执行到某一个地方时对全局标志为置位使这个线程退出这个循环，相当于实现了一个线程在执行到某一个地方利用while(1) ｛ if(m==) break；｝语句停下来，等到另一个线程执行到某个地方对标志位进行置位后该现程才从这个地方开始执行。
使用这种方法当两个或者多个线程中的条件都是为while(1) ｛ if(m==) break；｝的话，则在一个线程中对标志位进行赋值可以同时来唤醒这两个或者多个线程（相当于是使用了两个或者多个互斥锁）

线程的相关函数：
线程的相关函数是包含在头文件<pthread.h>里面的，而sleep()函数是包含在<time.h>里面的，使用了sleep()函数时才需要包含这个头文件，没有使用的时候只需要包含<pthread.h>这一个头文件就行了。

1、线程的创建
pthread_create(&th_a, NULL, producer, 0);
重点是第1个和第3个参数，分别表示所创建的这个线程的id，以及所创建的这个线程去执行的函数。
注意：是使用pthread_t这个类型来定义一个线程的id的，也就是定义一个线程的。 

2、线程的终止
(1)当线程本身的代码运行结束后，会自动退出。
(2)在一个线程中使用return语句也是可以导致线程退出，此时主线程并不会终止。
(3)在一个线程使用了pthread_exit(返回值)函数也是可以退出这个线程的。
(4)在一个线程中使用exit()终止的是主线程，此时会导致所有的现场都被终止，也是可以退出当前这个线程的。
(5)某一个线程是可以调用pthread_cancel(线程id)函数来终止另外的一个线程的。

注意：
(1)线程组中的任何一个线程调用了exit()函数，或者主线程在main()函数中执行了 return 语句，那么整个线程组内的所有线程都会终止。
(2)区分pthread_exit()、exit()、pthread_cancel()、,使用pthread_exit（）终止的是当前线程，使用exit（）终止的是主线程，使用pthread_cancel（）终止的是某一个指定id的线程。
(3)一个线程在结束时是可以有一个返回值的，当前线程调用这个pthread_exit（m）语句时会结束当前线程，当前线程的返回值就是m；当前线程可以通过return 语句来指明这个返回值；通过exit(m)语句结束的是主线程，其中的m就是这个主线程的返回值。

3、线程的等待
(1)可以使用sleep()函数来控制线程等待的时间，使用这个sleep()函数时要包含#include <time.h>这个头文件。

缺点：一个线程使用sleep()函数来等待另一个线程执行完，但是使用sleep()不仅不方便控制，而且效率也比较低（一个线程使用sleep()函数来等待另一个线程执行完时，可能另一个线程已经执行完了而该线程还在继续等待，造成时间的浪费），可以使用pthred_join（）等待函数来解决这些问题。

(2)使用线程等待函数pthred_join（线程id，该id线程的返回值），使用这个函数的线程会一直等待，直到指定id的这个线程结束时才会接着该线程才会接着往下执行。（这里的指定id的线程执行结束指的是这个线程执行完对应的函数或者这个线程被终止了，即是该线程调用了return语句或者pthread_exit（）等,对应了线程终止的那几种情况，其中pthred_join函数的第2个参数就是用来接收这个指定id的线程终止时的返回值的，这个参数也是可以为NULL的）。

条件变量的用法
1、相关函数说明
pthread_cond_t m;                              //定义一个条件变量m，也叫做一个信号m
pthread_cond_init(&m, NULL);           //条件变量（信号）m的初始化
pthread_cond_signal(&m);                  //在一个线程中使用了这个语句后这个线程就会发送一个信号m
pthread_cond_wait(&m, &b->lock);   //在一个线程中使用了这个语句后这个线程就会被阻塞，等待获得一个m信号后才会重新竞争互斥锁

2、实例分析与条件变量总结的用法
以生产者和消费者的例子来分析条件变量中pthread_cond_signal(&m)与pthread_cond_wait(&m, &b->lock)这两个语句的作用。

生产者线程:
{
   while(1)
   {
    if(满满满满)
          pthread_cond_wait(&not_full, &lock);  
    pthread_cond_signal(&not_empty);
    }
}

消费者线程
{
    while(1) 
    {
    if(空空空空)
           pthread_cond_wait(&not_empty,&lock);
     pthread_cond_signal(&not_full);
    } 
}   
分析：
<1>生产者每往仓库中放入一个产品就会调用  pthread_cond_signal(&not_empty) 这个语句发送一个not_empty的信号，同理，消费者每往仓库中取出一个产品也会调用  pthread_cond_signal(&not_full) 这个语句发送一个not_full的信号。
<2>当生产者根据条件 if(满满满满) 执行  pthread_cond_wait(&not_full, &lock) 这个语句时会被阻塞，同时将互斥锁lock给释放掉使得其他的线程可以使用这个互斥锁（可以对这个互斥锁所对应的临界区进行访问）。
<3>生产者根据条件 if(满满满满) 执行  pthread_cond_wait(&not_full, &lock) 这个语句包括了被阻塞和被苏醒两个阶段。
被阻塞时：
一个是为：这个生产者线程会被阻塞，这个生产者线程会等待一个not_full信号,只有其他的某一个线程通过  pthread_cond_signal(&not_full) 语句发送一个not_full的信号后该生产者线程才会被唤醒（其他的一个线程在这里所发送的信号必须要在生产者线程调用这个pthread_cond_signal（）函数被阻塞后，在生产者线程调用这个函数之前发送的信号是不会唤醒生产者的），这个生产者线程被阻塞后会释放掉其所占用的那个互斥锁。
即被阻塞时完成两个功能，其中一个是被阻塞，等待发送一个信号；另一个是将其所占用的互斥锁lock给释放掉(释放掉的互斥锁是为pthread_cond_wait（）函数中的第2个参数的，这个函数中的第2个参数就是用来指明其所释放掉的是为哪个互斥锁的)。

被唤醒时:
其他的某一个线程发送了一个“not_full”信号后，此时生产者线程在pthread_cond_wait(&not_full, &lock)处被唤醒，被唤醒之后的生产者会竞争这个互斥锁，竞争到这个互斥锁之后就接着往下执行，没有竞争到这个互斥锁的时则就继续被阻塞，继续尝试去竞争这个互斥锁。 

同理，消费者线程的分析也是同样的。

总：在条件变量中最关键的语句就是这个pthread_cond_wait(&m, &lock)语句，当一个线程执行这个语句时会被阻塞，由于是要进行有条件的阻塞，故这个语句一般是要搭配条件语句来使用的，即是if( ) pthread_cond_wait(&not_full, &lock)，当满足if条件时就会执行这个语句，执行这个语句时完成的功能有两个，一个是对互斥锁lock进行释放，使得其他的线程可以使用这个互斥锁，另一个是进行阻塞，等待某一个线程发送not_full的信号后才会重新竞争这个互斥锁（此时是不是处于阻塞状态还要看“当前获得这个互斥锁的线程”有没有释放掉这个互斥锁，为了使得发送这个信号m后“另一个因为某个条件被阻塞的线程”能够立刻运行，一般是“当前获得这个互斥锁的线程”要在发送信号m之前就已经将这个互斥锁给解锁了）。

注意：
(1)pthread_cond_wait()被唤醒时，它解除阻塞，并且尝试获取锁（不一定拿到锁）。因此，一般在使用的时候都是在一个循环里使用pthread_cond_wait()函数而不用if语句，因为它在返回的时候不一定能拿到锁。
(2)一个线程通过 pthread_cond_signal(&not_full)来发送信号唤醒另一个被通过执行pthread_cond_wait(&not_full, &lock)被阻塞的线程，发送信号指的是这个线程被阻塞后，前提条件是这个线程要先被阻塞，此时发送这个信号才有意义。一个线程被阻塞后另一个线程发送被阻塞线程需要的信号才有意义，才会唤醒被阻塞的线程，如果一个线程没有被阻塞另一个线程发送被阻塞线程需要的信号是没有意义的。
(3)信号变量就是用来实现有条件的阻塞（对应了 pthread_cond_wait(&not_full, &lock)搭配条件语句），有条件的唤醒的（pthread_cond_signal(&not_full);语句搭配条件语句）。
(4)由于条件变量也是要搭配互斥锁来使用的，故也是可以和一个互斥锁封装到一个结构体中的，这样就可以实现一个线程“有条件地获取这个对象资源”（指的是有条件的获取这个互斥锁，没有满足条件时是不能够访问这个互斥锁对应的资源的），一个线程“有条件地唤醒另外一个线程”（指的是有条件地来释放掉这个互斥锁，没有满足条件时这个线程是不能够发送信号的）。

问题：消费者通过if() prhread_cond_signal(&not_full)发送信号的时候是否要释放掉这个互斥锁，还是通过if()  pthread_cond_signal(&not_full)自动释放的？
解答：由于消费者执行if()  pthread_cond_signal(&not_full)发送一个信号时是不会自动地将这个互斥锁给释放掉，故在消费者满足条件发送一个信号时是要先释放掉这个互斥锁的，即消费者执行的条             件唤醒语句准确来说应该是if()  {   pthread_mutex_unlock(&lock);    pthread_cond_signal(&not_full)  }。
