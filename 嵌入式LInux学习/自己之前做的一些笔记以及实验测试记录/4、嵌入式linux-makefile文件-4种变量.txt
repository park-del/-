1、makefile文件中的自动变量
在编写一个makefile文件时是可以使用自动变量来代替makefile文件中目标文件或者是依赖文件的。

常见的是有3种自动变量的，如下：
在makefile文件中的每一个command指令都是对应有一个目标文件，对应有一些依赖文件的。在这个command指令中使用makefile中的这3种自动变量时替换的是这个command指令所对应的那一个
目标文件或者是这个command指令所对应的那一些依赖文件的。

makefile文件中的目标文件的代替：
$*：在一个command指令中使用$*加上一个没有扩展名的目标文件就可以在这个command指令中代替这个目标文件了。如目标文件为main.o(有扩展名)，则用$*main就可以代替main.o，如果目标文件为main(没有扩展名)，则用$*main就可以代替main了。

$@:在一个command指令中使用$@代替的是这个command指令所对应的那一个目标文件的。 

$<:在一个command指令中使用$<代替的是这个command指令所对应的那一些依赖文件中的第1个文件的。
 
$^:在一个command指令中使用$^代替的是这个command指令所对应的全部依赖文件的，这些依赖文件是以空格来分隔的，这里是不包含重复的依赖的文件的。


makefile文件中的自动变量的使用实例:

main：main.o mytool1.o mytool2.o
gcc -o $@ $^

说明:$@代表的是当前这个gcc指令所对应的目标文件(即是main)，在当前这个gcc指令中使用 gcc - o $@ 指令就相当于是gcc -o main。
        $^代表的是当前这个gcc指令所对应的所有依赖文件的(即是main.o mytoo1.o mytool2.o),在当前这个gcc指令中使用gcc -o $@ $^就相当于是gcc -o main main.o mmytool1.o mytool2.o。

main.o：main.c mytool1.h mytool2.h
gcc -c $<
说明:$<代表的是当前这个gcc指令所对应的第1个依赖文件(即是main.c)，在当前这个gcc指令中使用gcc -c $<指令就相当于是gcc -c main.c

2、makefile文件中自定义变量
在makefile文件中除了可以使用自动变量之外，也是可以在makefile文件中自己定义一些变量来使用的。
makefile文件中的自定义变量是为一个command指令中的一部分（如gcc、-L. -lmessage、gcc -o measage，此时在某一个command指令中使用该变量时就会将该变量所代替的那部分指令给替换进去）或者一些依赖文件的（此时这个自定义变量可以写在依赖文件列表中或者一个command指令中）。

如
OBJS=tty.o keyshell.o main.o gprs.o   //自定义变量替代的是依赖文件
CC=gcc                                                 //自定义变量替代的是command指令中的一部分，替代的是gcc指令
这里定义了两个变量，一个是为OBJS，一个是为CC的，OBJS这个自定义变量是为一些依赖文件的，CC这个自定义变量是为command指令中的一部分的。

引用自定义变量时是通过"$"来进行的。
main:$(OBJS)                                       //此时是在依赖文件列表中使用自定义变量
	$(cc) -o $@ $(OBJS)            //此时是在一个command指令中使用自定义变量

自定义变量的四种赋值方式：
(1)递归赋值：通过递归赋值的方式定义好了一个变量之后，是在引用时来确定这个变量的值是什么的。
如
X=gcc
Y=X -o
X=arm-linux-gcc

main:main.o
	$(Y) main main.o

分析：此时通过递归赋值的方式定义了两个变量X和Y，由于通过递归展开的方式来定义的变量的值是在引用这个变量的时候确定的，当command指令通过$(Y)引用变量Y时，此时的X=arm-linux-gcc，此时的Y=arm-linux-gcc -o。故这里的command指令就相当于是 arm-linux-gcc -o main main.o。

注意：通过递归赋值的方式的引用一个变量时是可以引用在这个变量之后定义的其他的一些变量的，在本例中就是在引用变量Y时引用了在Y之后定义的一个变量X。

(2)简单赋值：通过简单赋值的方式定义好了一个变量之后，是在定义这个变量的时候确定这个变量的值是什么的。
如
X：=gcc
Y：=X -o
X=arm-linux-gcc

main:main.o
	$(Y) main main.o

分析：此时通过简单赋值的方式定义了两个变量X和Y，由于通过简单赋值的变量的值是在定义这个变量的时候确定的，当command指令通过$(Y)引用变量Y时，此时的Y是在定义时确定的，Y在定义时的X是为gcc的。故这里的command指令就相当于是gcc -o main main.o的。

注意：通过简单赋值的方式引用一个变量时是不能引用在这个变量之后定义的一些变量的，如本例中引用变量Y时，是不能够引用在变量Y后面所定义的那一个变量X的，但是可以引用在变量Y前面所定义的那一个变量X的。

(3)条件赋值：如果某一个变量没有被赋值的话，那么在使用条件赋值符“?=”的时候会被赋值上条件赋值符后面的那一个值；如果某一个变量被赋值了的话，那么在使用条件赋值符“?=”的时候就不会再给这个变量赋值为条件赋值符后面的值了，而是保持这个变量的值不变。
如
LIBDIR?=stu
分析:如果LIBDIR这个变量之前没有被赋值的话，那么在执行完这个语句之后这个LIBDIR变量的值是为stu的；如果在执行这个语句之前变量LIBDIR已经被赋值为skn，那么此时变量LIBDIR的值还是保持为skn的。

(4)追加赋值：在makefile文件中是可以使用“+=”来为一个变量追加某些值的。
如
objects=main.o foo.o bar.o utils.o
objects+=another.o
分析：上面就相当于是在变量objects的后面追加了一个another.o,此时的objects就相当于是为main.o foo.o utils.o another.o。

提示：追加赋值不只是能通过“+=”的方式来进行，还是可以在递归赋值或者简单赋值的时候通过拼接的方式来进行的。
如 
objects=main.o foo.o bar.o utils.o
objects=$(objects) another.o
分析：上面这种在递归赋值或者简单赋值的时候通过拼接的方式与通过“+=”的方式所实现的效果是一样的。

扩展：可以在终端中对makefile文件中的一些自定义变量进行修改的，在终端中输入“make CC=arm-linux-gcc”就可以将makefile文件中的自定义变量“CC”的值修改成“arm-linux-gcc”（要注意，在终端中对makefile文件中的自定义变量所进行修改的优先级是大于在makefile文件的内部对自定义变量所进行修改的优先级的，即是如果既在makefile文件的内部对一个自定义变量进行了修改，也在终端中对一个makefile文件中的这个变量进行了修改，此时是以在终端中对这个变量的修改为主）。自定义的变量可以使用“override”修饰符来进行修饰，使用了这个“overrid”修饰符对一个自定义变量进行了修饰之后在终端中对这个自定义变量的值的修改就是无效的。

3、预定义变量
在makefile文件中是有一些系统已经预先定义好的一些变量，这些变量已经被赋值好了某个值，用户可以不用再对这些预定义变量进行赋值而直接使用它们就可以了。
系统中常见的预定义变量是有6个的，为：
AR:库文件维护程序的名称，默认值为ar。
CC：C编译器的名称，默认值为cc。
CXX：C++编译器的名称，默认值为g++。
RM：文件删除程序的名称，默认值为rm -f。
CFLAGS:C编译器的想象，无默认值。
CPPFLAGS:C预编译器的选项，无默认值。

注意：这些预定义变量都是可以重新赋值，如对CC重新赋值为CC=gcc。


4、环境变量（扩展部分，了解即可）
环境变量的本质就是为一个变量的，环境变量就是操作系统的一个全局变量，既然是一个变量的话，那么就一定会有一个值的，环境变量的值通常是为某一个目录的。因为环境变量又是为操作系统的一个全局变量，当这个环境变量的值为某一个目录时，就可以通过这个环境变量来找到操作系统上的某一个磁盘上的某一个文件（只需找到该文件所在的磁盘目录就行了）。

例如安装java的时候：
在磁盘上的一个目录下面下载了一个java的jdk，jdk就是java的开发工具包，jre是java程序的运行环境，安装了jdk后就会自动安装jre了（在这个jdk目录下面与bin目录同级的是有一个jre文件夹的，里面就是java程序的运行环境），因此只需要把java的jdk安装好就行了。（jdk目录下的bin目录里面有java开发环境的各种服务，jre目录下面的bin目录有java运行环境的各种服务，所谓的java的开发环境指的就是编写程序时候的那个环境，所谓的java的运行环境就是编写好一个程序后程序跑起来的那个环境）

一个java的编译平台要想能够正常运行就必须要有开发环境和运行环境，这个java的编译平台是通过操作系统为其分配的一个全局变量“JAVA_HOME”来找到其所对应的开发环境和运行环境的，这个环境变量“JAVA_HOME”的值就是jdk（这个jdk中有java编译平台的开发环境和运行环境的配置）所在的目录。
“JAVA_HOME”这个环境变量是为java编译平台所独享的，其他进程都是不能够使用的（java编译平台也可以当成是一个进程），但是系统的环境变量“PATH”确是一个公共的全局变量，可以别多个进程互斥的使用，因此这个环境变量也是对应有多个值的，在这个环境变量中添加一个java开发境的bin目录（获取java开发时的各种服务，即是编写java程序时的各种服务），添加一个java运行环境的bin目录（获取java程序运行时的各种服务），这样在一个java编译平台上写出一个程序并且运行一个java程序（注意：配置环境变量“PATH”时采用的是“%JAVA_HOME%/bin”和“%JAVA_HOME%/jre/bin”的，这里的“%JAVA_HOME%/bin”和“%JAVA_HOME%/jre/bin”都是为一个目录的，这里前面的%JAVA_HOME%是为环境变量“JAVA_HOME”的目录的，采用这种方式会更加的灵活，当jdk的安装目录更改时，只需改变环境变量“JAVA_HOME”的目录就行了，此时环境变量“PATH”里面对应的这两个值就会自动改变，不需要再进行修改。当然，环境变量“PATH”的这两个值也可以直接指定为两个目录，不包含“% %”的匹配，只不过当此时jdk的安装目录修改后两个环境变量“JAVA_HOME”和“PATH”都是要进行修改的）。

由于环境变量是为操作系统中的一个全局变量的，故是可以通过这个环境变量来实现不同进程间的通信的（此时环境变量的值就不是为某一个目录了，而是为具体传递的信息）。
在linux中的export指令可以用来查看当前这个linux操作系统中的全局变量，即是环境变量的。
